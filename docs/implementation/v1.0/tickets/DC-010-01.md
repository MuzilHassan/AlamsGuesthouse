# DC-010-01 — Static content migration script

Node script at scripts/migrate-static-content.ts that reads data/rooms.ts, data/hero.ts, data/gallery.ts, and related files, transforms them to the Prisma schema format, and upserts into PostgreSQL. Idempotent by matching existing IDs. Reports errors on missing files or unexpected structure. Does not modify the static data files.

**Contract:** npx tsx scripts/migrate-static-content.ts; reads data/rooms.ts -> Room + RoomImage upsert; data/hero.ts -> HeroImage upsert; data/gallery.ts -> GalleryImage upsert; idempotent by ID match; reports file/field errors and halts; does not delete or modify static files

## Why

REQ-FUNC-021 requires existing static content (rooms, hero images, gallery images) to be migrated into the PostgreSQL data store as initial content so the site can serve it from the database instead of static files, without any visible change to the visitor.

## What

A Node migration script at scripts/migrate-static-content.ts that reads data/rooms.ts, data/hero.ts, and data/gallery.ts, transforms their contents to the Prisma model shapes, and idempotently upserts Room, RoomImage, HeroImage, and GalleryImage records into PostgreSQL, reporting file and field errors and halting on unexpected structure without partial writes.

## Scope

**In:** The migration script scripts/migrate-static-content.ts, its file-reading and structure-validation logic, its transform functions mapping static data to Prisma models, its idempotent upsert logic, and its error reporting and exit-code behaviour.

**Out:** Does not modify or delete the static data files (data/rooms.ts, data/hero.ts, data/gallery.ts). Does not define or alter the Prisma schema or database tables (provided by DC-002-07). Does not build the public site rendering that consumes the migrated content. Does not handle ongoing content editing or CRUD APIs for content.

## Tasks

- [ ] **T1** — Create scripts/migrate-static-content.ts that imports data/rooms.ts, data/hero.ts, and data/gallery.ts, checks each file is present and readable, and validates each has the expected top-level structure (arrays of objects with the fields the transform expects) before proceeding _(verify: Running npx tsx scripts/migrate-static-content.ts with all three static files present and well-structured reads them without error; running it with a missing data file reports the specific missing file path and halts with a non-zero exit code)_
- [ ] **T2** — Implement the transform functions that map each static data file's object shape to the corresponding Prisma model shapes: rooms to Room + RoomImage records, hero to HeroImage records, and gallery to GalleryImage records, preserving all fields the schema defines _(verify: Each transform function produces objects matching the Prisma model field names and types from DC-002-07's schema for Room, RoomImage, HeroImage, and GalleryImage; a room with N images produces 1 Room record and N RoomImage records)_
- [ ] **T3** — Implement the idempotent upsert logic using the Prisma client (DATABASE_URL from DC-002-07), wrapping all upserts in a single transaction so that records are matched by their existing ID and updated or created, with no duplicates on re-run _(verify: Running the script a first time populates Room, RoomImage, HeroImage, and GalleryImage tables with content matching the static files; running it a second time completes with the same record counts and values, upserting by ID match and creating no duplicates)_
- [ ] **T4** — Add error handling that, when a static data file has an unexpected structure (missing required fields, wrong types), reports the specific file and field that caused the error, rolls back the transaction so no partial data is written, and exits with a non-zero code _(verify: Running the script against a data file with an unexpected structure (e.g. a room object missing a required field) reports the specific file and field name in the error output, exits with a non-zero exit code, and leaves the data store unchanged with no partial records written)_
- [ ] **T5** — Add structured logging to the script that reports each file processed, the number of records upserted per model (Room, RoomImage, HeroImage, GalleryImage), and a final summary line, so the migration result is observable in the terminal output _(verify: The script's stdout includes one line per source file processed and a summary showing the count of records upserted for each of the four model types, matching the actual rows written to the data store)_
- [ ] **T6** — Definition of Done: run the full migration against the existing static data files, verify the data store matches the static files, verify idempotency on a second run, verify error handling on a malformed file, and confirm the static data files are unmodified _(verify: npx tsx scripts/migrate-static-content.ts populates the data store with content matching data/rooms.ts, data/hero.ts, and data/gallery.ts (TC-032); a second run creates no duplicates (TC-034); a malformed file reports the specific file and field, halts with non-zero exit, and writes no partial data (TC-035); the static data files are byte-for-byte unchanged after the run; the script is documented with a runbook entry describing how to run it and what to expect)_

## Acceptance

- Given the existing static data files contain room listings, hero images, and gallery images, When the migration script runs, Then the data store contains the migrated content matching the static files
- Given the migration script has run, When a site visitor loads the public website, Then the public site displays the migrated content unchanged from the previous static version
