# DC-010-01 — Static content migration script

Node script at scripts/migrate-static-content.ts that reads data/rooms.ts, data/hero.ts, data/gallery.ts, and related files, transforms them to the Prisma schema format, and upserts into PostgreSQL. Idempotent by matching existing IDs. Reports errors on missing files or unexpected structure. Does not modify the static data files.

**Contract:** npx tsx scripts/migrate-static-content.ts; reads data/rooms.ts -> Room + RoomImage upsert; data/hero.ts -> HeroImage upsert; data/gallery.ts -> GalleryImage upsert; idempotent by ID match; reports file/field errors and halts; does not delete or modify static files

## Why

REQ-FUNC-021 requires existing static content (rooms, hero images, gallery images) to be migrated from the data/*.ts files into PostgreSQL as initial content so the data store is seeded before the public site reads from it.

## What

A Node script at scripts/migrate-static-content.ts that reads data/rooms.ts, data/hero.ts, and data/gallery.ts, transforms each record to the Prisma schema format, and upserts into PostgreSQL idempotently by ID, reporting file and field errors and halting without partial writes.

## Scope

**In:** The migration script scripts/migrate-static-content.ts, its data-reading and transform logic for Room, RoomImage, HeroImage, and GalleryImage, the Prisma upsert calls, idempotency by ID match, error reporting on missing files or unexpected structure, and a non-zero exit on failure.

**Out:** Does not modify or delete the static data files (data/rooms.ts, data/hero.ts, data/gallery.ts); does not build the Prisma schema or generate the Prisma client (provided by DC-002-07); does not build the public site rendering or API endpoints that consume the migrated content; does not handle authentication or notifications (Poly-X not involved).
