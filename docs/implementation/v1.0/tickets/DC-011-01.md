# DC-011-01 — Admin dashboard layout and navigation

Layout shell at /admin/layout.tsx with sidebar or top navigation linking to /admin/rooms, /admin/hero, /admin/promotions, /admin/gallery, /admin/blog-posts. Includes <UserButton showUserProfile> from @poly-x/next in the header for profile editing and MFA self-service. Semantic HTML, ARIA labels, keyboard navigation. Conforms to WCAG 2.2 AA.

**Contract:** /admin/layout.tsx; nav links to rooms, hero, promotions, gallery, blog-posts; <UserButton showUserProfile> in header; semantic HTML, ARIA labels, keyboard nav; WCAG 2.2 AA; 0 violations on automated audit

## Why

REQ-NFUNC-005 requires the admin dashboard to conform to WCAG 2.2 AA, and the dashboard sections need a consistent layout shell with navigation and header so an administrator can move between rooms, hero, promotions, gallery, and blog-posts screens and manage their profile and MFA without leaving the dashboard.

## What

A Next.js layout component at /admin/layout.tsx that renders a semantic header with the Poly-X <UserButton showUserProfile> component, a navigation bar or sidebar with links to /admin/rooms, /admin/hero, /admin/promotions, /admin/gallery, and /admin/blog-posts, and a main content region, all using semantic HTML, ARIA labels, and keyboard navigation, passing an automated WCAG 2.2 AA audit with 0 violations on every dashboard screen.

## Scope

**In:** The /admin/layout.tsx shell, its header with <UserButton showUserProfile> from @poly-x/next, the navigation links to the five admin sections, semantic HTML landmarks, ARIA labels, keyboard navigation, focus management, and locale-aware text for all user-facing strings.

**Out:** The individual admin page content for /admin/rooms, /admin/hero, /admin/promotions, /admin/gallery, and /admin/blog-posts (built by their own design components), the sign-in page and Poly-X BFF route handler (built by DC-001-04), and authentication, session handling, and MFA enrolment logic (provided by Poly-X, never rebuilt here).

## Tasks

- [ ] **T1** — Create /admin/layout.tsx with semantic HTML landmarks: a <header> element, a <nav> element for the dashboard navigation, and a <main> element as the content region that renders children _(verify: the layout renders a <header>, <nav>, and <main> landmark; an automated screen-reader landmark survey lists exactly these three regions with no redundant or missing landmarks)_
- [ ] **T2** — Add navigation links inside the <nav> to /admin/rooms, /admin/hero, /admin/promotions, /admin/gallery, and /admin/blog-posts, each with an accessible name and an aria-current attribute that reflects the active route _(verify: each of the five nav links resolves to its route; the link for the current route carries aria-current="page" and the others do not; tabbing through the nav reaches every link in DOM order)_
- [ ] **T3** — Add <UserButton showUserProfile showName afterSignOutUrl="/sign-in"> from @poly-x/next in the header for profile editing and MFA self-service, relying on the @poly-x/next/styles.css import already provided by DC-001-04 _(verify: the header renders the Poly-X UserButton; clicking it opens a menu with the user name and a link to the profile panel that includes MfaSettings; the button is reachable by keyboard and has an accessible label)_
- [ ] **T4** — Add ARIA labels to the nav region (aria-label="Admin dashboard navigation"), ensure the nav is operable by keyboard with visible focus indicators on every interactive element, and manage focus so it moves predictably between the header and nav _(verify: the nav element has aria-label="Admin dashboard navigation"; every link and the UserButton show a visible focus ring on Tab and Shift+Tab; no interactive element is unreachable by keyboard)_

- [ ] **T6** — Run an automated WCAG 2.2 AA audit (axe-core or equivalent) against /admin/rooms, /admin/hero, /admin/promotions, /admin/gallery, and /admin/blog-posts through the layout shell, and fix every violation until the count is 0 for each screen _(verify: the automated WCAG 2.2 AA audit reports 0 violations for /admin/rooms, /admin/hero, /admin/promotions, /admin/gallery, and /admin/blog-posts; all screens use semantic HTML, ARIA labels, and keyboard navigation (TC-045))_
