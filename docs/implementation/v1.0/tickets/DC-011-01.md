# DC-011-01 — Admin dashboard layout and navigation

Layout shell at /admin/layout.tsx with sidebar or top navigation linking to /admin/rooms, /admin/hero, /admin/promotions, /admin/gallery, /admin/blog-posts. Includes <UserButton showUserProfile> from @poly-x/next in the header for profile editing and MFA self-service. Semantic HTML, ARIA labels, keyboard navigation. Conforms to WCAG 2.2 AA.

**Contract:** /admin/layout.tsx; nav links to rooms, hero, promotions, gallery, blog-posts; <UserButton showUserProfile> in header; semantic HTML, ARIA labels, keyboard nav; WCAG 2.2 AA; 0 violations on automated audit

## Why

REQ-NFUNC-005 requires the admin dashboard to conform to WCAG 2.2 AA, so administrators need a consistent, accessible layout shell with navigation and Poly-X profile access that every dashboard screen inherits.

## What

A Next.js admin layout at /admin/layout.tsx with semantic HTML landmarks, accessible navigation to all five dashboard sections, and a Poly-X UserButton in the header, passing an automated WCAG 2.2 AA audit with 0 violations on every admin screen.

## Scope

**In:** The /admin/layout.tsx shell: header, sidebar or top navigation with links to /admin/rooms, /admin/hero, /admin/promotions, /admin/gallery, /admin/blog-posts, the <UserButton showUserProfile> from @poly-x/next in the header, semantic HTML structure, ARIA labels, keyboard navigation, focus management, and the automated accessibility audit tests.

**Out:** The individual dashboard pages (/admin/rooms, /admin/hero, /admin/promotions, /admin/gallery, /admin/blog-posts) and their content; the sign-in page and authentication flow (provided by DC-001-04 and Poly-X); password handling, token signing, or MFA enrolment UI (Poly-X provides these inside <UserButton>); nothing beyond the layout shell, navigation, and accessibility conformance above.

## Tasks

- [ ] **T1** — Create /admin/layout.tsx with semantic HTML landmarks: a <header>, a <nav> with aria-label='Admin navigation', and a <main> region, rendering children inside <main> _(verify: the layout renders header, nav, and main landmarks with correct ARIA roles; a screen reader announces 'Admin navigation' for the nav region and 'main' for the content area)_
- [ ] **T2** — Add navigation links in the nav to /admin/rooms, /admin/hero, /admin/promotions, /admin/gallery, /admin/blog-posts, each with an accessible name from an i18n string (no hard-coded user-facing text) and aria-current='page' on the active route _(verify: each nav link has a descriptive accessible name from the i18n resource, not a hard-coded string; the link matching the current route carries aria-current='page'; inactive links do not)_
- [ ] **T3** — Mount <UserButton showUserProfile showName afterSignOutUrl='/sign-in'> from @poly-x/next in the header, and import @poly-x/next/styles.css once before the Tailwind entry stylesheet _(verify: the header renders the Poly-X UserButton with profile and MFA self-service available; the stylesheet import resolves without a build error; the button is reachable by keyboard Tab and has a visible focus indicator)_

- [ ] **T6** — Definition of Done: run the full test suite, confirm the automated WCAG 2.2 AA audit passes with 0 violations on every admin screen, verify the layout is deployed to the test environment, and confirm the navigation and UserButton are documented in the admin dashboard runbook _(verify: all unit and accessibility tests pass; the axe audit reports 0 violations for /admin/rooms, /admin/hero, /admin/promotions, /admin/gallery, and /admin/blog-posts; the layout shell is deployed to the test environment and reachable at /admin; the runbook documents the admin nav structure and the Poly-X UserButton integration)_
