# DC-006-03 — DELETE /api/admin/promotions/:id

Remove a promotion from PostgreSQL.

**Contract:** DELETE /api/admin/promotions/:id -> 204 | 401 | 403 | 404 | 503

## Why

Admins need to remove promotions that are no longer relevant so they stop appearing on the public site, satisfying REQ-FUNC-014.

## What

A DELETE /api/admin/promotions/:id endpoint that removes a promotion from the data store, returns 204 on success, and returns 404 when the promotion does not exist, behind Poly-X admin authorization.

## Scope

**In:** The DELETE /api/admin/promotions/:id route handler, the 404 not-found path, and the Poly-X introspection middleware wiring for this endpoint.

**Out:** Does not build the promotions management UI, the POST or PUT promotion endpoints, or the public-site active-promotions query. Poly-X provides authentication and the admin role check; this unit consumes it.

## Tasks

- [ ] **T1** — Implement DELETE /api/admin/promotions/:id, mounting @poly-x/sdk requireUser() middleware, checking the promotions:delete grant in permissions.modulePermissions, validating the organization-id header against the token's organizationId, and returning 403 on mismatch or missing grant _(verify: a request with a valid admin token and matching organization-id returns 204; a request without the promotions:delete grant returns 403; a request with a mismatched organization-id returns 403; a request with no token returns 401; when Poly-X is unreachable the endpoint returns 503)_
- [ ] **T2** — Add the 404 not-found path: return 404 with code PROMOTION_NOT_FOUND when the id does not match an existing promotion; add structured logging with the request id and a promotion_deleted metric counter on the success path _(verify: DELETE to a non-existent promotion id returns 404 with code PROMOTION_NOT_FOUND; a successful DELETE logs a structured line with the request id and promotionId; the promotion_deleted counter increments by 1)_
- [ ] **T3** — Write integration tests covering TC-024: a valid DELETE returns 204 and the promotion is absent from GET /api/content/rooms; include cases for 401 unauthenticated, 403 missing admin grant, 404 PROMOTION_NOT_FOUND, and 503 Poly-X unreachable _(verify: TC-024 passes: DELETE /api/admin/promotions/{promotionId} returns 204 and a subsequent GET /api/content/rooms does not include the deleted promotion; the 401, 403, 404, and 503 error paths each return their documented status and error code)_
- [ ] **T4** — Document the DELETE /api/admin/promotions/:id endpoint in the API description: the polyxBearer security scheme, the organization-id header, the promotions:delete permission, and the 204/401/403/404/503 responses _(verify: the API description lists DELETE /api/admin/promotions/:id with the polyxBearer scheme, the organization-id header, the required promotions:delete grant, and all five response codes with their error codes)_
- [ ] **T5** — Definition of Done: all tests pass, TC-024 is demonstrated, API documentation is updated, and the endpoint is deployed to the test environment _(verify: the integration test suite passes including TC-024 and all error-path cases; the API description includes this endpoint; the endpoint responds in the test environment)_

## Acceptance

- Given an authenticated admin and an existing promotion, When the admin removes that promotion, Then the system removes the promotion from the data store and the promotion no longer appears on the public site
