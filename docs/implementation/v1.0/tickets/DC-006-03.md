# DC-006-03 — DELETE /api/admin/promotions/:id

Remove a promotion from PostgreSQL.

**Contract:** DELETE /api/admin/promotions/:id -> 204 | 401 | 403 | 404 | 503

## Why

REQ-FUNC-014 requires that an admin can remove a promotion so it no longer appears on the public site, keeping the public content free of stale or ended offers.

## What

A DELETE /api/admin/promotions/:id endpoint that removes a promotion from the data store, returns 204 on success, and handles 404 for a missing promotion, guarded by Poly-X introspection and admin-role authorization.

## Scope

**In:** The DELETE /api/admin/promotions/:id route handler, the 404 not-found path, and the Poly-X introspection and admin-permission check on this route.

**Out:** Creating promotions (DC-006-01), editing promotions (DC-006-02), the promotions table migration (DC-006-01), the admin UI (DC-006-04), public display filtering (DC-006-05); authentication and session management, which Poly-X provides.

## Tasks

- [ ] **T1** — Implement the DELETE /api/admin/promotions/:id route handler that looks up the promotion by id from the path parameter; return 404 with code PROMOTION_NOT_FOUND when the promotion does not exist _(verify: a DELETE to /api/admin/promotions/{non-existent-id} returns 404 with code PROMOTION_NOT_FOUND)_
- [ ] **T2** — Wire the Poly-X introspection middleware from DC-001-03 before the handler: introspect the Bearer token, check the admin grant for promotions:delete in permissions.modulePermissions, verify the organization-id header matches, and fail closed with 401 inactive, 403 missing grant or org-id mismatch, 503 Poly-X unreachable _(verify: a request without a Bearer token returns 401; a request with a valid token but no promotions:delete grant returns 403; a request with a mismatched organization-id header returns 403; a request when Poly-X is unreachable returns 503)_
- [ ] **T3** — Implement the delete logic: remove the promotion via Prisma and return 204 with an empty body; verify the promotion is absent from a subsequent GET /api/content/rooms response _(verify: a DELETE on an existing promotion returns 204 with an empty body; a subsequent GET /api/content/rooms does not include the deleted promotion)_
- [ ] **T4** — Add structured request logging with the request id, the Poly-X userId, and the deleted promotion id; add a counter metric for promotions_deleted _(verify: the log entry for a successful delete includes the request id, userId, and promotion id; the promotions_deleted counter increments by 1)_
- [ ] **T5** — Write integration tests covering TC-024: a valid admin request deletes a promotion and returns 204, and the promotion is absent from the public content response; also cover 401 unauthenticated, 403 missing admin grant, 404 non-existent promotion, and 503 Poly-X unreachable _(verify: the integration test suite passes: the valid delete returns 204 and the promotion is absent from GET /api/content/rooms; the 401, 403, 404, and 503 cases each return their expected status and code)_
- [ ] **T6** — Definition of Done: all tests pass, the endpoint is deployed to the test environment, structured logs and metrics are emitted, and the API description for DELETE /api/admin/promotions/:id is documented with its response codes and the polyxBearer security scheme _(verify: the test suite is green, the endpoint responds on the test environment, logs include the request id and userId, and the API documentation describes the 204/401/403/404/503 responses and the polyxBearer scheme)_

## Acceptance

- Given an authenticated admin and an existing promotion, When the admin removes that promotion, Then the system removes the promotion from the data store and the promotion no longer appears on the public site
