# DC-009-01 — GET /api/content/rooms

Public endpoint returning room listings with prices and active promotions. No authentication required. Reads from PostgreSQL via Prisma.

**Contract:** GET /api/content/rooms -> 200 { rooms: [{ id, name, description, amenities, maxOccupancy, price, images, promotions }] } | 500; no auth required; active promotions only

## Why

Site visitors need to see room listings with current prices and active promotions served from the data store (REQ-FUNC-019), so that managed content appears on the public site without manual data file edits.

## What

A public GET /api/content/rooms endpoint that returns all rooms with their images and active promotions from PostgreSQL via Prisma, returning 200 on success and 500 on database failure, with no authentication required.

## Scope

**In:** The route handler at app/api/content/rooms/route.ts, the Prisma query for rooms with images and active promotions (is_active = true per DC-006-05), response mapping to the contract shape, and error handling for the 500 path.

**Out:** Does not build the hero-images, gallery, or blog-posts endpoints (DC-009-02, DC-009-03, DC-009-04); does not modify public-facing components (DC-009-05); does not implement Poly-X authentication or authorization, as this is a public endpoint with no auth required; does not define the Prisma schema or migrations (DC-002-07).

## Tasks

- [ ] **T1** — Create app/api/content/rooms/route.ts with a GET handler that queries the Prisma client for all rooms, including room images and promotions where is_active = true, joined per the DC-006-05 contract _(verify: GET /api/content/rooms returns 200 with a rooms array where each room has id, name, description, amenities, maxOccupancy, price, images, and promotions; only promotions with is_active = true appear in the promotions array; removed or inactive promotions are excluded)_
- [ ] **T2** — Map the Prisma query result to the response contract shape { rooms: [{ id, name, description, amenities, maxOccupancy, price, images, promotions }] }, serialising Decimal price fields as { amount, currency } _(verify: A room stored with price 4000 PKR appears in the response with price { amount: '4000.00', currency: 'PKR' }, matching the TC-030 expected result)_
- [ ] **T3** — Add a try/catch around the Prisma query that returns 500 with a structured error log including the request id when the database query fails _(verify: When the Prisma client throws (for example, DATABASE_URL is unset), GET /api/content/rooms returns 500 and the server log contains the request id and the error message)_
- [ ] **T4** — Write an integration test that seeds a room priced at 4000 PKR with one active and one inactive promotion, sends GET /api/content/rooms, and asserts the response _(verify: The test asserts 200 status, the room with price { amount: '4000.00', currency: 'PKR' } is present (TC-030), only the active promotion appears in promotions, and the content matches what is stored in PostgreSQL (TC-029 rooms step))_
- [ ] **T5** — Definition of Done: confirm the endpoint is deployed to the test environment, the integration test passes, the 500 error path is covered, and the API route is documented in the project API reference _(verify: GET /api/content/rooms returns 200 with rooms from PostgreSQL including active promotions only; the integration test for TC-029 and TC-030 passes; the 500 path returns a structured error; the endpoint is reachable in the test environment with no authentication header)_

## Acceptance

- Given room listings, hero images, gallery images, and blog posts stored in the data store, When a site visitor loads the public website, Then the public site displays content read from the data store
- Given the data store contains a room priced at 4000, When a site visitor loads the room listing page, Then the public site displays 4000 for that room
