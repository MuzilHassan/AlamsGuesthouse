# DC-009-01 — GET /api/content/rooms

Public endpoint returning room listings with prices and active promotions. No authentication required. Reads from PostgreSQL via Prisma.

**Contract:** GET /api/content/rooms -> 200 { rooms: [{ id, name, description, amenities, maxOccupancy, price, images, promotions }] } | 500; no auth required; active promotions only

## Why

Site visitors need to see room listings with current prices and active promotions served from the data store, so that managed content appears on the public site without manual code changes to static files.

## What

A public API route at /api/content/rooms that returns 200 with room data including id, name, description, amenities, maxOccupancy, price, images, and active promotions from PostgreSQL via Prisma, or 500 on a data store error, with no authentication required.

## Scope

**In:** The GET /api/content/rooms route handler, its Prisma query joining rooms with active promotions (is_active = true), and the response shape.

**Out:** The Prisma schema and database setup (DC-002-07), the promotions query logic for content management (DC-006-05), the other three public content endpoints (DC-009-02 through DC-009-04), and the component modifications to consume this endpoint (DC-009-05). No authentication or Poly-X integration.

## Tasks

- [ ] **T1** — Create the route handler at app/api/content/rooms/route.ts that queries Prisma for rooms with their images and active promotions where is_active = true, excluding removed or inactive promotions per the DC-006-05 contract _(verify: GET /api/content/rooms returns 200 with a rooms array where each room has id, name, description, amenities, maxOccupancy, price, images, and promotions; only promotions with is_active = true are included and inactive promotions are excluded)_
- [ ] **T2** — Add the 500 error response path for when the Prisma query fails, returning a JSON error body without leaking database details _(verify: GET /api/content/rooms returns 500 with a JSON error response when the database is unreachable; the response body does not expose connection strings or query text)_
- [ ] **T3** — Add structured logging with the request id to the rooms route handler for observability _(verify: a request to /api/content/rooms produces a structured log entry containing the request id and the response status code)_
- [ ] **T4** — Write the integration test covering TC-029 step 1 and TC-030: seed the data store with rooms including one priced at 4000, then GET /api/content/rooms and assert the response _(verify: the integration test sends GET /api/content/rooms and asserts 200 with rooms matching the seeded data store, including the room with price { amount: '4000.00', currency: 'PKR' })_
- [ ] **T5** — Definition of Done check for the rooms endpoint _(verify: GET /api/content/rooms returns 200 with rooms from PostgreSQL including active promotions only, returns 500 on database error, requires no authentication, makes no Poly-X API calls, the integration test for TC-029 and TC-030 passes, and the route is deployed to the test environment)_

## Acceptance

- Given room listings, hero images, gallery images, and blog posts stored in the data store, When a site visitor loads the public website, Then the public site displays content read from the data store
- Given the data store contains a room priced at 4000, When a site visitor loads the room listing page, Then the public site displays 4000 for that room
