# DC-004-03 — DELETE /api/admin/rooms/:id

Delete a room listing and cascade-delete associated RoomImage and Promotion records from PostgreSQL.

**Contract:** DELETE /api/admin/rooms/:id -> 204 | 401 | 403 | 404 | 503

## Why

REQ-FUNC-006 requires that an authenticated admin can delete a room listing, so that the room is removed from the data store and no longer appears in the room listings list or on the public site.

## What

DELETE /api/admin/rooms/:id returns 204 when the room is deleted (with cascade deletion of associated RoomImage and Promotion records), 404 when the room does not exist, 401 for an unauthenticated caller, 403 for a missing admin role or organization mismatch, and 503 when Poly-X is unreachable.

## Scope

**In:** The DELETE /api/admin/rooms/:id endpoint, the Prisma delete that removes the room and cascade-deletes associated RoomImage and Promotion records, and the 204 response.

**Out:** Creating or editing rooms (DC-004-01, DC-004-02); price-specific updates (DC-004-04); the admin UI delete confirmation (DC-004-05); authentication and authorization, provided by Poly-X via DC-001-03; the Prisma schema, provided by DC-002-07.

- [ ] **T1** — Wire the Poly-X introspection middleware from DC-001-03 on the DELETE /api/admin/rooms/:id route with the same admin role, organization-id, and fail-closed checks _(verify: a request without a bearer token returns 401; a request with a valid token but no admin role returns 403; a request with a mismatched organization-id returns 403; Poly-X unreachable returns 503)_
- [ ] **T2** — Implement the DELETE /api/admin/rooms/:id handler: find the room by id via the Prisma client from DC-002-07, return 404 if not found, delete the room with cascade deletion of associated RoomImage and Promotion records, and return 204 with no body _(verify: DELETE /api/admin/rooms/:id on an existing room returns 204 and the room is absent from the data store; associated RoomImage and Promotion records are cascade-deleted; DELETE on a non-existent room id returns 404)_
