# DC-004-03 — DELETE /api/admin/rooms/:id

Delete a room listing and cascade-delete associated RoomImage and Promotion records from PostgreSQL.

**Contract:** DELETE /api/admin/rooms/:id -> 204 | 401 | 403 | 404 | 503

## Why

REQ-FUNC-006 requires that an authenticated admin can delete a room listing, removing it from the data store so it no longer appears in the room listings list or on the public site.

## What

A DELETE /api/admin/rooms/:id endpoint that removes the room and cascade-deletes associated RoomImage and Promotion records from PostgreSQL via Prisma, returning 204 on success, 404 if the room does not exist, 401/403 on auth failure, 503 when Poly-X is unreachable.

## Scope

**In:** The DELETE /api/admin/rooms/:id endpoint, the Prisma delete logic with cascade deletion of RoomImage and Promotion records, and the Poly-X introspection middleware wiring for admin authorization.

**Out:** Does not build the create endpoint (DC-004-01), the edit endpoint (DC-004-02), the price-only endpoint (DC-004-04), the room listings UI (DC-004-05), or the Prisma schema (DC-002-07). Poly-X provides authentication; this unit only wires the introspection middleware from DC-001-03.

## Tasks

- [ ] **T1** — Wire the Poly-X introspection middleware from DC-001-03 on the DELETE /api/admin/rooms/:id route: introspect the Bearer token, check admin role, validate organization-id header, fail closed with 401/403/503 as specified _(verify: a request without a Bearer token returns 401, a request with a valid token but no admin role returns 403, and a request when Poly-X is unreachable returns 503)_
- [ ] **T2** — Implement the DELETE /api/admin/rooms/:id handler: look up the room by id returning 404 if not found, delete the room and cascade-delete associated RoomImage and Promotion records via the Prisma client from DC-002-07, return 204 with no body _(verify: DELETE /api/admin/rooms/:id on an existing room returns 204 with no body, the room is removed from PostgreSQL, and associated RoomImage and Promotion records are cascade-deleted; DELETE on a non-existent room id returns 404)_
- [ ] **T3** — Add structured logging with the request id on the delete-room handler: log the admin userId, organizationId, and deleted room id on success, and the 404 detail on failure _(verify: a successful delete logs the userId, organizationId, and deleted room id with the request id; a 404 response logs the missing room id with the request id)_
- [ ] **T4** — Write integration test covering TC-014 (delete existing room returns 204, room absent from list and public site, associated records cascade-deleted) _(verify: TC-014 passes: DELETE on an existing room returns 204, a subsequent GET to /api/content/rooms does not include the deleted room, and associated RoomImage and Promotion records are absent from the data store)_
- [ ] **T5** — Definition of Done: all tests pass, the endpoint returns 204 for an existing room and 404 for a non-existent room, cascade deletion of RoomImage and Promotion records is verified, 401/403/503 auth paths are covered, structured logs include the request id, and the endpoint is deployed to the test environment _(verify: the test suite passes, TC-014 is green, a curl to the test environment DELETE /api/admin/rooms/:id on an existing room returns 204, and a subsequent GET to /:content/rooms confirms the room is absent)_

## Acceptance

- Given an authenticated admin and an existing room listing, When the admin confirms deletion of that listing, Then the system removes the room listing from the data store and the listing no longer appears in the room listings list or on the public site
