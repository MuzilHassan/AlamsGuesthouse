# DC-009-03 — GET /api/content/gallery

Public endpoint returning gallery images in display order with captions and alt text. No authentication required.

**Contract:** GET /api/content/gallery -> 200 { galleryImages: [{ id, cloudinaryUrl, caption, altText, displayPosition }] } | 500; ordered by display_position

## Why

Site visitors need to see gallery images with captions and alt text in the correct display order from the data store, so that managed gallery content appears on the public site without manual code changes to static files.

## What

A public API route at /api/content/gallery that returns 200 with gallery image data including id, cloudinaryUrl, caption, altText, and displayPosition from PostgreSQL via Prisma ordered by display_position, or 500 on a data store error, with no authentication required.

## Scope

**In:** The GET /api/content/gallery route handler, its Prisma query ordering by display_position, and the response shape.

**Out:** The Prisma schema and database setup (DC-002-07), the rooms endpoint (DC-009-01), the hero-images endpoint (DC-009-02), the blog-posts endpoint (DC-009-04), and the component modifications (DC-009-05). No authentication or Poly-X integration.

## Tasks

- [ ] **T1** — Create the route handler at app/api/content/gallery/route.ts that queries Prisma for gallery images ordered by display_position ascending, including caption and altText fields _(verify: GET /api/content/gallery returns 200 with a galleryImages array where each item has id, cloudinaryUrl, caption, altText, and displayPosition, and the items are ordered by display_position ascending)_
- [ ] **T2** — Add the 500 error response path for when the Prisma query fails, returning a JSON error body without leaking database details _(verify: GET /api/content/gallery returns 500 with a JSON error response when the database is unreachable; the response body does not expose connection strings or query text)_
- [ ] **T3** — Write the integration test covering TC-029 step 3: seed gallery images in the data store, then GET /api/content/gallery and assert the response _(verify: the integration test sends GET /api/content/gallery and asserts 200 with galleryImages matching the seeded data store, ordered by display_position ascending, with caption and altText populated)_
- [ ] **T4** — Definition of Done check for the gallery endpoint _(verify: GET /api/content/gallery returns 200 with gallery images from PostgreSQL ordered by display_position with caption and altText, returns 500 on database error, requires no authentication, makes no Poly-X API calls, the integration test for TC-029 passes, and the route is deployed to the test environment)_

## Acceptance

- Given room listings, hero images, gallery images, and blog posts stored in the data store, When a site visitor loads the public website, Then the public site displays content read from the data store
- Given the data store contains a room priced at 4000, When a site visitor loads the room listing page, Then the public site displays 4000 for that room
