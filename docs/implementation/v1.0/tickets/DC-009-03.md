# DC-009-03 — GET /api/content/gallery

Public endpoint returning gallery images in display order with captions and alt text. No authentication required.

**Contract:** GET /api/content/gallery -> 200 { galleryImages: [{ id, cloudinaryUrl, caption, altText, displayPosition }] } | 500; ordered by display_position

## Why

Site visitors need to see gallery images with captions and alt text served from the data store (REQ-FUNC-019), so that managed gallery content appears on the public site without manual data file edits.

## What

A public GET /api/content/gallery endpoint that returns gallery images in display order with captions and alt text from PostgreSQL via Prisma, returning 200 on success and 500 on database failure, with no authentication required.

## Scope

**In:** The route handler at app/api/content/gallery/route.ts, the Prisma query for gallery images ordered by display_position, response mapping to the contract shape, and error handling for the 500 path.

**Out:** Does not build the rooms, hero-images, or blog-posts endpoints (DC-009-01, DC-009-02, DC-009-04); does not modify public-facing components (DC-009-05); does not implement Poly-X authentication or authorization, as this is a public endpoint with no auth required; does not define the Prisma schema or migrations (DC-002-07).

## Tasks

- [ ] **T1** — Create app/api/content/gallery/route.ts with a GET handler that queries the Prisma client for all gallery images ordered by display_position ascending, including caption and altText fields _(verify: GET /api/content/gallery returns 200 with a galleryImages array where each item has id, cloudinaryUrl, caption, altText, and displayPosition; the array is ordered by display_position ascending)_
- [ ] **T2** — Add a try/catch around the Prisma query that returns 500 with a structured error log including the request id when the database query fails _(verify: When the Prisma client throws, GET /api/content/gallery returns 500 and the server log contains the request id and the error message)_
- [ ] **T3** — Write an integration test that seeds gallery images with display positions, captions, and alt text, sends GET /api/content/gallery, and asserts the response _(verify: The test asserts 200 status and the galleryImages array is ordered by display_position, with each item containing id, cloudinaryUrl, caption, and altText matching the seeded data (TC-029 gallery step))_
- [ ] **T4** — Definition of Done: confirm the endpoint is deployed to the test environment, the integration test passes, the 500 error path is covered, and the API route is documented in the project API reference _(verify: GET /api/content/gallery returns 200 with gallery images from PostgreSQL ordered by display_position with caption and altText; the integration test passes; the 500 path returns a structured error; the endpoint is reachable in the test environment with no authentication header)_

## Acceptance

- Given room listings, hero images, gallery images, and blog posts stored in the data store, When a site visitor loads the public website, Then the public site displays content read from the data store
- Given the data store contains a room priced at 4000, When a site visitor loads the room listing page, Then the public site displays 4000 for that room
