# DC-001-05 — Account lifecycle pages

/forgot-password, /reset-password, and /claim pages rendering <ForgotPassword>, <ResetPassword>, and <ClaimAccount> from @poly-x/next. Tokens read from searchParams in Server Components and passed as props to avoid hydration mismatch.

**Contract:** /forgot-password -> <ForgotPassword signInPath='/sign-in' />; /reset-password -> <ResetPassword token={token} signInPath='/sign-in' forgotPasswordPath='/forgot-password' />; /claim -> <ClaimAccount token={token} signInPath='/sign-in' />; token from searchParams in RSC

## Why

REQ-FUNC-001 requires that administrators can recover access through password reset and claim purchased accounts. The account lifecycle pages render the Poly-X ForgotPassword, ResetPassword, and ClaimAccount components, so the product does not build a password reset flow, email sending, or account claiming logic itself.

## What

The /forgot-password, /reset-password, and /claim pages render <ForgotPassword>, <ResetPassword>, and <ClaimAccount> from @poly-x/next respectively, with tokens read from searchParams in Server Components and passed as props to avoid hydration mismatch, and /claim is reachable while signed in.

## Scope

**In:** The /forgot-password, /reset-password, and /claim page components, the searchParams token reading in Server Components, and the prop passing to the Poly-X components.

**Out:** The BFF catch-all route (DC-001-01) that handles the password reset and claiming actions, the edge gate (DC-001-02) that keeps these routes public, the introspection middleware (DC-001-03), and the sign-in page (DC-001-04). Poly-X provides the ForgotPassword, ResetPassword, and ClaimAccount components and the underlying endpoints; this unit only renders them. No password reset logic, email sending, or claim validation is built here.

## Acceptance

- Given an unauthenticated request to any admin dashboard route, When the system checks the Poly-X session, Then the system returns HTTP 401 and does not display the dashboard
- Given an authenticated request whose Poly-X token lacks the admin role, When the system checks the role grant, Then the system returns HTTP 403 and does not display the dashboard
- Given an authenticated request with the admin role, When the system checks the Poly-X session, Then the system grants access to the admin dashboard
