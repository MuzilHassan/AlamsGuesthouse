# DC-008-03 — PUT /api/admin/blog-posts/:id/publish

Publish a blog post by setting is_published to true. The post then appears on the public site.

**Contract:** PUT /api/admin/blog-posts/:id/publish -> 200 { blogPost, is_published: true } | 401 | 403 | 404 | 503

## Why

REQ-FUNC-024 requires that an authenticated admin can publish an unpublished blog post so it appears on the public site.

## What

PUT /api/admin/blog-posts/:id/publish endpoint that sets is_published to true on the post and returns 200 with the blogPost object where is_published is true.

## Scope

**In:** The PUT /api/admin/blog-posts/:id/publish route handler, Prisma update setting is_published to true, and the 200/401/403/404/503 response shapes.

**Out:** Creating or editing blog post content (DC-008-01, DC-008-02); deleting posts (DC-008-04); the admin UI publish button (DC-008-05); the public content endpoint that filters by is_published; the blog_posts Prisma model definition (DC-002-07); Poly-X token introspection and permission checks (DC-001-03).

## Tasks

- [ ] **T1** — Implement the PUT /api/admin/blog-posts/:id/publish route handler behind the Poly-X introspection middleware from DC-001-03, checking admin role and organization-id, returning 401 for inactive token, 403 for missing admin role or org-id mismatch, 404 when the post id does not exist, and 503 when Poly-X is unreachable _(verify: A publish request with a valid admin token and an existing unpublished post id returns 200 with is_published true; a non-existent post id returns 404; an expired token returns 401; a non-admin token returns 403; Poly-X unreachable returns 503)_
- [ ] **T2** — Add the Prisma update call that sets is_published to true and updates updated_at, returning the blogPost object _(verify: PUT /api/admin/blog-posts/{blogPostId}/publish on an unpublished post returns 200 with blogPost.is_published equal to true and the post is marked as published in the data store)_
- [ ] **T3** — Add structured request logging with the request id and a metric counter for blog post publishing, and document PUT /api/admin/blog-posts/:id/publish in the OpenAPI contract _(verify: A publish request emits a structured log line with the request id and increments the blog_post_publish counter; the OpenAPI contract documents the 200, 401, 403, 404, and 503 responses)_
- [ ] **T4** — Write integration tests covering TC-039 (publishing an unpublished post returns 200 with is_published true and the post appears on the public site via GET /api/content/blog-posts) and TC-040 (an unpublished post does not appear in GET /api/content/blog-posts) _(verify: TC-039 passes: PUT /publish returns 200 with is_published true and GET /api/content/blog-posts includes the post; TC-040 passes: GET /api/content/blog-posts does not include posts where is_published is false)_
- [ ] **T5** — Definition of Done: run the full test suite, confirm the endpoint is deployed to the test environment, verify the OpenAPI contract is updated, and confirm all response paths behave per the contract _(verify: All tests pass, PUT /api/admin/blog-posts/:id/publish is reachable in the test environment, the OpenAPI contract includes the endpoint with all response codes, and the acceptance criterion for REQ-FUNC-024 is demonstrated: publishing an unpublished post marks it as published and it appears on the public site)_

## Acceptance

- Given an authenticated admin and an existing unpublished blog post, When the admin publishes the post, Then the system marks the post as published in the data store and the blog post appears on the public site
