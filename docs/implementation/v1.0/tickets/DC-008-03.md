# DC-008-03 — PUT /api/admin/blog-posts/:id/publish

Publish a blog post by setting is_published to true. The post then appears on the public site.

**Contract:** PUT /api/admin/blog-posts/:id/publish -> 200 { blogPost, is_published: true } | 401 | 403 | 404 | 503

## Why

Admins need to publish blog posts so that content appears on the public-facing site for guests to read, satisfying REQ-FUNC-024.

## What

A PUT /api/admin/blog-posts/:id/publish endpoint that sets is_published to true on the matching Prisma record and returns the blogPost object with is_published true, so the post appears in the public content listing.

## Scope

**In:** The PUT /api/admin/blog-posts/:id/publish route handler, Prisma update setting is_published true, and the 200/401/403/404/503 response shapes.

**Out:** Creating or editing blog posts (DC-008-01, DC-008-02); deleting posts (DC-008-04); the publish button UI (DC-008-05); the public content listing endpoint that filters by is_published; the blog_posts Prisma model (DC-002-07); authentication and authorization (DC-001-03).

## Tasks

- [ ] **T1** — Implement the PUT /api/admin/blog-posts/:id/publish route handler: wire the Poly-X introspection middleware from DC-001-03 (requireUser, admin role check, organization-id check, fail closed 401/403/503), call prisma.blogPost.update to set is_published true and updated_at to now, and return 200 with the blogPost object where is_published is true; return 404 when the post id does not exist _(verify: A PUT request on an existing unpublished post returns 200 with blogPost.is_published equal to true; a PUT on a non-existent post id returns 404; a request without a token returns 401; a non-admin token returns 403; Poly-X unreachable returns 503)_
- [ ] **T2** — Add structured logging with the request id and a publish-blog-post audit log entry (userId, blogPostId, action: 'blog_post.publish') on success _(verify: Publishing a blog post emits a structured log line with the request id, userId, blogPostId, and action 'blog_post.publish' at info level)_
- [ ] **T3** — Write integration tests covering TC-039 (publishing an unpublished post marks it published and it appears on the public site) and TC-040 (an unpublished post does not appear on the public site) _(verify: TC-039: PUT /v1/blog-posts/{blogPostId}/publish returns 200 with is_published true; a GET to /api/content/blog-posts includes the post; TC-040: a GET to /api/content/blog-posts for an unpublished post does not include it in the response)_
- [ ] **T4** — Definition of Done: run the full test suite for this endpoint, confirm all acceptance criteria are demonstrated, verify structured logging and audit entries are emitted, and confirm the endpoint is deployed to the test environment _(verify: All tests pass (TC-039, TC-040, and the 401/403/404/503 path tests); structured logs include the request id and audit entry; the endpoint is reachable in the test environment and returns 200 for a valid admin publish request)_

## Acceptance

- Given an authenticated admin and an existing unpublished blog post, When the admin publishes the post, Then the system marks the post as published in the data store and the blog post appears on the public site
