# DC-008-05 — Blog posts management UI

Admin dashboard pages at /admin/blog-posts, /admin/blog-posts/new, /admin/blog-posts/:id/edit. Forms with title, body content, and image upload. Publish button. List shows published status. Conforms to WCAG 2.2 AA.

**Contract:** Pages at /admin/blog-posts, /admin/blog-posts/new, /admin/blog-posts/:id/edit; list with title and published status; form with title, body, image upload; publish button; delete with confirmation; WCAG 2.2 AA

## Why

Admins need dashboard pages to create, edit, publish, and delete blog posts through a form-based UI so that content management is accessible without direct API calls, satisfying REQ-FUNC-022 through REQ-FUNC-025.

## What

Admin dashboard pages at /admin/blog-posts (list with title and published status), /admin/blog-posts/new (create form with title, body, image upload, and submit), and /admin/blog-posts/:id/edit (edit form with publish button and delete with confirmation), all conforming to WCAG 2.2 AA.

## Scope

**In:** The three admin dashboard pages and their form components, the blog posts list table with published status column, the create and edit forms with title input, body textarea, image upload via the DC-003-01 upload endpoint, the publish button calling DC-008-03, the delete button with confirmation dialog calling DC-008-04, client-side validation matching the server zod schemas, and all WCAG 2.2 AA accessibility and i18n requirements.

**Out:** The API endpoint handlers for create, edit, publish, and delete (DC-008-01 through DC-008-04 provide them); the image upload endpoint itself (DC-003-01 provides it); the public-facing blog content listing; authentication and authorization (DC-001-03 provides Poly-X introspection); the blog_posts Prisma model (DC-002-07).

- [ ] **T2** — Create the new blog post page at /admin/blog-posts/new with a form containing a labelled title text input, a labelled body textarea, an image upload field that posts to the DC-003-01 upload endpoint and stores the returned URL, and a submit button that posts to the DC-008-01 endpoint; include client-side validation that rejects a blank title before submission with a field-level error message naming the title field _(verify: Submitting the form with a valid title, body, and image calls POST /api/admin/blog-posts and on 201 redirects to /admin/blog-posts with the new post visible in the list; submitting with a blank title shows a validation error message on the title field without making the API call; the title input has an associated label element; the body textarea has an associated label element; the image upload field has an accessible label and announces upload progress to screen readers)_

## Acceptance

- Given an authenticated admin on the blog posts section, When the admin submits a create-blog-post form with title, body content, and an image, Then the system stores the blog post in the data store and displays it in the blog posts list
- Given an authenticated admin submits a create-blog-post form with a blank title, When the system validates the submission, Then the system rejects the submission with a validation error message naming the title field
- Given an authenticated admin and an existing blog post, When the admin changes the body content and saves, Then the system updates the stored blog post and the updated content appears in the blog posts list
- Given an authenticated admin and an existing unpublished blog post, When the admin publishes the post, Then the system marks the post as published in the data store and the blog post appears on the public site
- Given an authenticated admin and an existing blog post, When the admin confirms deletion of that post, Then the system removes the blog post from the data store and the post no longer appears in the blog posts list or on the public site
