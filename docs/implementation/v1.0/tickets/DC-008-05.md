# DC-008-05 — Blog posts management UI

Admin dashboard pages at /admin/blog-posts, /admin/blog-posts/new, /admin/blog-posts/:id/edit. Forms with title, body content, and image upload. Publish button. List shows published status. Conforms to WCAG 2.2 AA.

**Contract:** Pages at /admin/blog-posts, /admin/blog-posts/new, /admin/blog-posts/:id/edit; list with title and published status; form with title, body, image upload; publish button; delete with confirmation; WCAG 2.2 AA

## Why

REQ-FUNC-022 through REQ-FUNC-025 require an admin dashboard UI for creating, editing, publishing, and deleting blog posts with title, body content, and image, conforming to WCAG 2.2 AA.

## What

Admin dashboard pages at /admin/blog-posts (list with title and published status), /admin/blog-posts/new (create form with title, body, image upload, and submit), and /admin/blog-posts/:id/edit (edit form with publish and delete-with-confirmation buttons), all conforming to WCAG 2.2 AA.

## Scope

**In:** The three admin dashboard pages, the blog post list table with published status badges, the create and edit forms with title input, body textarea, and image upload via the DC-003-01 upload endpoint, the publish button calling DC-008-03, the delete button with a confirmation dialog calling DC-008-04, form validation error display, and WCAG 2.2 AA accessibility compliance.

**Out:** The API endpoint handlers for create, edit, publish, and delete (DC-008-01, DC-008-02, DC-008-03, DC-008-04); the file upload endpoint itself (DC-003-01); Poly-X authentication and the admin route guard (DC-001-03); the public blog content display pages; the blog_posts Prisma model (DC-002-07).

## Tasks

- [ ] **T1** — Create the blog posts list page at /admin/blog-posts that fetches blog posts and renders a table with columns for title and published status, with accessible table headers, row labels, and keyboard navigation _(verify: An authenticated admin navigating to /admin/blog-posts sees a table of blog posts with each post's title and a published status badge; the table headers have proper scope attributes, rows are reachable by keyboard, and the page has no WCAG 2.2 AA violations)_
- [ ] **T2** — Create the new blog post page at /admin/blog-posts/new with a form containing a labelled title text input, a labelled body textarea, an image upload field that posts to the DC-003-01 upload endpoint and stores the returned URL, and a submit button that calls POST /api/admin/blog-posts _(verify: An admin filling in title 'Welcome to Alam Guest House', body 'We are delighted to welcome you.', and selecting an image, then submitting, receives a 201 response and the post appears in the blog posts list; all form fields have associated label elements, focus order is logical, and the form has no WCAG 2.2 AA violations)_
- [ ] **T3** — Add client-side validation to the create form that prevents submission when title is blank, displaying a validation error message naming the title field, and shows server-side 422 validation errors with field-level messages _(verify: Submitting the create form with a blank title shows a validation error message naming the title field before the request is sent; a 422 response from the server with field '/title' and code 'FIELD_REQUIRED' displays the error message next to the title field)_
- [ ] **T4** — Create the edit blog post page at /admin/blog-posts/:id/edit that loads the existing post into a form with title, body, and image fields, a save button calling PUT /api/admin/blog-posts/:id, a publish button calling PUT /api/admin/blog-posts/:id/publish, and a delete button with a confirmation dialog calling DELETE /api/admin/blog-posts/:id _(verify: An admin navigating to /admin/blog-posts/{id}/edit sees the form pre-filled with the post's current title, body, and image; saving changes calls PUT and the updated content appears in the list; clicking publish calls the publish endpoint and the status badge updates to published; clicking delete shows a confirmation dialog and confirming calls DELETE returning 204 and redirecting to the list)_
- [ ] **T5** — Ensure all user-facing text uses locale-aware string resources with no hard-coded strings, and verify the publish and delete confirmation dialog has an accessible role, focus trap, and escape-to-close behaviour _(verify: No hard-coded user-facing strings exist in the components; all text is sourced from locale resource files; the delete confirmation dialog has role 'alertdialog', traps focus within it while open, returns focus to the delete button on close, and closes on Escape key press)_
- [ ] **T6** — Write component and integration tests covering TC-036 through TC-041: create with valid data displays the post in the list, blank title shows a validation error, edit updates the body and the list reflects it, publish marks the post as published and it appears on the public site, unpublished posts do not appear on the public site, and delete with confirmation removes the post from the list and public site _(verify: TC-036: creating a post with title, body, and image stores it and it appears in the list; TC-037: blank title is rejected with a validation error naming the title field; TC-038: editing body content updates the post and the list; TC-039: publishing marks the post as published and it appears on the public site; TC-040: unpublished posts do not appear on the public site; TC-041: deleting with confirmation removes the post from the list and public site)_
- [ ] **T7** — Definition of Done: run the full test suite and an automated WCAG 2.2 AA audit on all three pages, confirm the pages are deployed to the test environment, and verify all acceptance criteria for REQ-FUNC-022 through REQ-FUNC-025 are demonstrated through the UI _(verify: All tests pass, the automated accessibility audit reports no WCAG 2.2 AA violations on /admin/blog-posts, /admin/blog-posts/new, and /admin/blog-posts/:id/edit, the pages are reachable in the test environment, and the acceptance criteria are demonstrated: create stores and displays the post, blank title is rejected, edit updates and displays the change, publish marks the post and it appears on the public site, and delete with confirmation removes the post from the list and public site)_

## Acceptance

- Given an authenticated admin on the blog posts section, When the admin submits a create-blog-post form with title, body content, and an image, Then the system stores the blog post in the data store and displays it in the blog posts list
- Given an authenticated admin submits a create-blog-post form with a blank title, When the system validates the submission, Then the system rejects the submission with a validation error message naming the title field
- Given an authenticated admin and an existing blog post, When the admin changes the body content and saves, Then the system updates the stored blog post and the updated content appears in the blog posts list
- Given an authenticated admin and an existing unpublished blog post, When the admin publishes the post, Then the system marks the post as published in the data store and the blog post appears on the public site
- Given an authenticated admin and an existing blog post, When the admin confirms deletion of that post, Then the system removes the blog post from the data store and the post no longer appears in the blog posts list or on the public site
