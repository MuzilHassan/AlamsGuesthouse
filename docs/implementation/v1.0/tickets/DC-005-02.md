# DC-005-02 — DELETE /api/admin/hero-images/:id

Remove a hero image from PostgreSQL.

**Contract:** DELETE /api/admin/hero-images/:id -> 204 | 401 | 403 | 404 | 503

## Why

REQ-FUNC-008 requires that an authenticated admin can remove an existing hero section image so it no longer appears in the hero carousel on the public site.

## What

DELETE /api/admin/hero-images/:id removes the hero image record from PostgreSQL and returns 204; it returns 404 for a non-existent id, 401 for an unauthenticated caller, 403 for a non-admin, and 503 when Poly-X is unreachable.

## Scope

**In:** The DELETE /api/admin/hero-images/:id endpoint, Poly-X introspection middleware wiring, 404 handling for a non-existent id, structured logging, and integration tests.

**Out:** The POST endpoint (DC-005-01), the reorder endpoint (DC-005-03), the admin management UI (DC-005-04), the image upload endpoint (DC-003-01), and the public hero-images read endpoint. Authentication is provided by Poly-X via DC-001-03; this unit wires it, it does not build login or token handling. The hero_images table migration is owned by DC-005-01.

## Tasks

- [ ] **T1** — Implement DELETE /api/admin/hero-images/:id to look up the hero image by id in PostgreSQL via Prisma, delete it if found, and return 204; return 404 when no record exists for the given id _(verify: DELETE /api/admin/hero-images/{existingId} returns 204 and the record is absent from the database; DELETE /api/admin/hero-images/{nonExistentId} returns 404 with an error body indicating the image was not found)_
- [ ] **T2** — Wire the Poly-X introspection middleware from DC-001-03: call polyx.auth.introspect on the bearer token, check the admin role in permissions.modulePermissions, validate the organization-id header, and fail closed with 401, 403, or 503 as specified _(verify: a DELETE with an expired token returns 401; a DELETE with a valid non-admin token returns 403; a DELETE with a mismatched organization-id header returns 403; a DELETE when Poly-X is unreachable returns 503)_
- [ ] **T3** — Add structured logging with the request id on each DELETE call, logging the outcome (deleted, not_found) and the admin userId, without logging the token _(verify: a successful delete logs the request id, userId, target image id, and outcome 'deleted'; a 404 logs the request id and outcome 'not_found'; no token value appears in any log line)_
- [ ] **T4** — Write integration tests covering TC-016: a DELETE of an existing hero image returns 204, a subsequent GET to /api/content/hero-images does not include the deleted image, a DELETE of a non-existent id returns 404, a DELETE without a token returns 401, a DELETE with a non-admin token returns 403, and a DELETE when Poly-X is unreachable returns 503 _(verify: all six test cases pass: 204 for existing id, deleted image absent from GET /api/content/hero-images, 404 for non-existent id, 401 for no token, 403 for non-admin, 503 for Poly-X unreachable)_
- [ ] **T5** — Definition of Done: confirm the endpoint returns the contract's status codes for every path, tests pass, structured logging is in place, and the endpoint is deployed to the test environment _(verify: DELETE /api/admin/hero-images/:id returns 204, 404, 401, 403, and 503 per the contract; the deleted image is absent from the public hero carousel; all integration tests pass; structured logs include the request id; the endpoint is reachable in the test environment)_

## Acceptance

- Given an authenticated admin and an existing hero section image, When the admin removes that image, Then the system removes the image from the data store and the image no longer appears in the hero carousel on the public site
