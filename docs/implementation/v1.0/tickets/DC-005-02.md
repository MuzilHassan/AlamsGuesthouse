# DC-005-02 — DELETE /api/admin/hero-images/:id

Remove a hero image from PostgreSQL.

**Contract:** DELETE /api/admin/hero-images/:id -> 204 | 401 | 403 | 404 | 503

## Why

REQ-FUNC-008 requires that an admin can remove an existing hero section image, so that it no longer appears in the hero carousel on the public site.

## What

DELETE /api/admin/hero-images/:id removes the hero image record from PostgreSQL via Prisma and returns 204, or 404 when the image does not exist.

## Scope

**In:** The DELETE /api/admin/hero-images/:id endpoint, its Prisma deletion logic, and the Poly-X introspection middleware wiring for admin authorization.

**Out:** The POST and reorder endpoints (DC-005-01, DC-005-03), the admin UI page (DC-005-04), and the public-site hero carousel rendering. Poly-X provides authentication and authorization via the introspection middleware from DC-001-03; this unit does not build login, token signing, or password handling.

## Tasks

- [ ] **T1** — Implement the DELETE /api/admin/hero-images/:id route handler that finds the hero image by id via Prisma, returns 404 if not found, deletes the record, and returns 204 with no body _(verify: DELETE /api/admin/hero-images/{existingId} returns 204 with an empty body; DELETE /api/admin/hero-images/{nonExistentId} returns 404)_
- [ ] **T2** — Wire the Poly-X introspection middleware from DC-001-03 before the handler: call polyx.auth.introspect on the bearer token, check the admin role in permissions.modulePermissions, validate the organization-id header against the token organization, and fail closed with 401 for an inactive token, 403 for a missing admin role or org-id mismatch, and 503 when Poly-X is unreachable within the 5s timeout _(verify: a DELETE request with an expired or revoked token returns 401; a valid token without admin role returns 403; a mismatched organization-id header returns 403; Poly-X unreachable returns 503; a valid admin token with matching organization-id proceeds to the handler)_
- [ ] **T3** — Add unit and integration tests covering TC-016: the 204 success path deleting an existing hero image and confirming it is absent from GET /api/content/hero-images, the 404 path for a non-existent id, the 401 unauthenticated path, the 403 missing admin role path, and the 503 Poly-X unreachable path _(verify: the test suite passes: TC-016 returns 204 for an existing heroImageId and the image is absent from GET /api/content/hero-images; 404 for a non-existent id; 401 for no token; 403 for non-admin role; 503 for Poly-X unreachable)_
- [ ] **T4** — Add structured logging with the request id on every DELETE /api/admin/hero-images/:id call, and a counter metric for hero image deletions _(verify: a successful DELETE logs a structured entry with the request id, the deleted heroImage id, and the action 'hero_image_delete'; the counter metric increments by 1 per deletion)_
- [ ] **T5** — Definition of Done: verify the endpoint is deployed to the test environment, all tests pass, the Poly-X middleware is wired, structured logging and metrics are present, and the API documentation describes the DELETE /api/admin/hero-images/:id operation with its 204, 401, 403, 404, and 503 responses _(verify: in the test environment, DELETE /api/admin/hero-images/{existingId} returns 204 for a valid admin request; the deleted image is absent from GET /api/content/hero-images; all unit and integration tests pass; the API docs list the endpoint with its response codes and the polyxBearer security scheme)_

## Acceptance

- Given an authenticated admin and an existing hero section image, When the admin removes that image, Then the system removes the image from the data store and the image no longer appears in the hero carousel on the public site
