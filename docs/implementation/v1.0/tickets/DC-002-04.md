# DC-002-04 — HeroImage table

Prisma schema for HeroImage table storing hero carousel images and display positions.

**Contract:** HeroImage { id UUID PK, cloudinary_url text not null, display_position int not null }

## Why

REQ-FUNC-020 and REQ-NFUNC-006 require hero carousel images to persist across restarts and deployments; the HeroImage table stores hero section images and their display order.

## What

A Prisma model and PostgreSQL migration for the HeroImage table with id (UUID PK), cloudinary_url (text not null), and display_position (int not null), plus its rollback migration.

## Scope

**In:** The HeroImage Prisma model definition and its up/down SQL migration only.

**Out:** Room, RoomImage, Promotion, GalleryImage, and BlogPost tables; the Prisma client generation and DATABASE_URL configuration (DC-002-07); any image upload or Cloudinary integration logic; any API endpoints that read or write hero images.

## Tasks

- [ ] **T1** — Add the HeroImage model to prisma/schema.prisma with id as UUID @id @default(uuid()), cloudinary_url as non-null String, and display_position as non-null Int _(verify: prisma validate succeeds; the HeroImage model has id UUID PK, cloudinary_url text not null, display_position int not null)_
- [ ] **T2** — Generate and apply the Prisma migration for the HeroImage table with npx prisma migrate dev --name add_hero_image_table, and confirm the down migration drops the HeroImage table cleanly _(verify: the migration creates a hero_image table with columns id, cloudinary_url, display_position matching the contract types; prisma migrate down removes the hero_image table without errors)_
- [ ] **T3** — Write a persistence test that inserts a HeroImage row, restarts the Prisma client connection, and re-reads the row to confirm it survives a connection cycle _(verify: after closing and reopening the Prisma client, the inserted HeroImage row is present with cloudinary_url and display_position unchanged, satisfying TC-031 for the HeroImage table)_
- [ ] **T4** — Definition of Done: run prisma validate, run the migration up and down, run the persistence test, and confirm the schema is committed _(verify: prisma validate passes, migrate up creates the hero_image table with the contract columns, migrate down removes it cleanly, the persistence test passes with no data loss across a connection restart, and the migration file is committed to the repository)_

- Given managed content in the data store, When the application undergoes a restart or deployment, Then an inspection of the data store shows all managed content present and unchanged
