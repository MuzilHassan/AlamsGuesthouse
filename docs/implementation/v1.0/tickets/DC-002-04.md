# DC-002-04 — HeroImage table

Prisma schema for HeroImage table storing hero carousel images and display positions.

**Contract:** HeroImage { id UUID PK, cloudinary_url text not null, display_position int not null }

## Why

REQ-FUNC-020 and REQ-NFUNC-006 require hero carousel images to persist across restarts and deployments so the homepage hero section remains populated without data loss.

## What

A HeroImage table in PostgreSQL 16 defined via a Prisma 6 schema with migration and rollback, storing Cloudinary URLs and display positions for hero carousel images.

## Scope

**In:** The Prisma model and migration for the HeroImage table only: columns id (UUID PK), cloudinary_url (text not null), display_position (int not null).

**Out:** RoomImage, GalleryImage, and other image tables; the Prisma client configuration (DC-002-07); any image upload or Cloudinary integration; API endpoints that serve hero images.

## Tasks

- [ ] **T1** — Add the HeroImage model to prisma/schema.prisma with id as @id @db.Uuid, cloudinary_url as String not null, display_position as Int not null _(verify: prisma validate succeeds and the HeroImage model matches the contract fields and types exactly)_
- [ ] **T2** — Generate the Prisma migration for the HeroImage table (prisma migrate dev --name add_hero_image_table) and verify the up SQL creates the hero_image table with all contract columns _(verify: the migration SQL creates hero_image with id uuid PK default gen_random_uuid(), cloudinary_url text not null, display_position int not null)_
- [ ] **T3** — Write the down migration that drops the hero_image table, so the migration is reversible _(verify: running the down migration removes the hero_image table cleanly)_
- [ ] **T4** — Write a unit test that inserts a HeroImage record, simulates a restart by re-instantiating the PrismaClient, and reads the record back to confirm it is present and unchanged _(verify: the test inserts a hero_image with cloudinary_url and display_position 1, re-instantiates the client, reads the record and confirms all fields match; TC-031 is demonstrated)_
- [ ] **T5** — Definition of Done: run prisma validate, apply the migration and its rollback, and run the persistence test suite for HeroImage _(verify: prisma validate passes, the hero_image migration applies and rolls back without error, the persistence test passes confirming hero image content survives a simulated restart, and the schema is committed)_

## Acceptance

- Given managed content stored in the data store, When the application is restarted or redeployed, Then the managed content remains available in the data store unchanged
- Given managed content in the data store, When the application undergoes a restart or deployment, Then an inspection of the data store shows all managed content present and unchanged
