# DC-007-04 — Gallery management UI

Admin dashboard page at /admin/gallery showing gallery images with captions and alt text. Add, edit, and remove controls. Image upload calls /api/admin/upload. Conforms to WCAG 2.2 AA.

**Contract:** Page at /admin/gallery; grid of gallery images with caption and alt text; add form with image upload, caption, alt text; edit form for caption and alt text; remove button; WCAG 2.2 AA

## Why

REQ-FUNC-016, REQ-FUNC-017, and REQ-FUNC-018 require that an admin can add, edit, and remove gallery images through the dashboard, so the admin needs a single management interface at /admin/gallery.

## What

An admin dashboard page at /admin/gallery showing a grid of gallery images with their captions and alt text, with add, edit, and remove controls, conforming to WCAG 2.2 AA.

## Scope

**In:** The /admin/gallery page component, the image grid display, the add form (image upload via DC-003-01 then POST via DC-007-01), the edit form (PUT via DC-007-02), the remove button (DELETE via DC-007-03), accessibility (WCAG 2.2 AA), and internationalisation.

**Out:** The POST, PUT, and DELETE gallery API endpoints (DC-007-01, DC-007-02, DC-007-03), the image upload endpoint (DC-003-01), the Poly-X SDK and auth middleware (DC-001-03), the Prisma schema (DC-002-07), the public gallery display, and authentication or notification delivery (Poly-X provides these).

## Tasks

- [ ] **T1** — Scaffold the /admin/gallery page component with a server-side auth() check that redirects unauthenticated users to /sign-in, and fetch the gallery images from the content API to render a grid showing each image's thumbnail, caption, and alt text _(verify: an authenticated admin visiting /admin/gallery sees a grid of gallery images with their captions and alt text; an unauthenticated visitor is redirected to /sign-in)_
- [ ] **T2** — Implement the add form: a file input that uploads the image via POST /api/admin/upload (DC-003-01), and fields for caption, alt text, and display position that submit via POST /api/admin/gallery (DC-007-01); refresh the grid on success and show a 422 validation error inline if cloudinaryUrl or displayPosition is missing _(verify: submitting the add form with an image, caption 'Garden view', altText 'Garden view from terrace', and displayPosition 1 creates the gallery image and it appears in the grid; submitting without an image shows a validation error)_
- [ ] **T3** — Implement the edit form: an inline or modal form pre-populated with the current caption and alt text that submits via PUT /api/admin/gallery/:id (DC-007-02); refresh the grid on success and show a 404 error if the image was removed by another admin _(verify: editing an image's caption to 'Poolside view' and altText to 'Poolside view from room balcony' and saving updates the grid to show the new values; editing a since-deleted image shows a not-found error)_
- [ ] **T4** — Implement the remove button with a confirmation dialog that calls DELETE /api/admin/gallery/:id (DC-007-03); remove the image from the grid on 204 and show a 404 error if the image was already removed _(verify: clicking remove and confirming on an existing image removes it from the grid; the image no longer appears in the gallery on the public site; removing a since-deleted image shows a not-found error)_
- [ ] **T5** — Apply WCAG 2.2 AA accessibility: associate labels with all form fields (caption, alt text, display position, file input), ensure all controls are keyboard-reachable with visible focus, manage focus on add/edit/remove actions, verify colour contrast meets AA, and provide an alt text preview for each image; ensure no user-facing text is hard-coded by using the project's locale and message files _(verify: all form fields have programmatically associated labels; the add, edit, and remove flows are operable by keyboard alone with visible focus indicators; colour contrast meets WCAG 2.2 AA; user-facing strings are sourced from locale message files, not inline literals)_
- [ ] **T6** — Write component and integration tests covering TC-026 (add flow creates image and it appears in the grid), TC-027 (edit flow updates caption and altText and the grid reflects changes), and TC-028 (remove flow deletes image and it is absent from the public gallery) _(verify: TC-026 passes: the add form creates a gallery image that appears in the grid; TC-027 passes: the edit form updates caption and altText and the grid reflects the changes; TC-028 passes: the remove button deletes the image and it is absent from GET /api/content/gallery)_
- [ ] **T7** — Definition of Done: run the full test suite for the gallery management UI, confirm all acceptance criteria for REQ-FUNC-016, REQ-FUNC-017, and REQ-FUNC-018 are demonstrated through the UI, confirm accessibility passes WCAG 2.2 AA audit, and confirm the page is deployed to the test environment _(verify: all tests pass (TC-026, TC-027, TC-028 are green), the add/edit/remove flows work end to end through the UI, the page passes a WCAG 2.2 AA accessibility audit, locale strings are used for all user-facing text, and /admin/gallery is reachable in the test environment)_

## Acceptance

- Given an authenticated admin on the gallery management interface, When the admin uploads an image and enters a caption and alt text, Then the system stores the image reference, caption, and alt text in the data store and the image appears in the gallery management list
- Given an authenticated admin and an existing gallery image, When the admin changes the caption to 'Poolside view' and the alt text to 'Poolside view from room balcony' and saves, Then the system stores the updated caption and alt text and the gallery management list reflects the changes
- Given an authenticated admin and an existing gallery image, When the admin removes that image, Then the system removes the image, caption, and alt text from the data store and the image no longer appears in the gallery on the public site
