# DC-007-04 — Gallery management UI

Admin dashboard page at /admin/gallery showing gallery images with captions and alt text. Add, edit, and remove controls. Image upload calls /api/admin/upload. Conforms to WCAG 2.2 AA.

**Contract:** Page at /admin/gallery; grid of gallery images with caption and alt text; add form with image upload, caption, alt text; edit form for caption and alt text; remove button; WCAG 2.2 AA

## Why

REQ-FUNC-016, REQ-FUNC-017, and REQ-FUNC-018 require an admin dashboard interface for adding, editing, and removing gallery images with caption and alt text, so that an admin can manage the gallery without developer intervention.

## What

An admin dashboard page at /admin/gallery showing a grid of gallery images with their captions and alt text, an add form with image upload, caption, and alt text, an edit form for caption and alt text, and a remove button, all conforming to WCAG 2.2 AA.

## Scope

**In:** The /admin/gallery page component, the image grid, the add form (image upload via DC-003-01, caption, alt text, display position), the edit form (caption, alt text), the remove button, and all client-side calls to POST, PUT, and DELETE /api/admin/gallery endpoints.

**Out:** Does not build the API endpoints themselves (DC-007-01, DC-007-02, DC-007-03), the image upload service (DC-003-01), the public gallery display, or any authentication or session handling (Poly-X provides it).

## Tasks

- [ ] **T1** — Scaffold the /admin/gallery page component with a responsive grid that fetches the current gallery images and displays each image thumbnail with its caption and alt text, using semantic HTML (figure, figcaption) and ARIA labels for screen readers _(verify: the page renders a grid of gallery images with each thumbnail, caption, and alt text visible; each image is wrapped in a figure element with a figcaption; keyboard focus reaches each grid item in a logical order)_
- [ ] **T2** — Build the add form with an image upload input that posts the file to /api/admin/upload (DC-003-01), and fields for caption, alt text, and display position, with all user-facing text sourced from locale strings (no hard-coded text) and labels associated with their inputs via htmlFor/id _(verify: the add form shows file upload, caption, alt text, and display position fields; each field has a visible label linked by htmlFor/id; all user-facing strings come from the locale file, not inline literals; uploading a file calls /api/admin/upload and receives a cloudinaryUrl)_
- [ ] **T3** — Wire the add form submit to POST /api/admin/gallery (DC-007-01) with the returned cloudinaryUrl, caption, altText, and displayPosition, and on 201 refresh the grid to show the new image; handle 422 by showing field-level validation errors, 401 by redirecting to sign-in, 403 by showing a permission-denied message, and 503 by showing a service-unavailable message _(verify: submitting the add form with a valid image, caption 'Garden view', altText 'Garden view from terrace', and displayPosition 1 calls POST /api/admin/gallery and the new image appears in the grid; a 422 response shows field-level error messages; a 401 redirects to sign-in; a 403 shows a permission-denied message; a 503 shows a service-unavailable message)_
- [ ] **T4** — Build the edit form for an existing gallery image with editable caption and alt text fields, and wire its submit to PUT /api/admin/gallery/:id (DC-007-02); on 200 refresh the grid to reflect the changes; handle 404 by showing a not-found message, 422 by showing field-level errors, 401 by redirecting to sign-in, 403 by showing a permission-denied message, and 503 by showing a service-unavailable message _(verify: editing caption to 'Poolside view' and altText to 'Poolside view from room balcony' and saving calls PUT /api/admin/gallery/:id and the grid reflects the updated values; a 404 shows a not-found message; a 422 shows field-level errors; a 401 redirects to sign-in; a 403 shows a permission-denied message; a 503 shows a service-unavailable message)_
- [ ] **T5** — Build the remove button for each gallery image with a confirmation dialog, and wire it to DELETE /api/admin/gallery/:id (DC-007-03); on 204 remove the image from the grid; handle 404 by showing a not-found message, 401 by redirecting to sign-in, 403 by showing a permission-denied message, and 503 by showing a service-unavailable message _(verify: clicking remove shows a confirmation dialog; confirming calls DELETE /api/admin/gallery/:id and the image disappears from the grid on 204; a 404 shows a not-found message; a 401 redirects to sign-in; a 403 shows a permission-denied message; a 503 shows a service-unavailable message)_
- [ ] **T6** — Verify WCAG 2.2 AA conformance: ensure all interactive elements are keyboard reachable with visible focus indicators, color contrast meets 4.5:1 for text and 3:1 for large text and UI components, the confirmation dialog traps focus and returns it on close, and all images have non-empty alt text or an explicit empty alt decorative marker _(verify: keyboard-only navigation can add, edit, and remove gallery images; focus is visible on every interactive element; the confirmation dialog traps focus and restores it to the remove button on close; an automated contrast audit passes at WCAG 2.2 AA; every gallery image has alt text or an explicit decorative marker)_
- [ ] **T7** — Add integration tests covering TC-026 (add image appears in grid), TC-027 (edit reflects in grid), and TC-028 (remove removes from grid and image is absent from public gallery), and add structured logging on the client for each action with the request id _(verify: the TC-026 test asserts that after adding an image it appears in the grid; the TC-027 test asserts that after editing, the grid shows the updated caption and alt text; the TC-028 test asserts that after removing, the image is absent from the grid and from GET /api/content/gallery; client-side logs include the request id for each action)_
- [ ] **T8** — Definition of Done: run the full test suite, confirm the page is accessible at /admin/gallery behind the Poly-X admin role check, confirm the locale file has all user-facing strings, and confirm the page is deployed to the test environment _(verify: all tests pass; navigating to /admin/gallery as an admin renders the management page; navigating without the admin role redirects to sign-in; the locale file contains every user-facing string used by the page; the page renders on the test environment)_

## Acceptance

- Given an authenticated admin on the gallery management interface, When the admin uploads an image and enters a caption and alt text, Then the system stores the image reference, caption, and alt text in the data store and the image appears in the gallery management list
- Given an authenticated admin and an existing gallery image, When the admin changes the caption to 'Poolside view' and the alt text to 'Poolside view from room balcony' and saves, Then the system stores the updated caption and alt text and the gallery management list reflects the changes
- Given an authenticated admin and an existing gallery image, When the admin removes that image, Then the system removes the image, caption, and alt text from the data store and the image no longer appears in the gallery on the public site
