# DC-007-01 — POST /api/admin/gallery

Add a gallery image. Accepts Cloudinary URL, caption, alt text, and display position.

**Contract:** POST /api/admin/gallery { cloudinaryUrl, caption?, altText?, displayPosition } -> 201 { galleryImage } | 401 | 403 | 422 | 503

## Why

REQ-FUNC-016 requires that an admin can add gallery images with caption and alt text through the dashboard, so that the public gallery stays current with the property's visuals.

## What

POST /api/admin/gallery accepts a Cloudinary URL, optional caption, optional alt text, and display position, persists them to the gallery_images table, and returns 201 with the created galleryImage object.

## Scope

**In:** The POST /api/admin/gallery route handler, its request validation, the Prisma insert into the gallery_images table, the Poly-X introspection middleware wiring, and the structured log with request id.

**Out:** Does not build the image upload to Cloudinary (provided by DC-003-01), the gallery management UI (DC-007-04), the PUT or DELETE endpoints (DC-007-02, DC-007-03), or any authentication or session handling (Poly-X provides it).

## Tasks

- [ ] **T1** — Add the gallery_images table migration to the Prisma schema with columns id, cloudinaryUrl, caption, altText, displayPosition, createdAt, updatedAt, and a unique index on id, per the DC-002-07 schema contract _(verify: prisma migrate dev creates the gallery_images table with the listed columns and unique index on id; prisma generate produces a GalleryImage model with all fields typed)_
- [ ] **T2** — Scaffold the POST /api/admin/gallery route handler that validates the request body for required cloudinaryUrl and displayPosition, optional caption and altText, returning 422 with a field-specific error code for a missing cloudinaryUrl or a non-integer displayPosition _(verify: POST /api/admin/gallery with a missing cloudinaryUrl returns 422 with code CLOUDINARY_URL_REQUIRED; POST with a non-integer displayPosition returns 422 with code DISPLAY_POSITION_INVALID; a valid body passes validation to the handler logic)_
- [ ] **T3** — Wire the Poly-X introspection middleware from DC-001-03 before the handler: call polyx.auth.introspect on the Bearer token, check the admin role in permissions.modulePermissions, validate the organization-id header against the token's organizationId, and fail closed with 401 for an inactive token, 403 for a missing admin role or org-id mismatch, and 503 when Poly-X is unreachable within the 5s timeout _(verify: a request with an expired token returns 401 with shouldRelogin true; a request with a valid token but no admin role returns 403; a request with a mismatched organization-id header returns 403; when Poly-X is unreachable the endpoint returns 503 within 5s)_
- [ ] **T4** — Implement the handler logic that inserts a new gallery_images row via the Prisma client with cloudinaryUrl, caption, altText, and displayPosition, and returns 201 with the created galleryImage object and a Location header _(verify: POST /api/admin/gallery with cloudinaryUrl, caption 'Garden view', altText 'Garden view from terrace', and displayPosition 1 returns 201 with a galleryImage object containing those values and a Location header pointing to the new resource)_
- [ ] **T5** — Add structured logging with the request id, user id, and action 'gallery_image_create' on both success and error paths, and add a unit test and an integration test covering TC-026 (success), 422 validation, 401 unauthenticated, 403 forbidden, and 503 Poly-X unreachable _(verify: the integration test for TC-026 asserts 201 with the galleryImage object matching the input; the 422, 401, 403, and 503 test cases each assert the correct status and error code; structured logs include the request id on all paths)_
- [ ] **T6** — Definition of Done: run the full test suite, confirm the migration applies and rolls back cleanly, confirm the endpoint is registered in the API route documentation, and confirm the endpoint is deployed to the test environment _(verify: all tests pass; prisma migrate reset followed by prisma migrate dev restores the gallery_images table; the OpenAPI spec lists POST /api/admin/gallery with its 201, 401, 403, 422, and 503 responses; the endpoint responds on the test environment)_
