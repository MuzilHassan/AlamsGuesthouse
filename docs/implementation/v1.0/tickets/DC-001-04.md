# DC-001-04 — Admin sign-in page

/sign-in page rendering <SignIn> from @poly-x/next with forgotPasswordUrl='/forgot-password'. MFA steps appear inside <SignIn> automatically. onRecoveryCodes handler fires once before redirect.

**Contract:** <SignIn forgotPasswordUrl='/forgot-password' onRecoveryCodes={showOnce} /> at /sign-in; import @poly-x/next/styles.css; MFA steps inline; redirects to /admin on success

## Why

REQ-FUNC-001 and REQ-FUNC-002 require an admin sign-in surface where MFA is prompted and the dashboard is accessible only after the second factor is verified. The sign-in page renders the Poly-X SignIn component, so the product does not build a login form, password handling, or MFA flow itself.

## What

The /sign-in page renders <SignIn> from @poly-x/next with forgotPasswordUrl='/forgot-password' and onRecoveryCodes wired to display recovery codes once, the @poly-x/next/styles.css stylesheet is imported once before the Tailwind entry, MFA steps appear inside <SignIn> automatically, and successful sign-in redirects to /admin.

## Scope

**In:** The /sign-in page component, the @poly-x/next/styles.css import, the onRecoveryCodes handler, and the afterSignInPath redirect to /admin.

**Out:** The BFF catch-all route (DC-001-01) that the SignIn component posts to, the edge gate (DC-001-02) that protects /admin/*, the introspection middleware (DC-001-03), and the account lifecycle pages (DC-001-05). Poly-X provides the SignIn component, the MFA challenge, and the recovery code generation; this unit only renders and wires them. No password store or token signing is built here.

## Acceptance

- Given an unauthenticated request to any admin dashboard route, When the system checks the Poly-X session, Then the system returns HTTP 401 and does not display the dashboard
- Given an authenticated request whose Poly-X token lacks the admin role, When the system checks the role grant, Then the system returns HTTP 403 and does not display the dashboard
- Given an authenticated request with the admin role, When the system checks the Poly-X session, Then the system grants access to the admin dashboard
- Given an administrator entering valid credentials, When the Poly-X sign-in flow prompts for a second factor, Then the dashboard is accessible only after the second factor is verified
