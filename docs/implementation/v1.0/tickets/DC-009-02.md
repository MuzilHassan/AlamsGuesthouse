# DC-009-02 — GET /api/content/hero-images

Public endpoint returning hero images in display order. No authentication required.

**Contract:** GET /api/content/hero-images -> 200 { heroImages: [{ id, cloudinaryUrl, displayPosition }] } | 500; ordered by display_position

## Why

Site visitors need to see hero images in the correct display order from the data store, so that managed hero content appears on the public site without manual code changes to static files.

## What

A public API route at /api/content/hero-images that returns 200 with hero image data including id, cloudinaryUrl, and displayPosition from PostgreSQL via Prisma ordered by display_position, or 500 on a data store error, with no authentication required.

## Scope

**In:** The GET /api/content/hero-images route handler, its Prisma query ordering by display_position, and the response shape.

**Out:** The Prisma schema and database setup (DC-002-07), the rooms endpoint (DC-009-01), the gallery endpoint (DC-009-03), the blog-posts endpoint (DC-009-04), and the component modifications (DC-009-05). No authentication or Poly-X integration.

## Tasks

- [ ] **T1** — Create the route handler at app/api/content/hero-images/route.ts that queries Prisma for hero images ordered by display_position ascending _(verify: GET /api/content/hero-images returns 200 with a heroImages array where each item has id, cloudinaryUrl, and displayPosition, and the items are ordered by display_position ascending)_
- [ ] **T2** — Add the 500 error response path for when the Prisma query fails, returning a JSON error body without leaking database details _(verify: GET /api/content/hero-images returns 500 with a JSON error response when the database is unreachable; the response body does not expose connection strings or query text)_
- [ ] **T3** — Write the integration test covering TC-029 step 2: seed hero images in the data store, then GET /api/content/hero-images and assert the response _(verify: the integration test sends GET /api/content/hero-images and asserts 200 with heroImages matching the seeded data store, ordered by display_position ascending)_
- [ ] **T4** — Definition of Done check for the hero-images endpoint _(verify: GET /api/content/hero-images returns 200 with hero images from PostgreSQL ordered by display_position, returns 500 on database error, requires no authentication, makes no Poly-X API calls, the integration test for TC-029 passes, and the route is deployed to the test environment)_

## Acceptance

- Given room listings, hero images, gallery images, and blog posts stored in the data store, When a site visitor loads the public website, Then the public site displays content read from the data store
- Given the data store contains a room priced at 4000, When a site visitor loads the room listing page, Then the public site displays 4000 for that room
