# DC-009-02 — GET /api/content/hero-images

Public endpoint returning hero images in display order. No authentication required.

**Contract:** GET /api/content/hero-images -> 200 { heroImages: [{ id, cloudinaryUrl, displayPosition }] } | 500; ordered by display_position

## Why

Site visitors need to see hero images served from the data store (REQ-FUNC-019), so that managed hero carousel content appears on the public site without manual data file edits.

## What

A public GET /api/content/hero-images endpoint that returns hero images in display order from PostgreSQL via Prisma, returning 200 on success and 500 on database failure, with no authentication required.

## Scope

**In:** The route handler at app/api/content/hero-images/route.ts, the Prisma query for hero images ordered by display_position, response mapping to the contract shape, and error handling for the 500 path.

**Out:** Does not build the rooms, gallery, or blog-posts endpoints (DC-009-01, DC-009-03, DC-009-04); does not modify public-facing components (DC-009-05); does not implement Poly-X authentication or authorization, as this is a public endpoint with no auth required; does not define the Prisma schema or migrations (DC-002-07).

## Tasks

- [ ] **T1** — Create app/api/content/hero-images/route.ts with a GET handler that queries the Prisma client for all hero images ordered by display_position ascending _(verify: GET /api/content/hero-images returns 200 with a heroImages array where each item has id, cloudinaryUrl, and displayPosition; the array is ordered by display_position ascending)_
- [ ] **T2** — Add a try/catch around the Prisma query that returns 500 with a structured error log including the request id when the database query fails _(verify: When the Prisma client throws, GET /api/content/hero-images returns 500 and the server log contains the request id and the error message)_
- [ ] **T3** — Write an integration test that seeds three hero images with display positions 3, 1, 2, sends GET /api/content/hero-images, and asserts the response _(verify: The test asserts 200 status and the heroImages array is ordered by display_position (1, 2, 3), with each item containing id, cloudinaryUrl, and displayPosition matching the seeded data (TC-029 hero-images step))_
- [ ] **T4** — Definition of Done: confirm the endpoint is deployed to the test environment, the integration test passes, the 500 error path is covered, and the API route is documented in the project API reference _(verify: GET /api/content/hero-images returns 200 with hero images from PostgreSQL ordered by display_position; the integration test passes; the 500 path returns a structured error; the endpoint is reachable in the test environment with no authentication header)_

## Acceptance

- Given room listings, hero images, gallery images, and blog posts stored in the data store, When a site visitor loads the public website, Then the public site displays content read from the data store
- Given the data store contains a room priced at 4000, When a site visitor loads the room listing page, Then the public site displays 4000 for that room
