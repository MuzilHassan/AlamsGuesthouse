# DC-005-01 — POST /api/admin/hero-images

Add a hero image. Accepts a Cloudinary URL and display position, stores in PostgreSQL.

**Contract:** POST /api/admin/hero-images { cloudinaryUrl, displayPosition } -> 201 { heroImage } | 401 | 403 | 422 | 503

## Why

REQ-FUNC-007 requires that an admin can add a hero section image with a display position to the homepage carousel, so that the image appears in the hero carousel management list.

## What

POST /api/admin/hero-images accepts a Cloudinary URL and display position, stores the hero image reference in PostgreSQL via Prisma, and returns 201 with the created heroImage object.

## Scope

**In:** The POST /api/admin/hero-images endpoint, its request validation, Prisma persistence of the hero image record, and the Poly-X introspection middleware wiring for admin authorization.

**Out:** The DELETE and reorder endpoints (DC-005-02, DC-005-03), the admin UI page (DC-005-04), the Cloudinary upload endpoint (DC-003-01), and the public-site hero carousel rendering. Poly-X provides authentication and authorization via the introspection middleware from DC-001-03; this unit does not build login, token signing, or password handling.
