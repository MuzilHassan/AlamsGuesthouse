# DC-005-01 — POST /api/admin/hero-images

Add a hero image. Accepts a Cloudinary URL and display position, stores in PostgreSQL.

**Contract:** POST /api/admin/hero-images { cloudinaryUrl, displayPosition } -> 201 { heroImage } | 401 | 403 | 422 | 503

## Why

REQ-FUNC-007 requires that an authenticated admin can add a hero section image with a display position so it appears in the hero carousel management list.

## What

POST /api/admin/hero-images accepts a cloudinaryUrl and displayPosition, stores them in PostgreSQL, and returns 201 with the created heroImage object; it returns 422 for an invalid body, 401 for an unauthenticated caller, 403 for a non-admin, and 503 when Poly-X is unreachable.

## Scope

**In:** The POST /api/admin/hero-images endpoint, the hero_images table migration with its down migration, input validation, Poly-X introspection middleware wiring, structured logging, and integration tests.

**Out:** The DELETE endpoint (DC-005-02), the reorder endpoint (DC-005-03), the admin management UI (DC-005-04), the image upload endpoint (DC-003-01), and the public hero-images read endpoint. Authentication is provided by Poly-X via the introspection contract from DC-001-03; this unit wires it, it does not build login, token signing, or password handling.

## Tasks

- [ ] **T1** — Add the hero_images table Prisma migration with columns id (uuid PK), cloudinaryUrl (text, not null), displayPosition (integer, not null), createdAt, updatedAt, and a unique index on displayPosition; include the down migration that drops the table and index _(verify: the migration creates hero_images with the columns and unique index on displayPosition; the down migration drops the table and index cleanly; prisma generate succeeds against the updated schema)_
- [ ] **T2** — Implement POST /api/admin/hero-images to accept { cloudinaryUrl, displayPosition }, validate that cloudinaryUrl is a non-empty string and displayPosition is a positive integer, persist via Prisma, and return 201 with the created heroImage object _(verify: POST /api/admin/hero-images with a valid cloudinaryUrl and displayPosition 1 returns 201 with the heroImage object containing id, cloudinaryUrl, and displayPosition; a request missing cloudinaryUrl returns 422; a request with a non-integer displayPosition returns 422)_
- [ ] **T3** — Wire the Poly-X introspection middleware from DC-001-03: call polyx.auth.introspect on the bearer token, check the admin role in permissions.modulePermissions, validate the organization-id header against the token organization, and fail closed with 401 for an inactive token, 403 for a missing admin role or org-id mismatch, and 503 when Poly-X is unreachable within the 5s timeout _(verify: a request with a valid admin token and matching organization-id header passes through to the handler; a request with an expired token returns 401; a request with a valid token lacking the admin role returns 403; a request with a mismatched organization-id header returns 403; a request when Poly-X is unreachable returns 503)_
- [ ] **T4** — Add structured logging with the request id on each POST /api/admin/hero-images call, logging the outcome (created, rejected) and the admin userId from the introspected token, without logging the token itself _(verify: a successful create logs the request id, userId, and outcome 'created'; a 422 rejection logs the request id and outcome 'rejected' with the validation reason; no token value appears in any log line)_
- [ ] **T5** — Write integration tests covering TC-015: a valid POST returns 201 with the heroImage object whose cloudinaryUrl and displayPosition match the request; a POST with a missing cloudinaryUrl returns 422; a POST without a bearer token returns 401; a POST with a non-admin token returns 403; a POST when Poly-X is unreachable returns 503 _(verify: all five test cases pass: 201 with correct heroImage body, 422 for missing cloudinaryUrl, 401 for no token, 403 for non-admin, 503 for Poly-X unreachable; the created image appears in the hero carousel management list on a subsequent GET)_
