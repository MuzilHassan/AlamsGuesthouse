# DC-001-01 — Poly-X BFF catch-all route

Mount createPolyXHandler() at app/api/polyx/[...polyx]/route.ts for sign-in, callback, refresh, signout, MFA, claiming, and session actions. The browser never holds a token; the session is an AES-GCM sealed httpOnly cookie.

**Contract:** createPolyXHandler() at app/api/polyx/[...polyx]/route.ts; env: NEXT_PUBLIC_POLYX_PUBLISHABLE_KEY (pk_), POLYX_SESSION_SECRET, POLYX_BASE_URL, POLYX_COOKIE_SECURE; handles sign-in, callback, refresh, signout, MFA, claiming; 404 unknown segments, 405 wrong methods

## Why

REQ-FUNC-001 and REQ-FUNC-002 require authenticated admin sessions with MFA before any dashboard route is accessible. The BFF catch-all route is the entry point for Poly-X sign-in, callback, refresh, signout, and MFA flows, so that the browser never holds a token and the session is sealed in an httpOnly cookie.

## What

The createPolyXHandler() catch-all route is mounted at app/api/polyx/[...polyx]/route.ts, the four required environment variables are named in the environment configuration, and the handler dispatches sign-in, callback, refresh, signout, MFA, and claiming actions, returning 404 for unknown segments and 405 for wrong methods.

## Scope

**In:** The Poly-X BFF catch-all route file at app/api/polyx/[...polyx]/route.ts and the environment variable names NEXT_PUBLIC_POLYX_PUBLISHABLE_KEY, POLYX_SESSION_SECRET, POLYX_BASE_URL, and POLYX_COOKIE_SECURE in the environment configuration.

**Out:** The edge gate middleware (DC-001-02), the token introspection and role enforcement middleware (DC-001-03), the sign-in page UI (DC-001-04), and the account lifecycle pages (DC-001-05). Poly-X provides the authentication, session, and MFA flows; this unit only mounts the handler.

## Acceptance

- Given an unauthenticated request to any admin dashboard route, When the system checks the Poly-X session, Then the system returns HTTP 401 and does not display the dashboard
- Given an authenticated request whose Poly-X token lacks the admin role, When the system checks the role grant, Then the system returns HTTP 403 and does not display the dashboard
- Given an authenticated request with the admin role, When the system checks the Poly-X session, Then the system grants access to the admin dashboard
- Given an administrator entering valid credentials, When the Poly-X sign-in flow prompts for a second factor, Then the dashboard is accessible only after the second factor is verified
