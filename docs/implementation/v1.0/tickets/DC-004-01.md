# DC-004-01 — POST /api/admin/rooms

Create a room listing. Validates with zod (name non-blank, price positive, max occupancy positive). Stores room and any associated image URLs in PostgreSQL. Returns 201 with the created room.

**Contract:** POST /api/admin/rooms { name, description, amenities[], imageUrls[], maxOccupancy, price } -> 201 { room } | 401 | 403 | 422 validation error | 503

## Why

REQ-FUNC-004 requires that an authenticated admin can create a room listing with name, description, amenities, images, maximum occupancy, and price, and have it stored and displayed in the room listings list.

## What

A POST /api/admin/rooms endpoint that validates the request body with zod, stores the room and its image URLs in PostgreSQL via Prisma, and returns 201 with the created room object and a Location header, or 422 on validation failure, 401/403 on auth failure, 503 when Poly-X is unreachable.

## Scope

**In:** The POST /api/admin/rooms endpoint, its zod validation schema (name non-blank, price positive, maxOccupancy positive), the Prisma create logic for the room and its associated image URLs, and the Poly-X introspection middleware wiring for admin authorization.

**Out:** Does not build the room listings UI (DC-004-05), the edit endpoint (DC-004-02), the delete endpoint (DC-004-03), the price-only update endpoint (DC-004-04), the image upload endpoint (DC-003-01), or the Prisma schema itself (DC-002-07). Poly-X provides authentication and authorization; this unit only wires the introspection middleware from DC-001-03.

## Tasks

- [ ] **T1** — Add the zod validation schema for the create-room request body: name non-blank string, description optional string, amenities array of strings, imageUrls array of URL strings, maxOccupancy positive integer, price object with positive amount and currency string _(verify: the schema accepts a body with name 'Deluxe Room', amenities ['WiFi','AC'], imageUrls ['https://res.cloudinary.com/test/img1.jpg'], maxOccupancy 2, price { amount: '3000.00', currency: 'PKR' } and rejects a body with name set to an empty string with a field '/name' error)_
- [ ] **T2** — Wire the Poly-X introspection middleware from DC-001-03 on the POST /api/admin/rooms route: call polyx.auth.introspect on the Bearer token, check the admin role in permissions.modulePermissions, validate the organization-id header against the token's organizationId, fail closed with 401 for inactive token, 403 for missing admin role or org-id mismatch, 503 when Poly-X is unreachable within the 5s timeout _(verify: a request without a Bearer token returns 401, a request with a valid token but no admin role returns 403, a request with a mismatched organization-id header returns 403, and a request when Poly-X is unreachable returns 503)_
- [ ] **T3** — Implement the POST /api/admin/rooms handler: validate the body with the zod schema returning 422 with error code VALIDATION_ERROR and an errors array on failure, create the room and associated RoomImage records in PostgreSQL via the Prisma client from DC-002-07, return 201 with the created room object and a Location header pointing to the new resource _(verify: POST /api/admin/rooms with a valid body returns 201 with the created room object and a Location header, and the room is persisted in PostgreSQL; POST with name set to an empty string returns 422 with error code VALIDATION_ERROR and an errors array containing an item with field '/name' and code 'FIELD_REQUIRED', and no room is stored)_
- [ ] **T4** — Add structured logging with the request id on the create-room handler: log the admin userId, organizationId, the created room id on success, and the validation error details on 422 _(verify: a successful create logs the userId, organizationId, and room id with the request id; a 422 response logs the validation error fields with the request id)_
- [ ] **T5** — Write integration tests covering TC-010 (valid create returns 201 with room and Location header, room appears in list) and TC-011 (blank name returns 422 with VALIDATION_ERROR and field '/name', no room stored) _(verify: TC-010 passes: POST with all required fields returns 201, the room object matches the input, a Location header is present, and a subsequent GET to the room listings list includes the new room; TC-011 passes: POST with empty name returns 422 with error code VALIDATION_ERROR and errors array item { field: '/name', code: 'FIELD_REQUIRED' }, and no room is in the data store)_
- [ ] **T6** — Definition of Done: all tests pass, the endpoint returns 201 with Location for valid input and 422 with field-level errors for a blank name, 401/403/503 auth paths are covered, structured logs include the request id, and the endpoint is deployed to the test environment _(verify: the test suite passes, TC-010 and TC-011 are green, a curl to the test environment POST /api/admin/rooms with a valid body returns 201 with a Location header, and a curl with a blank name returns 422 with field '/name')_

## Acceptance

- Given an authenticated admin on the room listings section, When the admin submits a create-room form with name, description, amenities, images, maximum occupancy, and price, Then the system stores the room listing in the data store and displays it in the room listings list
- Given an authenticated admin submits a create-room form with a blank name, When the system validates the submission, Then the system rejects the submission with a validation error message naming the name field
