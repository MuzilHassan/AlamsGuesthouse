# DC-004-01 — POST /api/admin/rooms

Create a room listing. Validates with zod (name non-blank, price positive, max occupancy positive). Stores room and any associated image URLs in PostgreSQL. Returns 201 with the created room.

**Contract:** POST /api/admin/rooms { name, description, amenities[], imageUrls[], maxOccupancy, price } -> 201 { room } | 401 | 403 | 422 validation error | 503

## Why

REQ-FUNC-004 requires that an authenticated admin can create a room listing with name, description, amenities, images, maximum occupancy, and price, so that the room is stored and appears in the room listings list.

## What

POST /api/admin/rooms returns 201 with the created room and a Location header for a valid body, 422 for validation failures (blank name, non-positive price or max occupancy), 401 for an unauthenticated caller, 403 for a missing admin role or organization mismatch, and 503 when Poly-X is unreachable.

## Scope

**In:** The POST /api/admin/rooms endpoint, its zod validation schema (name non-blank, price positive, maxOccupancy positive), the Prisma write that stores the room and associated image URLs, and the 201 response with Location header.

**Out:** Editing, deleting, or price-specific updates on rooms (DC-004-02, DC-004-03, DC-004-04); the admin UI forms (DC-004-05); image upload handling (DC-003-01); authentication and authorization logic, which is provided by Poly-X via DC-001-03; the Prisma schema definition, which is provided by DC-002-07.
