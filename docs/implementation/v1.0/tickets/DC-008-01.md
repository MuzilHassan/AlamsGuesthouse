# DC-008-01 — POST /api/admin/blog-posts

Create a blog post. Validates title non-blank and body non-blank with zod. Stores in PostgreSQL with is_published default false.

**Contract:** POST /api/admin/blog-posts { title, body, imageUrl? } -> 201 { blogPost } | 401 | 403 | 422 title or body blank | 503

## Why

REQ-FUNC-022 requires that an authenticated admin can create a blog post with a title, body, and image so it is stored and displayed in the blog posts list.

## What

POST /api/admin/blog-posts endpoint that validates title and body as non-blank with zod, stores the post in PostgreSQL with is_published defaulting to false, and returns 201 with the created blogPost object.

## Scope

**In:** The POST /api/admin/blog-posts route handler, zod validation schema for title and body, Prisma create call with is_published default false, and the 201/401/403/422/503 response shapes.

**Out:** Editing, publishing, or deleting blog posts (DC-008-02, DC-008-03, DC-008-04); the admin UI forms (DC-008-05); the blog_posts Prisma model definition (DC-002-07); Poly-X token introspection and permission checks (DC-001-03); file upload handling (DC-003-01).

## Acceptance

- Given an authenticated admin on the blog posts section, When the admin submits a create-blog-post form with title, body content, and an image, Then the system stores the blog post in the data store and displays it in the blog posts list
- Given an authenticated admin submits a create-blog-post form with a blank title, When the system validates the submission, Then the system rejects the submission with a validation error message naming the title field
