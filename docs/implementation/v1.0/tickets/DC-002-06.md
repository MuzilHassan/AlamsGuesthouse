# DC-002-06 — BlogPost table

Prisma schema for BlogPost table storing blog posts with title, body, image URL, and published status.

**Contract:** BlogPost { id UUID PK, title text not null, body text not null, image_url text nullable, is_published boolean not null default false, created_at timestamp not null, updated_at timestamp not null }

## Why

REQ-FUNC-020 and REQ-NFUNC-006 require blog posts to persist across restarts and deployments; the BlogPost table stores blog post title, body, optional image URL, and published status.

## What

A Prisma model and PostgreSQL migration for the BlogPost table with id (UUID PK), title (text not null), body (text not null), image_url (text nullable), is_published (boolean not null, default false), created_at, and updated_at, plus its rollback migration.

## Scope

**In:** The BlogPost Prisma model definition and its up/down SQL migration only.

**Out:** Room, RoomImage, Promotion, HeroImage, and GalleryImage tables; the Prisma client generation and DATABASE_URL configuration (DC-002-07); any blog post rendering or CMS logic; any API endpoints that read or write blog posts.

## Tasks

- [ ] **T1** — Add the BlogPost model to prisma/schema.prisma with id as UUID @id @default(uuid()), title as non-null String, body as non-null String, image_url as nullable String, is_published as Boolean @default(false) non-null, created_at and updated_at as non-null DateTime @default(now()) _(verify: prisma validate succeeds; the BlogPost model has id UUID PK, title text not null, body text not null, image_url text nullable, is_published boolean not null default false, created_at timestamp not null, updated_at timestamp not null)_
- [ ] **T2** — Generate and apply the Prisma migration for the BlogPost table with npx prisma migrate dev --name add_blog_post_table, and confirm the down migration drops the BlogPost table cleanly _(verify: the migration creates a blog_post table with columns id, title, body, image_url, is_published default false, created_at, updated_at matching the contract types; prisma migrate down removes the blog_post table without errors)_
- [ ] **T3** — Write a persistence test that inserts a BlogPost row with is_published false and another with is_published true, restarts the Prisma client connection, and re-reads both rows to confirm they survive a connection cycle _(verify: after closing and reopening the Prisma client, both BlogPost rows are present with title, body, image_url, is_published, created_at, and updated_at unchanged, satisfying TC-031 for the BlogPost table)_
- [ ] **T4** — Definition of Done: run prisma validate, run the migration up and down, run the persistence test, and confirm the schema is committed _(verify: prisma validate passes, migrate up creates the blog_post table with the contract columns, migrate down removes it cleanly, the persistence test passes with no data loss across a connection restart, and the migration file is committed to the repository)_

## Acceptance

- Given managed content stored in the data store, When the application is restarted or redeployed, Then the managed content remains available in the data store unchanged
- Given managed content in the data store, When the application undergoes a restart or deployment, Then an inspection of the data store shows all managed content present and unchanged
