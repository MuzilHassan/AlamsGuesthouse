# DC-008-02 — PUT /api/admin/blog-posts/:id

Edit a blog post. Updates title, body, or image URL. Updates updated_at timestamp.

**Contract:** PUT /api/admin/blog-posts/:id { title?, body?, imageUrl? } -> 200 { blogPost } | 401 | 403 | 404 | 422 | 503

## Why

REQ-FUNC-023 requires that an authenticated admin can edit an existing blog post's title, body, or image so the updated content appears in the blog posts list.

## What

PUT /api/admin/blog-posts/:id endpoint that updates the provided fields, sets updated_at, and returns 200 with the updated blogPost object.

## Scope

**In:** The PUT /api/admin/blog-posts/:id route handler, partial-update zod validation for optional title/body/imageUrl, Prisma update call with updated_at, and the 200/401/403/404/422/503 response shapes.

**Out:** Creating blog posts (DC-008-01); publishing or deleting posts (DC-008-03, DC-008-04); the admin UI edit form (DC-008-05); the blog_posts Prisma model definition (DC-002-07); Poly-X token introspection and permission checks (DC-001-03).

## Tasks

- [ ] **T1** — Create the zod partial-update validation schema accepting optional title (non-blank if present), body (non-blank if present), and imageUrl (string URL if present), requiring at least one field _(verify: A body with only { body: 'Updated content here' } passes validation; a body with title set to an empty string fails with field '/title' and code 'FIELD_REQUIRED'; an empty body object fails with a validation error indicating no fields to update)_
- [ ] **T2** — Implement the PUT /api/admin/blog-posts/:id route handler behind the Poly-X introspection middleware from DC-001-03, checking admin role and organization-id, returning 401 for inactive token, 403 for missing admin role or org-id mismatch, 404 when the post id does not exist, and 503 when Poly-X is unreachable _(verify: A PUT request with a valid admin token and an existing post id returns 200; a request with a non-existent post id returns 404; a request with an expired token returns 401; a non-admin token returns 403; Poly-X unreachable returns 503)_
- [ ] **T3** — Add the Prisma update call that sets the provided fields and updates updated_at, returning the updated blogPost object _(verify: PUT /api/admin/blog-posts/{blogPostId} with body changed to 'Updated content here' returns 200 with the blogPost object where body is 'Updated content here' and updated_at is later than created_at)_
- [ ] **T4** — Add structured request logging with the request id and a metric counter for blog post updates, and document PUT /api/admin/blog-posts/:id in the OpenAPI contract _(verify: An update request emits a structured log line with the request id and increments the blog_post_update counter; the OpenAPI contract documents the 200, 401, 403, 404, 422, and 503 responses)_
- [ ] **T5** — Write integration tests covering TC-038 (edit body content returns 200 with updated body) and the 404 path for a non-existent post id _(verify: TC-038 passes: PUT with body 'Updated content here' returns 200 with blogPost.body equal to 'Updated content here'; a PUT to a non-existent id returns 404)_
- [ ] **T6** — Definition of Done: run the full test suite, confirm the endpoint is deployed to the test environment, verify the OpenAPI contract is updated, and confirm all response paths behave per the contract _(verify: All tests pass, PUT /api/admin/blog-posts/:id is reachable in the test environment, the OpenAPI contract includes the endpoint with all response codes, and the acceptance criterion for REQ-FUNC-023 is demonstrated: editing body content updates the stored post and the updated content appears in the blog posts list)_

## Acceptance

- Given an authenticated admin and an existing blog post, When the admin changes the body content and saves, Then the system updates the stored blog post and the updated content appears in the blog posts list
