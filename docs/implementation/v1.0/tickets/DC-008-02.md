# DC-008-02 — PUT /api/admin/blog-posts/:id

Edit a blog post. Updates title, body, or image URL. Updates updated_at timestamp.

**Contract:** PUT /api/admin/blog-posts/:id { title?, body?, imageUrl? } -> 200 { blogPost } | 401 | 403 | 404 | 422 | 503

## Why

Admins need to edit existing blog posts to update title, body, or image so that content stays current, satisfying REQ-FUNC-023.

## What

A PUT /api/admin/blog-posts/:id endpoint that accepts optional title, body, or imageUrl fields, updates the matching Prisma record with a refreshed updated_at timestamp, and returns the updated blogPost object with a 200 status.

## Scope

**In:** The PUT /api/admin/blog-posts/:id route handler, partial-update zod validation, Prisma update call with updated_at refresh, and the 200/401/403/404/422/503 response shapes.

**Out:** Creating blog posts (DC-008-01); publishing or deleting posts (DC-008-03, DC-008-04); the admin edit UI form (DC-008-05); the blog_posts Prisma model definition (DC-002-07); authentication and authorization (DC-001-03 provides Poly-X introspection); image upload (DC-003-01).

## Tasks

- [ ] **T1** — Create the zod validation schema for the edit-blog-post request body: title as optional non-empty string, body as optional non-empty string, imageUrl as optional string URL, with at least one field required _(verify: Passing {} to the schema parse throws a ZodError indicating at least one field is required; passing { body: 'Updated content here' } succeeds; passing { title: '' } throws with field '/title' and code 'FIELD_REQUIRED')_
- [ ] **T2** — Implement the PUT /api/admin/blog-posts/:id route handler: wire the Poly-X introspection middleware from DC-001-03 (requireUser, admin role check, organization-id check, fail closed 401/403/503), parse and validate the body, call prisma.blogPost.update with the provided fields and updated_at set to now, and return 200 with the updated blogPost object; return 404 when the post id does not exist _(verify: A PUT request with { body: 'Updated content here' } on an existing post returns 200 with blogPost.body equal to 'Updated content here' and updated_at greater than created_at; a PUT on a non-existent post id returns 404; a request without a token returns 401; a non-admin token returns 403; Poly-X unreachable returns 503)_
- [ ] **T3** — Add structured logging with the request id and an edit-blog-post audit log entry (userId, blogPostId, action: 'blog_post.update', updatedFields) on success _(verify: Editing a blog post emits a structured log line with the request id, userId, blogPostId, action 'blog_post.update', and the list of updated fields at info level)_
- [ ] **T4** — Write integration tests covering TC-038 (admin edits body content and the updated content appears in the blog posts list) _(verify: TC-038: PUT /v1/blog-posts/{blogPostId} with body 'Updated content here' returns 200 with blogPost.body equal to 'Updated content here'; a subsequent list request shows the updated content; a PUT on a non-existent id returns 404)_
- [ ] **T5** — Definition of Done: run the full test suite for this endpoint, confirm all acceptance criteria are demonstrated, verify structured logging and audit entries are emitted, and confirm the endpoint is deployed to the test environment _(verify: All tests pass (TC-038 and the 401/403/404/503 path tests); structured logs include the request id and audit entry; the endpoint is reachable in the test environment and returns 200 for a valid admin edit request)_

## Acceptance

- Given an authenticated admin and an existing blog post, When the admin changes the body content and saves, Then the system updates the stored blog post and the updated content appears in the blog posts list
