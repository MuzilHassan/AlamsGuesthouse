# DC-007-03 — DELETE /api/admin/gallery/:id

Remove a gallery image from PostgreSQL.

**Contract:** DELETE /api/admin/gallery/:id -> 204 | 401 | 403 | 404 | 503

## Why

REQ-FUNC-018 requires that an admin can remove a gallery image, so that outdated or incorrect images do not appear on the public site.

## What

DELETE /api/admin/gallery/:id removes the matching gallery_images row from PostgreSQL and returns 204, or 404 when the image does not exist.

## Scope

**In:** The DELETE /api/admin/gallery/:id route handler, the Prisma delete on the gallery_images table, the Poly-X introspection middleware wiring, and the structured log with request id.

**Out:** Does not build the gallery management UI (DC-007-04), the POST or PUT endpoints (DC-007-01, DC-007-02), the image upload (DC-003-01), Cloudinary resource deletion, or any authentication or session handling (Poly-X provides it).

## Tasks

- [ ] **T1** — Scaffold the DELETE /api/admin/gallery/:id route handler that validates the id path parameter as a valid identifier, returning 422 with code INVALID_ID_FORMAT for an invalid id _(verify: DELETE /api/admin/gallery/invalid-id returns 422 with code INVALID_ID_FORMAT; DELETE with a valid id passes validation to the handler logic)_
- [ ] **T2** — Wire the Poly-X introspection middleware from DC-001-03 before the handler: introspect the Bearer token, check the admin role in permissions.modulePermissions, validate the organization-id header against the token's organizationId, and fail closed with 401 for an inactive token, 403 for a missing admin role or org-id mismatch, and 503 when Poly-X is unreachable within the 5s timeout _(verify: a request with an expired token returns 401 with shouldRelogin true; a request with a valid token but no admin role returns 403; a request with a mismatched organization-id header returns 403; when Poly-X is unreachable the endpoint returns 503 within 5s)_
- [ ] **T3** — Implement the handler logic that finds the gallery_images row by id via the Prisma client, returns 404 with code GALLERY_IMAGE_NOT_FOUND when no row exists, and otherwise deletes the row and returns 204 with no body _(verify: DELETE /api/admin/gallery/{existingId} returns 204 with an empty body; a subsequent GET /api/content/gallery does not include the deleted image; DELETE with a non-existent id returns 404 with code GALLERY_IMAGE_NOT_FOUND)_
- [ ] **T4** — Add structured logging with the request id, user id, and action 'gallery_image_delete' on success, 404, and error paths, and add a unit test and an integration test covering TC-028 (success with public-site verification), 404 not found, 422 validation, 401 unauthenticated, 403 forbidden, and 503 Poly-X unreachable _(verify: the integration test for TC-028 asserts 204 and that a subsequent GET /api/content/gallery does not include the deleted image; the 404, 422, 401, 403, and 503 test cases each assert the correct status and error code; structured logs include the request id on all paths)_
- [ ] **T5** — Definition of Done: run the full test suite, confirm the endpoint is registered in the API route documentation, and confirm the endpoint is deployed to the test environment _(verify: all tests pass; the OpenAPI spec lists DELETE /api/admin/gallery/:id with its 204, 401, 403, 404, and 503 responses; the endpoint responds on the test environment)_
