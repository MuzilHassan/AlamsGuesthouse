# DC-007-03 — DELETE /api/admin/gallery/:id

Remove a gallery image from PostgreSQL.

**Contract:** DELETE /api/admin/gallery/:id -> 204 | 401 | 403 | 404 | 503

## Why

REQ-FUNC-018 requires that an admin can remove a gallery image, so outdated or unwanted images no longer appear on the public site.

## What

A DELETE /api/admin/gallery/:id endpoint that removes the gallery image record from PostgreSQL and returns 204, with 404 for a non-existent id.

## Scope

**In:** The DELETE /api/admin/gallery/:id route handler, Prisma delete call, 404 handling for a non-existent id, Poly-X introspection and admin role authorization, and error responses (401, 403, 404, 503).

**Out:** The Prisma schema and GalleryImage model (provided by DC-002-07), the Poly-X SDK and introspection middleware (provided by DC-001-03), the POST and PUT gallery endpoints (DC-007-01, DC-007-02), the gallery management UI (DC-007-04), and the public gallery content API.

## Tasks

- [ ] **T1** — Scaffold the DELETE /api/admin/gallery/:id route handler, wiring the Poly-X introspection middleware from DC-001-03 (requireUser) to authenticate the caller, check the admin grant in permissions.modulePermissions, and validate the organization-id header against the token's organizationId _(verify: a request without a Bearer token receives 401; a request with a valid token but no admin grant receives 403; a request with a mismatched organization-id header receives 403; a request when Poly-X is unreachable receives 503)_
- [ ] **T2** — Implement the DELETE handler body: find the gallery image by id from the route param (return 404 if not found), delete the record via Prisma, and return 204 with no body _(verify: DELETE /api/admin/gallery/:id on an existing image returns 204 with an empty body; a subsequent GET /api/content/gallery does not include the deleted image; DELETE on a non-existent id returns 404)_
- [ ] **T3** — Write integration tests covering TC-028: the 204 success path with the image absent from GET /api/content/gallery after deletion, plus the 401 unauthenticated, 403 non-admin, 404 not found, and 503 Poly-X unreachable error paths _(verify: TC-028 passes: the DELETE returns 204 and the deleted image is absent from GET /api/content/gallery; the 401, 403, 404, and 503 error paths each return their documented status code)_
- [ ] **T4** — Add structured request logging with the request id for the DELETE /api/admin/gallery/:id endpoint, and update the API docs with the DELETE endpoint description _(verify: a successful DELETE logs the request id, the deleted gallery image id, and the 204 status; the API docs describe the 204 response and the 401, 403, 404, and 503 error responses)_

## Acceptance

- Given an authenticated admin and an existing gallery image, When the admin removes that image, Then the system removes the image, caption, and alt text from the data store and the image no longer appears in the gallery on the public site
