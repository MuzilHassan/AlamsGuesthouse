# DC-006-01 — POST /api/admin/promotions

Create a promotion associated with a room. Validates room_id exists, title non-blank.

**Contract:** POST /api/admin/promotions { roomId, title, description?, isActive } -> 201 { promotion } | 401 | 403 | 422 | 503

## Why

REQ-FUNC-012 requires that an admin can create a promotion associated with a room so it is stored and displayed in the promotions list, enabling the business to advertise room-level offers.

## What

A POST /api/admin/promotions endpoint that validates the request body, confirms the room exists, persists the promotion, and returns 201 with the created promotion object, guarded by Poly-X introspection and admin-role authorization.

## Scope

**In:** The promotions table migration with its rollback, the POST /api/admin/promotions route handler, request-body validation (roomId exists, title non-blank), and the Poly-X introspection and admin-permission check on this route.

**Out:** Editing, deleting, or listing promotions (DC-006-02, DC-006-03); the admin promotions UI (DC-006-04); public display of active promotions (DC-006-05); authentication and session management, which Poly-X provides.

## Tasks

- [ ] **T1** — Add the promotions table Prisma migration with columns id, roomId (FK to rooms), title, description (nullable), isActive (boolean, default false), createdAt, updatedAt, and a unique index on (roomId, title); include the down migration _(verify: the migration creates the promotions table with the listed columns, the FK to rooms, and the unique index on (roomId, title); the down migration drops the table cleanly)_
- [ ] **T2** — Implement the POST /api/admin/promotions route handler that validates roomId is a non-empty string referencing an existing room, title is non-blank, and isActive is a boolean; return 422 with a code field for each violation (ROOM_NOT_FOUND, TITLE_REQUIRED, INVALID_IS_ACTIVE) _(verify: a request with a non-existent roomId returns 422 with code ROOM_NOT_FOUND; a request with a blank title returns 422 with code TITLE_REQUIRED; a request with isActive as a string returns 422 with code INVALID_IS_ACTIVE)_
- [ ] **T3** — Wire the Poly-X introspection middleware from DC-001-03 before the handler: call polyx.auth.introspect on the Bearer token, check the admin grant in permissions.modulePermissions for the promotions module, verify the organization-id header matches the token organizationId, and fail closed with 401 for an inactive token, 403 for a missing admin grant or org-id mismatch, 503 when Poly-X is unreachable within the 5s timeout _(verify: a request without a Bearer token returns 401; a request with a valid token but no promotions:create grant returns 403; a request with a mismatched organization-id header returns 403; a request when Poly-X is unreachable returns 503)_
- [ ] **T4** — Implement the success path: persist the promotion via Prisma with roomId, title, description, isActive, and return 201 with the full promotion object and a Location header pointing to /api/admin/promotions/{id} _(verify: a POST with valid roomId, title 'Summer Discount', description '20% off', and isActive true returns 201 with the promotion object containing those fields and a Location header; the promotion is retrievable from the data store)_
- [ ] **T5** — Add structured request logging with the request id, the Poly-X userId, and the created promotion id; add a counter metric for promotions_created _(verify: the log entry for a successful create includes the request id, userId, and promotion id; the promotions_created counter increments by 1 on a successful create)_
- [ ] **T6** — Write integration tests covering TC-022: a valid admin request creates a promotion and returns 201 with the promotion object; also cover 401 unauthenticated, 403 missing admin grant, 422 blank title, 422 unknown roomId, and 503 Poly-X unreachable _(verify: the integration test suite passes: the valid request returns 201 with the stored promotion; the 401, 403, 422, and 503 cases each return their expected status and code)_
- [ ] **T7** — Definition of Done: all tests pass, the migration applies and rolls back cleanly, the endpoint is deployed to the test environment, structured logs and metrics are emitted, and the API description for POST /api/admin/promotions is documented with its request body, response codes, and the polyxBearer security scheme _(verify: the test suite is green, the migration up and down both succeed, the endpoint responds on the test environment, logs include the request id and userId, and the API documentation describes the 201/401/403/422/503 responses and the polyxBearer scheme)_
