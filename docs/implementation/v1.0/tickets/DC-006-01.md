# DC-006-01 — POST /api/admin/promotions

Create a promotion associated with a room. Validates room_id exists, title non-blank.

**Contract:** POST /api/admin/promotions { roomId, title, description?, isActive } -> 201 { promotion } | 401 | 403 | 422 | 503

## Why

Admins need to create promotions tied to specific rooms so that special offers can be advertised to site visitors, satisfying REQ-FUNC-012.

## What

A POST /api/admin/promotions endpoint that validates the request body, confirms the room exists, persists the promotion, and returns 201 with the created promotion object, behind Poly-X admin authorization.

## Scope

**In:** The POST /api/admin/promotions route handler, its request validation (roomId exists, title non-blank), the Promotion Prisma model and its migration with rollback, and the Poly-X introspection middleware wiring for this endpoint.

**Out:** Does not build the promotions management UI, the PUT or DELETE promotion endpoints, or the public-site active-promotions query. Poly-X provides authentication, session management, and the admin role check; this unit consumes it, never rebuilds it.

## Tasks

- [ ] **T1** — Add the Promotion model to prisma/schema.prisma with fields id, roomId (FK to Room), title (non-null string), description (nullable string), isActive (boolean default true), createdAt, updatedAt, and a unique index on (roomId, title); generate the Prisma migration with its down migration _(verify: the migration creates the promotions table with the listed columns, the FK to rooms, and the unique index on (roomId, title); the down migration drops the table cleanly)_
- [ ] **T2** — Implement POST /api/admin/promotions, mounting @poly-x/sdk requireUser() middleware, checking the promotions:create grant in permissions.modulePermissions, validating the organization-id header against the token's organizationId, and returning 403 on mismatch or missing grant _(verify: a request with a valid admin token and organization-id returns 201 with the promotion object; a request without the promotions:create grant returns 403; a request with a mismatched organization-id returns 403; a request with no token returns 401; when Poly-X is unreachable the endpoint returns 503)_
- [ ] **T3** — Add request body validation: roomId must reference an existing room (422 with code ROOM_NOT_FOUND if not), title must be non-blank (422 with code TITLE_REQUIRED if blank or missing), isActive must be a boolean if present (422 with code INVALID_IS_ACTIVE otherwise) _(verify: POST with a non-existent roomId returns 422 with code ROOM_NOT_FOUND; POST with a blank title returns 422 with code TITLE_REQUIRED; POST with isActive as a string returns 422 with code INVALID_IS_ACTIVE; POST with a valid body returns 201)_
- [ ] **T4** — Add structured logging with the request id and a promotion_created metric counter on the success path; configure the new environment setting POLYX_SECRET_KEY (server-only, already required by DC-001-03) for this endpoint's introspection calls _(verify: a successful POST logs a structured line with the request id, roomId, and promotionId; the promotion_created counter increments by 1; POLYX_SECRET_KEY is documented as a required server-only environment variable and is never exposed in a browser bundle)_
- [ ] **T5** — Write integration tests covering TC-022: a valid POST returns 201 with the promotion object stored and associated with the room; include cases for 401 unauthenticated, 403 missing admin grant, 403 organization-id mismatch, 422 ROOM_NOT_FOUND, 422 TITLE_REQUIRED, and 503 Poly-X unreachable _(verify: TC-022 passes: POST /api/admin/promotions with roomId, title 'Summer Discount', description '20% off', isActive true returns 201 with the created promotion object; the 401, 403, 422, and 503 error paths each return their documented status and error code)_
- [ ] **T6** — Document the POST /api/admin/promotions endpoint in the API description: request body schema, the polyxBearer security scheme, the organization-id header, the promotions:create permission, and the 201/401/403/422/503 responses _(verify: the API description lists POST /api/admin/promotions with its body fields, the polyxBearer scheme, the organization-id header, the required promotions:create grant, and all five response codes with their error codes)_
- [ ] **T7** — Definition of Done: all tests pass, TC-022 is demonstrated, the migration applies and rolls back cleanly, configuration and API documentation are updated, and the endpoint is deployed to the test environment _(verify: the integration test suite passes including TC-022 and all error-path cases; the migration up and down both succeed; POLYX_SECRET_KEY is documented; the API description includes this endpoint; the endpoint responds in the test environment)_
