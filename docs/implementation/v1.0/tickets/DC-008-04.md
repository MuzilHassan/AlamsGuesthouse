# DC-008-04 — DELETE /api/admin/blog-posts/:id

Delete a blog post from PostgreSQL.

**Contract:** DELETE /api/admin/blog-posts/:id -> 204 | 401 | 403 | 404 | 503

## Why

REQ-FUNC-025 requires that an authenticated admin can delete a blog post so it no longer appears in the blog posts list or on the public site.

## What

DELETE /api/admin/blog-posts/:id endpoint that removes the post from PostgreSQL and returns 204 with no body.

## Scope

**In:** The DELETE /api/admin/blog-posts/:id route handler, Prisma delete call, and the 204/401/403/404/503 response shapes.

**Out:** Creating, editing, or publishing blog posts (DC-008-01, DC-008-02, DC-008-03); the admin UI delete confirmation dialog (DC-008-05); the blog_posts Prisma model definition (DC-002-07); Poly-X token introspection and permission checks (DC-001-03).

## Tasks

- [ ] **T1** — Implement the DELETE /api/admin/blog-posts/:id route handler behind the Poly-X introspection middleware from DC-001-03, checking admin role and organization-id, returning 401 for inactive token, 403 for missing admin role or org-id mismatch, 404 when the post id does not exist, and 503 when Poly-X is unreachable _(verify: A delete request with a valid admin token and an existing post id returns 204; a non-existent post id returns 404; an expired token returns 401; a non-admin token returns 403; Poly-X unreachable returns 503)_
- [ ] **T2** — Add the Prisma delete call that removes the blog post record from PostgreSQL _(verify: DELETE /api/admin/blog-posts/{blogPostId} returns 204 and the post is no longer present in the database; a subsequent GET /api/content/blog-posts does not include the deleted post)_
- [ ] **T3** — Add structured request logging with the request id and a metric counter for blog post deletion, and document DELETE /api/admin/blog-posts/:id in the OpenAPI contract _(verify: A delete request emits a structured log line with the request id and increments the blog_post_delete counter; the OpenAPI contract documents the 204, 401, 403, 404, and 503 responses)_
- [ ] **T4** — Write integration tests covering TC-041 (deleting an existing post returns 204, the post is removed from the data store, and it no longer appears in GET /api/content/blog-posts) and the 404 path for a non-existent post id _(verify: TC-041 passes: DELETE returns 204 and GET /api/content/blog-posts does not include the deleted post; a DELETE to a non-existent id returns 404)_
- [ ] **T5** — Definition of Done: run the full test suite, confirm the endpoint is deployed to the test environment, verify the OpenAPI contract is updated, and confirm all response paths behave per the contract _(verify: All tests pass, DELETE /api/admin/blog-posts/:id is reachable in the test environment, the OpenAPI contract includes the endpoint with all response codes, and the acceptance criterion for REQ-FUNC-025 is demonstrated: deleting a post removes it from the data store and it no longer appears in the blog posts list or on the public site)_

## Acceptance

- Given an authenticated admin and an existing blog post, When the admin confirms deletion of that post, Then the system removes the blog post from the data store and the post no longer appears in the blog posts list or on the public site
