# DC-008-04 — DELETE /api/admin/blog-posts/:id

Delete a blog post from PostgreSQL.

**Contract:** DELETE /api/admin/blog-posts/:id -> 204 | 401 | 403 | 404 | 503

## Why

Admins need to delete blog posts so that outdated or incorrect content can be removed from both the dashboard list and the public site, satisfying REQ-FUNC-025.

## What

A DELETE /api/admin/blog-posts/:id endpoint that removes the matching Prisma record from PostgreSQL and returns 204, so the post no longer appears in the admin list or the public content listing.

## Scope

**In:** The DELETE /api/admin/blog-posts/:id route handler, Prisma delete call, and the 204/401/403/404/503 response shapes.

**Out:** Creating, editing, or publishing blog posts (DC-008-01, DC-008-02, DC-008-03); the delete confirmation UI (DC-008-05); the blog_posts Prisma model (DC-002-07); authentication and authorization (DC-001-03).

## Tasks

- [ ] **T1** — Implement the DELETE /api/admin/blog-posts/:id route handler: wire the Poly-X introspection middleware from DC-001-03 (requireUser, admin role check, organization-id check, fail closed 401/403/503), call prisma.blogPost.delete for the given id, and return 204 with no body; return 404 when the post id does not exist _(verify: A DELETE request on an existing post returns 204 with an empty body; a subsequent GET to /api/content/blog-posts does not include the deleted post; a DELETE on a non-existent id returns 404; a request without a token returns 401; a non-admin token returns 403; Poly-X unreachable returns 503)_
- [ ] **T2** — Add structured logging with the request id and a delete-blog-post audit log entry (userId, blogPostId, action: 'blog_post.delete') on success _(verify: Deleting a blog post emits a structured log line with the request id, userId, blogPostId, and action 'blog_post.delete' at info level)_
- [ ] **T3** — Write integration tests covering TC-041 (deleting an existing post removes it from the data store and it no longer appears in the blog posts list or on the public site) _(verify: TC-041: DELETE /v1/blog-posts/{blogPostId} returns 204; a subsequent GET to /api/content/blog-posts does not include the deleted post; a DELETE on a non-existent id returns 404)_
- [ ] **T4** — Definition of Done: run the full test suite for this endpoint, confirm all acceptance criteria are demonstrated, verify structured logging and audit entries are emitted, and confirm the endpoint is deployed to the test environment _(verify: All tests pass (TC-041 and the 401/403/404/503 path tests); structured logs include the request id and audit entry; the endpoint is reachable in the test environment and returns 204 for a valid admin delete request)_

## Acceptance

- Given an authenticated admin and an existing blog post, When the admin confirms deletion of that post, Then the system removes the blog post from the data store and the post no longer appears in the blog posts list or on the public site
