# DC-009-05 — Public component modification

Modify existing Hero, RoomsSection, GallerySection, and related components to read from PostgreSQL via Prisma instead of importing from data/ directory. Visual design and page structure remain unchanged. Next.js server components fetch data at render time.

**Contract:** Hero, RoomsSection, GallerySection components: replace imports from data/ with Prisma queries; same JSX structure and styling; no Poly-X dependency in public code path; Next.js server component data fetching with caching

## Why

The public site must display managed content from the data store (REQ-FUNC-019) while preserving the existing visual design (REQ-FUNC-026), maintaining comparable response time to the static version (REQ-NFUNC-001), and remaining fully available during Poly-X auth service outages with no runtime dependency on Poly-X (REQ-NFUNC-007).

## What

Hero, RoomsSection, and GallerySection components modified to receive data from Prisma queries fetched in Next.js server components with caching, replacing static imports from the data/ directory, with identical JSX structure, styling, and no Poly-X dependency in the public code path.

## Scope

**In:** A server-side data fetching module with cached Prisma queries for hero images, rooms (with active promotions), and gallery images; modifications to components/Hero.tsx, components/RoomsSection.tsx, components/GallerySection.tsx to accept data as props; updates to app/page.tsx to fetch and pass data; and verification that no Poly-X calls exist in the public code path.

**Out:** Does not build the API content endpoints (DC-009-01 through DC-009-04); does not define or modify the Prisma schema or migrations (DC-002-07); does not implement Poly-X authentication, authorization, or notification; does not alter the visual design, CSS, or page structure; does not modify components unrelated to content display (Navbar, Footer, ContactSection, etc.).

- [ ] **T2** — Modify components/Hero.tsx to accept a heroImages prop instead of importing heroImages from @/data/hero, preserving the existing JSX structure, className values, and the HeroCarousel invocation _(verify: Hero.tsx no longer imports from @/data/hero; the component renders the same section, motion.div, h1, p, and WhatsAppButton elements with identical className strings; HeroCarousel receives the prop data instead of the static import)_
- [ ] **T3** — Modify components/RoomsSection.tsx to accept a rooms prop instead of importing rooms from @/data/rooms, preserving the existing JSX structure, className values, and the RoomCard mapping _(verify: RoomsSection.tsx no longer imports from @/data/rooms; the component renders the same section, SectionHeading, and motion.div grid with identical className strings; RoomCard receives each room from the prop array instead of the static import)_

- [ ] **T5** — Update app/page.tsx to call getHeroImages(), getRooms(), and getGalleryImages() from lib/content/queries.ts and pass the results as props to Hero, RoomsSection, and GallerySection respectively _(verify: app/page.tsx imports from lib/content/queries.ts and no longer relies on the components importing from data/; the homepage renders with Hero receiving heroImages, RoomsSection receiving rooms, and GallerySection receiving galleryImages from the Prisma queries)_
- [ ] **T6** — Verify that no Poly-X imports, Poly-X SDK calls, or Poly-X environment variable references exist in the public code path (app/page.tsx, components/Hero.tsx, components/RoomsSection.tsx, components/GallerySection.tsx, lib/content/queries.ts) _(verify: A search of the public code path files finds no @poly-x imports, no POLYX_ environment variable references, and no Poly-X API calls; when the Poly-X auth service is unreachable, GET requests to the public homepage still return 200 with content from the data store and no 503 or 401 is returned (TC-006, TC-046))_

## Acceptance

- Given room listings, hero images, gallery images, and blog posts stored in the data store, When a site visitor loads the public website, Then the public site displays content read from the data store
- Given the data store contains a room priced at 4000, When a site visitor loads the room listing page, Then the public site displays 4000 for that room
- Given the public website before migration with a specific layout and visual design, When the public site serves content from the data store after migration, Then the layout and visual design match the pre-migration version
- Given the public site serving content from the data store, When a site visitor loads a page, Then the page renders content within a response time comparable to the static version (target value for response time to be confirmed by the client)
- Given the Poly-X auth service is unreachable, When a site visitor loads the public website, Then the public site serves existing content from the data store with no dependency on Poly-X
