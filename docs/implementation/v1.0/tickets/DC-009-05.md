# DC-009-05 — Public component modification

Modify existing Hero, RoomsSection, GallerySection, and related components to read from PostgreSQL via Prisma instead of importing from data/ directory. Visual design and page structure remain unchanged. Next.js server components fetch data at render time.

**Contract:** Hero, RoomsSection, GallerySection components: replace imports from data/ with Prisma queries; same JSX structure and styling; no Poly-X dependency in public code path; Next.js server component data fetching with caching

## Why

The public site must display managed content from the data store while preserving the existing visual design and remaining fully available during Poly-X outages, so that visitors see current content without any degradation of the existing experience.

## What

Hero, RoomsSection, and GallerySection components modified to fetch data from the four public content API endpoints via Next.js server component data fetching with caching, replacing imports from the data/ directory, with identical JSX structure and styling and no Poly-X dependency in the public code path.

## Scope

**In:** Modifications to components/Hero.tsx (replace data/hero.ts import with a fetch to /api/content/hero-images), components/RoomsSection.tsx (replace data/rooms.ts import with a fetch to /api/content/rooms), components/GallerySection.tsx (replace data/gallery.ts import with a fetch to /api/content/gallery), and any related components that import from data/ for public content. Next.js server component data fetching with caching.

**Out:** The four public content API endpoints themselves (DC-009-01 through DC-009-04), the Prisma schema and database setup (DC-002-07), the promotions query logic (DC-006-05), any admin or content management components, and any Poly-X authentication or notification integration. The static data files in data/ are not deleted here, only unlinked from the public components.
