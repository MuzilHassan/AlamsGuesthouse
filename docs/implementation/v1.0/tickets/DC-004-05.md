# DC-004-05 — Room listings management UI

Admin dashboard pages for room listings list, create-room form, and edit-room form. Forms include image upload fields that call /api/admin/upload. Accessible at /admin/rooms. Conforms to WCAG 2.2 AA.

**Contract:** Pages at /admin/rooms, /admin/rooms/new, /admin/rooms/:id/edit; forms with name, description, amenities, images, maxOccupancy, price fields; image upload calls /api/admin/upload; zod validation; WCAG 2.2 AA

## Why

REQ-FUNC-004, REQ-FUNC-005, REQ-FUNC-006, and REQ-FUNC-011 require an admin dashboard UI for creating, editing, and deleting room listings and updating prices, so that an admin can manage rooms through accessible forms that conform to WCAG 2.2 AA.

## What

Admin dashboard pages at /admin/rooms (list), /admin/rooms/new (create form), and /admin/rooms/:id/edit (edit form) with fields for name, description, amenities, images, maxOccupancy, and price; image upload calls /api/admin/upload; forms validate with zod and call the room CRUD endpoints from DC-004-01 through DC-004-04; all pages conform to WCAG 2.2 AA.

## Scope

**In:** The three admin pages (/admin/rooms, /admin/rooms/new, /admin/rooms/:id/edit), their form components with zod validation, the image upload integration calling /api/admin/upload from DC-003-01, the API client calls to the room CRUD endpoints, and the delete confirmation flow.

**Out:** The room CRUD API endpoints themselves (DC-004-01, DC-004-02, DC-004-03, DC-004-04); the image upload endpoint (DC-003-01); authentication and authorization, provided by Poly-X via DC-001-03; the Prisma schema and database layer (DC-002-07); public-facing room display pages.

## Tasks

- [ ] **T1** — Scaffold the /admin/rooms list page: fetch the room listings from the API, render a table or list with columns for name, price, maxOccupancy, and actions (edit, delete), with accessible table semantics (caption, scope on th, row headers) _(verify: the /admin/rooms page renders a list of rooms with name, price, maxOccupancy, and edit and delete action buttons; the table has a caption and th elements with scope attributes; keyboard focus reaches every action button)_
- [ ] **T2** — Build the create-room form at /admin/rooms/new with fields for name (text input with associated label), description (textarea with label), amenities (multi-input with label), images (file upload calling /api/admin/upload from DC-003-01), maxOccupancy (number input with label), and price (amount and currency inputs with labels); validate on submit with the zod schema and display field-level error messages _(verify: the create form has labeled inputs for every field; submitting with a blank name shows a validation error message naming the name field; submitting with all valid fields calls POST /api/admin/rooms and on 201 redirects to /admin/rooms with the new room visible in the list)_
- [ ] **T3** — Build the edit-room form at /admin/rooms/:id/edit: pre-populate all fields from the existing room, allow partial edits (price, amenities, name, description, maxOccupancy, images), submit via PUT /api/admin/rooms/:id from DC-004-02, and include a dedicated price field that can also call PUT /api/admin/rooms/:id/price from DC-004-04 _(verify: the edit form pre-populates fields from the existing room; changing price to 4500 and saving calls PUT /api/admin/rooms/:id and the list shows 4500; removing all amenities and saving stores an empty amenities list and the form reflects the empty list on reload)_
- [ ] **T4** — Implement the delete confirmation flow on the /admin/rooms list: a delete button opens a confirmation dialog (accessible, focus-trapped, Escape to cancel), confirm calls DELETE /api/admin/rooms/:id from DC-004-03, and on 204 the room is removed from the list without a full page reload _(verify: clicking delete opens a confirmation dialog with a focus trap and an Escape-to-cancel behaviour; confirming calls DELETE /api/admin/rooms/:id and on 204 the room disappears from the list; the dialog closes and focus returns to the deleted row's former position)_
- [ ] **T5** — Wire the image upload in the create and edit forms: the file input calls /api/admin/upload from DC-003-01 on file selection, displays a preview of the uploaded image, stores the returned URL, and shows an error message on upload failure (422 or timeout) _(verify: selecting an image file calls POST /api/admin/upload and on 200 displays a preview with the returned URL; an upload failure shows an error message and does not store a partial reference; the image URL is included in the form submission to POST /api/admin/rooms or PUT /api/admin/rooms/:id)_
- [ ] **T6** — Add accessibility conformance to WCAG 2.2 AA across all three pages: ensure all form inputs have associated labels, keyboard reach covers every interactive element, focus is visible on all controls, color contrast meets AA ratios, error messages are announced via aria-live, and the delete dialog traps focus and restores it on close _(verify: an axe or Lighthouse audit on /admin/rooms, /admin/rooms/new, and /admin/rooms/:id/edit reports no WCAG 2.2 AA violations; all inputs have programmatically associated labels; keyboard-only navigation reaches and operates every control; error messages are announced to assistive technology)_
- [ ] **T7** — Add internationalisation: no hard-coded user-facing text in any page or form; all labels, button text, error messages, and the delete confirmation dialog text are sourced from a locale message bundle with the current locale format _(verify: no user-facing string is hard-coded in the page components; changing the locale changes all labels, button text, and error messages; price displays use the locale's currency format)_
- [ ] **T8** — Write integration tests covering the UI flows for TC-010 (create room with all fields, room appears in list), TC-011 (blank name shows validation error naming name field), TC-012 (edit price to 4500, list shows updated price), TC-013 (remove all amenities, save, empty list reflected), TC-014 (delete confirmation removes room from list), TC-020 (price update to 3500, public site shows 3500), and TC-021 (non-positive price shows validation error naming price field) _(verify: TC-010: filling the create form and submitting stores the room and it appears in the list; TC-011: submitting with a blank name shows a validation error naming the name field and no room is created; TC-012: editing price to 4500 and saving shows 4500 in the list; TC-013: removing all amenities and saving shows an empty amenities list; TC-014: confirming delete removes the room from the list; TC-020: updating price to 3500 and checking the public site shows 3500; TC-021: entering a non-positive price shows a validation error naming the price field and the stored price is unchanged)_
- [ ] **T9** — Definition of Done: all UI integration tests pass, all three pages render and operate correctly, forms validate and call the correct API endpoints, image upload integrates with /api/admin/upload, accessibility audit passes WCAG 2.2 AA, no hard-coded user-facing text, and the pages are deployed to the test environment _(verify: the test suite passes for TC-010 through TC-014, TC-020, and TC-021; /admin/rooms, /admin/rooms/new, and /admin/rooms/:id/edit render and operate; the create form calls POST /api/admin/rooms, the edit form calls PUT /api/admin/rooms/:id, the delete flow calls DELETE /api/admin/rooms/:id, the price field calls PUT /api/admin/rooms/:id/price, image upload calls /api/admin/upload; an accessibility audit reports no WCAG 2.2 AA violations; all text is locale-sourced; the pages are reachable in the test environment)_

## Acceptance

- Given an authenticated admin on the room listings section, When the admin submits a create-room form with name, description, amenities, images, maximum occupancy, and price, Then the system stores the room listing in the data store and displays it in the room listings list
- Given an authenticated admin submits a create-room form with a blank name, When the system validates the submission, Then the system rejects the submission with a validation error message naming the name field
- Given an authenticated admin and an existing room listing, When the admin changes the price field to 4500 and saves, Then the system updates the stored room listing with the new price and the updated price appears in the room listings list
- Given an authenticated admin and an existing room listing, When the admin removes all amenities and saves, Then the system stores the room listing with an empty amenities list
- Given an authenticated admin and an existing room listing, When the admin confirms deletion of that listing, Then the system removes the room listing from the data store and the listing no longer appears in the room listings list or on the public site
- Given an authenticated admin and an existing room listing priced at 3000, When the admin changes the price to 3500 and saves, Then the system stores the updated price and the public site displays 3500 for that room on the next page load
