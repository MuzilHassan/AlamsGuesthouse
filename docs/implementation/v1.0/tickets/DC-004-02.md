# DC-004-02 — PUT /api/admin/rooms/:id

Edit an existing room listing. Updates any submitted fields. Validates with zod. Updates updated_at timestamp.

**Contract:** PUT /api/admin/rooms/:id { name?, description?, amenities?, imageUrls?, maxOccupancy?, price? } -> 200 { room } | 401 | 403 | 404 | 422 | 503

## Why

REQ-FUNC-005 requires that an authenticated admin can edit an existing room listing, including changing fields like price and amenities, so that the updated values are stored and reflected in the room listings list.

## What

PUT /api/admin/rooms/:id returns 200 with the updated room for valid partial updates, 404 when the room does not exist, 422 for validation failures, 401 for an unauthenticated caller, 403 for a missing admin role or organization mismatch, and 503 when Poly-X is unreachable.

## Scope

**In:** The PUT /api/admin/rooms/:id endpoint, its zod partial validation schema, the Prisma update that sets submitted fields and updates updated_at, and the 200 response with the updated room.

**Out:** Creating rooms (DC-004-01), deleting rooms (DC-004-03), price-specific updates (DC-004-04); the admin UI forms (DC-004-05); authentication and authorization, provided by Poly-X via DC-001-03; the Prisma schema, provided by DC-002-07.

## Acceptance

- Given an authenticated admin and an existing room listing, When the admin changes the price field to 4500 and saves, Then the system updates the stored room listing with the new price and the updated price appears in the room listings list
- Given an authenticated admin and an existing room listing, When the admin removes all amenities and saves, Then the system stores the room listing with an empty amenities list
