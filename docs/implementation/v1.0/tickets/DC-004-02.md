# DC-004-02 — PUT /api/admin/rooms/:id

Edit an existing room listing. Updates any submitted fields. Validates with zod. Updates updated_at timestamp.

**Contract:** PUT /api/admin/rooms/:id { name?, description?, amenities?, imageUrls?, maxOccupancy?, price? } -> 200 { room } | 401 | 403 | 404 | 422 | 503

## Why

REQ-FUNC-005 requires that an authenticated admin can edit an existing room listing, including changing the price and removing all amenities, and have the updated listing reflected in the room listings list.

## What

A PUT /api/admin/rooms/:id endpoint that accepts partial room fields, validates with zod, updates the room and its updated_at timestamp in PostgreSQL via Prisma, and returns 200 with the updated room, or 404 if the room does not exist, 422 on validation failure, 401/403 on auth failure, 503 when Poly-X is unreachable.

## Scope

**In:** The PUT /api/admin/rooms/:id endpoint, its partial-update zod validation schema, the Prisma update logic including the updated_at timestamp, and the Poly-X introspection middleware wiring for admin authorization.

**Out:** Does not build the create endpoint (DC-004-01), the delete endpoint (DC-004-03), the price-only endpoint (DC-004-04), the room listings UI (DC-004-05), or the Prisma schema (DC-002-07). Poly-X provides authentication; this unit only wires the introspection middleware from DC-001-03.

## Tasks

- [ ] **T1** — Add the zod partial-update validation schema for the edit-room request body: all fields optional, name non-blank when present, price positive when present, maxOccupancy positive when present, amenities and imageUrls as arrays of strings when present _(verify: the schema accepts a body with only price { amount: '4500.00', currency: 'PKR' }, accepts a body with amenities set to an empty array, and rejects a body with name set to an empty string)_
- [ ] **T2** — Wire the Poly-X introspection middleware from DC-001-03 on the PUT /api/admin/rooms/:id route: introspect the Bearer token, check admin role, validate organization-id header, fail closed with 401/403/503 as specified _(verify: a request without a Bearer token returns 401, a request with a valid token but no admin role returns 403, and a request when Poly-X is unreachable returns 503)_
- [ ] **T3** — Implement the PUT /api/admin/rooms/:id handler: look up the room by id returning 404 if not found, validate the body with the zod schema returning 422 on failure, update the room fields and set updated_at to the current timestamp via the Prisma client from DC-002-07, update associated RoomImage records if imageUrls is provided, return 200 with the updated room object _(verify: PUT /api/admin/rooms/:id with price { amount: '4500.00', currency: 'PKR' } on an existing room returns 200 with the updated room where price is 4500; PUT with amenities set to an empty array returns 200 with amenities as an empty array; PUT on a non-existent room id returns 404)_
- [ ] **T4** — Add structured logging with the request id on the edit-room handler: log the admin userId, organizationId, room id, and updated fields on success, and the validation error or 404 details on failure _(verify: a successful update logs the userId, organizationId, room id, and updated field names with the request id; a 404 response logs the missing room id with the request id)_
- [ ] **T5** — Write integration tests covering TC-012 (price change to 4500 returns 200 and updated price appears in list) and TC-013 (amenities set to empty array returns 200 with empty amenities list) _(verify: TC-012 passes: PUT with price { amount: '4500.00', currency: 'PKR' } returns 200 with price 4500, and a subsequent GET to the room listings list shows the updated price; TC-013 passes: PUT with amenities [] returns 200 with amenities as an empty array, and the data store reflects the empty list)_
- [ ] **T6** — Definition of Done: all tests pass, the endpoint returns 200 with the updated room for valid partial updates, 404 for a non-existent room, 422 for invalid input, 401/403/503 auth paths are covered, structured logs include the request id, and the endpoint is deployed to the test environment _(verify: the test suite passes, TC-012 and TC-013 are green, a curl to the test environment PUT /api/admin/rooms/:id with a price change returns 200 with the updated price, and a curl to a non-existent room id returns 404)_

## Acceptance

- Given an authenticated admin and an existing room listing, When the admin changes the price field to 4500 and saves, Then the system updates the stored room listing with the new price and the updated price appears in the room listings list
- Given an authenticated admin and an existing room listing, When the admin removes all amenities and saves, Then the system stores the room listing with an empty amenities list
