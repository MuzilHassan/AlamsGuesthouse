# DC-009-04 — GET /api/content/blog-posts

Public endpoint returning published blog posts only. No authentication required.

**Contract:** GET /api/content/blog-posts -> 200 { blogPosts: [{ id, title, body, imageUrl, createdAt }] } | 500; is_published = true only

## Why

Site visitors need to see published blog posts served from the data store (REQ-FUNC-019), so that managed blog content appears on the public site without manual data file edits.

## What

A public GET /api/content/blog-posts endpoint that returns only published blog posts from PostgreSQL via Prisma, returning 200 on success and 500 on database failure, with no authentication required.

## Scope

**In:** The route handler at app/api/content/blog-posts/route.ts, the Prisma query for blog posts where is_published = true, response mapping to the contract shape, and error handling for the 500 path.

**Out:** Does not build the rooms, hero-images, or gallery endpoints (DC-009-01, DC-009-02, DC-009-03); does not modify public-facing components (DC-009-05); does not implement Poly-X authentication or authorization, as this is a public endpoint with no auth required; does not define the Prisma schema or migrations (DC-002-07).

## Tasks

- [ ] **T1** — Create app/api/content/blog-posts/route.ts with a GET handler that queries the Prisma client for blog posts where is_published = true, ordered by createdAt descending _(verify: GET /api/content/blog-posts returns 200 with a blogPosts array where each item has id, title, body, imageUrl, and createdAt; only posts with is_published = true appear; unpublished posts are excluded)_
- [ ] **T2** — Add a try/catch around the Prisma query that returns 500 with a structured error log including the request id when the database query fails _(verify: When the Prisma client throws, GET /api/content/blog-posts returns 500 and the server log contains the request id and the error message)_
- [ ] **T3** — Write an integration test that seeds one published and one unpublished blog post, sends GET /api/content/blog-posts, and asserts the response _(verify: The test asserts 200 status, only the published post appears in the blogPosts array with id, title, body, imageUrl, and createdAt, and the unpublished post is absent (TC-029 blog-posts step))_
- [ ] **T4** — Definition of Done: confirm the endpoint is deployed to the test environment, the integration test passes, the 500 error path is covered, and the API route is documented in the project API reference _(verify: GET /api/content/blog-posts returns 200 with only published blog posts from PostgreSQL; the integration test passes; the 500 path returns a structured error; the endpoint is reachable in the test environment with no authentication header)_

## Acceptance

- Given room listings, hero images, gallery images, and blog posts stored in the data store, When a site visitor loads the public website, Then the public site displays content read from the data store
- Given the data store contains a room priced at 4000, When a site visitor loads the room listing page, Then the public site displays 4000 for that room
