# DC-009-04 — GET /api/content/blog-posts

Public endpoint returning published blog posts only. No authentication required.

**Contract:** GET /api/content/blog-posts -> 200 { blogPosts: [{ id, title, body, imageUrl, createdAt }] } | 500; is_published = true only

## Why

Site visitors need to see published blog posts from the data store, so that managed blog content appears on the public site without manual code changes to static files.

## What

A public API route at /api/content/blog-posts that returns 200 with published blog post data including id, title, body, imageUrl, and createdAt from PostgreSQL via Prisma where is_published = true, or 500 on a data store error, with no authentication required.

## Scope

**In:** The GET /api/content/blog-posts route handler, its Prisma query filtering is_published = true, and the response shape.

**Out:** The Prisma schema and database setup (DC-002-07), the rooms endpoint (DC-009-01), the hero-images endpoint (DC-009-02), the gallery endpoint (DC-009-03), and the component modifications (DC-009-05). No authentication or Poly-X integration.

## Tasks

- [ ] **T1** — Create the route handler at app/api/content/blog-posts/route.ts that queries Prisma for blog posts where is_published = true, returning id, title, body, imageUrl, and createdAt _(verify: GET /api/content/blog-posts returns 200 with a blogPosts array where each item has id, title, body, imageUrl, and createdAt; only posts with is_published = true are included and unpublished posts are excluded)_
- [ ] **T2** — Add the 500 error response path for when the Prisma query fails, returning a JSON error body without leaking database details _(verify: GET /api/content/blog-posts returns 500 with a JSON error response when the database is unreachable; the response body does not expose connection strings or query text)_
- [ ] **T3** — Write the integration test covering TC-029 step 4: seed published and unpublished blog posts in the data store, then GET /api/content/blog-posts and assert the response _(verify: the integration test sends GET /api/content/blog-posts and asserts 200 with blogPosts matching only the seeded published posts (is_published = true); unpublished posts are absent from the response)_
- [ ] **T4** — Definition of Done check for the blog-posts endpoint _(verify: GET /api/content/blog-posts returns 200 with published blog posts from PostgreSQL (is_published = true only), returns 500 on database error, requires no authentication, makes no Poly-X API calls, the integration test for TC-029 passes, and the route is deployed to the test environment)_

## Acceptance

- Given room listings, hero images, gallery images, and blog posts stored in the data store, When a site visitor loads the public website, Then the public site displays content read from the data store
- Given the data store contains a room priced at 4000, When a site visitor loads the room listing page, Then the public site displays 4000 for that room
