# DC-001-02 — Edge gate middleware

proxy() from @poly-x/next/proxy in proxy.ts protecting /admin/* routes. Matcher excludes /api/polyx. Public routes /sign-in, /forgot-password, /reset-password, /claim remain reachable. Sets POLYX_PUBLIC_ORIGIN or trustForwardedOrigin behind reverse proxy.

**Contract:** proxy({ protectedRoutes: ['/admin/*'], signInPath: '/sign-in', redirectParam: 'redirect' }) in proxy.ts; matcher excludes /api/polyx; /sign-in, /forgot-password, /reset-password, /claim stay public; /claim reachable while signed in

## Why

REQ-FUNC-001 requires that unauthenticated requests to admin dashboard routes are rejected. The edge gate middleware redirects unauthenticated visitors to the sign-in page before they reach any admin route, while keeping public routes reachable.

## What

proxy() from @poly-x/next/proxy is configured in proxy.ts protecting /admin/* routes, with a matcher that excludes /api/polyx, and public routes /sign-in, /forgot-password, /reset-password, /claim remain reachable, including /claim while signed in.

## Scope

**In:** The proxy.ts (or middleware.ts on Next 15 or earlier) edge gate file with proxy() configuration, protectedRoutes, signInPath, redirectParam, and the matcher exclusion.

**Out:** BFF catch-all route (DC-001-01), token introspection and admin role enforcement (DC-001-03), sign-in page UI (DC-001-04), account lifecycle pages (DC-001-05), and notification dispatch (separate component via Poly-X poly-alert). Poly-X provides the edge gate logic; no custom route guard is built here.

## Tasks

- [ ] **T1** — Create proxy.ts (on Next 16) or middleware.ts (on Next 15 or earlier) with proxy({ protectedRoutes: ['/admin/*'], signInPath: '/sign-in', redirectParam: 'redirect' }) from @poly-x/next/proxy _(verify: the file imports proxy from @poly-x/next/proxy and exports the middleware with protectedRoutes including '/admin/*', signInPath set to '/sign-in', and redirectParam set to 'redirect')_
- [ ] **T2** — Configure the matcher to exclude /api/polyx so the BFF catch-all route is not intercepted by the edge gate _(verify: the matcher configuration excludes /api/polyx and a request to /api/polyx/sign-in is not redirected or blocked by the edge gate)_
- [ ] **T3** — Verify that /sign-in, /forgot-password, /reset-password, and /claim remain public and reachable, and that /claim is reachable while signed in (not bounced to a signed-out-only set) _(verify: an unauthenticated GET to /sign-in, /forgot-password, /reset-password, and /claim returns 200 without redirect; an authenticated GET to /claim also returns 200 without being bounced to sign-in)_
- [ ] **T4** — Set POLYX_PUBLIC_ORIGIN (or pass trustForwardedOrigin: true only when an ingress pins the hostname) so redirects do not leak the bind address behind a reverse proxy or container _(verify: behind a reverse proxy, redirect URLs use the public origin and not the bind address (e.g. no https://0.0.0.0:3000 in the Location header))_
- [ ] **T5** — Verify that an unauthenticated GET to /admin/rooms is redirected to /sign-in with the redirect param carrying the original path and query (TC-001) _(verify: an unauthenticated GET to /admin/rooms returns a redirect to /sign-in?redirect=/admin/rooms and the admin dashboard is not served)_
- [ ] **T6** — Definition of Done: the edge gate is configured, the matcher excludes /api/polyx, all public routes remain reachable including /claim while signed in, the redirect param carries path and query only (never an absolute URL), POLYX_PUBLIC_ORIGIN is set for reverse proxy deployment, the build passes, and the middleware is deployed to the test environment _(verify: a build passes; unauthenticated requests to /admin/* redirect to /sign-in with the redirect param; /api/polyx is excluded from the matcher; /sign-in, /forgot-password, /reset-password, and /claim are reachable unauthenticated and /claim is reachable while signed in; redirect URLs use the public origin; the middleware is deployed to the test environment)_

## Acceptance

- Given an unauthenticated request to any admin dashboard route, When the system checks the Poly-X session, Then the system returns HTTP 401 and does not display the dashboard
- Given an authenticated request whose Poly-X token lacks the admin role, When the system checks the role grant, Then the system returns HTTP 403 and does not display the dashboard
- Given an authenticated request with the admin role, When the system checks the Poly-X session, Then the system grants access to the admin dashboard
