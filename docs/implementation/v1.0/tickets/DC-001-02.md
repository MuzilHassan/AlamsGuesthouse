# DC-001-02 — Edge gate middleware

proxy() from @poly-x/next/proxy in proxy.ts protecting /admin/* routes. Matcher excludes /api/polyx. Public routes /sign-in, /forgot-password, /reset-password, /claim remain reachable. Sets POLYX_PUBLIC_ORIGIN or trustForwardedOrigin behind reverse proxy.

**Contract:** proxy({ protectedRoutes: ['/admin/*'], signInPath: '/sign-in', redirectParam: 'redirect' }) in proxy.ts; matcher excludes /api/polyx; /sign-in, /forgot-password, /reset-password, /claim stay public; /claim reachable while signed in

## Why

REQ-FUNC-001 requires that unauthenticated requests to admin dashboard routes are rejected before the page renders. The edge gate middleware redirects unauthenticated visitors to /sign-in and keeps public routes reachable, so the admin dashboard is protected at the edge.

## What

proxy() from @poly-x/next/proxy is configured in proxy.ts with protectedRoutes set to /admin/*, the matcher excludes /api/polyx, and the public routes /sign-in, /forgot-password, /reset-password, /claim remain reachable, with /claim reachable while signed in.

## Scope

**In:** The proxy.ts (or middleware.ts on Next.js 15 or earlier) edge gate file with the proxy() configuration, the protectedRoutes matcher, and the POLYX_PUBLIC_ORIGIN or trustForwardedOrigin setting for reverse proxy deployments.

**Out:** The BFF catch-all route (DC-001-01), the token introspection and role enforcement middleware (DC-001-03), the sign-in page UI (DC-001-04), and the account lifecycle pages (DC-001-05). This unit only configures the edge gate; it does not implement the sign-in form or the back-end authorization check.

## Tasks

- [ ] **T1** — Create proxy.ts (on Next.js 16) or middleware.ts (on Next.js 15 or earlier) importing proxy() from @poly-x/next/proxy with protectedRoutes: ['/admin/*'], signInPath: '/sign-in', and redirectParam: 'redirect' _(verify: proxy.ts exports the proxy() configuration with protectedRoutes covering /admin/*, signInPath set to /sign-in, and redirectParam set to 'redirect'; a build completes without type errors)_
- [ ] **T2** — Configure the matcher to exclude /api/polyx so the BFF catch-all route is not intercepted by the edge gate _(verify: the matcher in proxy.ts excludes /api/polyx; a request to /api/polyx/sign-in is not redirected or blocked by the edge gate)_
- [ ] **T3** — Ensure the public routes /sign-in, /forgot-password, /reset-password, and /claim are not in protectedRoutes and remain reachable; verify /claim is reachable while signed in (not in a signed-out-only set) _(verify: an unauthenticated GET to /sign-in returns 200 (not redirected); an unauthenticated GET to /forgot-password returns 200; an authenticated GET to /claim returns 200 (not bounced away))_
- [ ] **T4** — Set POLYX_PUBLIC_ORIGIN (or pass trustForwardedOrigin: true only when an ingress pins the hostname) so redirects use the public origin instead of the bind address behind a reverse proxy or container _(verify: behind a reverse proxy, a redirect from the edge gate uses the public origin URL, not https://0.0.0.0:3000; the environment configuration names POLYX_PUBLIC_ORIGIN without a value)_
- [ ] **T5** — Definition of Done: the edge gate is configured, the matcher excludes /api/polyx, public routes are reachable, /claim is reachable while signed in, the reverse proxy origin is configured, the build passes, and the middleware is deployed to the test environment _(verify: an unauthenticated GET to /admin/rooms is redirected to /sign-in with a redirect param; /sign-in, /forgot-password, /reset-password, and /claim return 200 without authentication; /claim returns 200 while authenticated; /api/polyx/* is not intercepted; the build passes and the middleware is deployed to the test environment)_

## Acceptance

- Given an unauthenticated request to any admin dashboard route, When the system checks the Poly-X session, Then the system returns HTTP 401 and does not display the dashboard
- Given an authenticated request whose Poly-X token lacks the admin role, When the system checks the role grant, Then the system returns HTTP 403 and does not display the dashboard
- Given an authenticated request with the admin role, When the system checks the Poly-X session, Then the system grants access to the admin dashboard
