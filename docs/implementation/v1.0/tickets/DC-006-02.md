# DC-006-02 — PUT /api/admin/promotions/:id

Edit an existing promotion. Updates title, description, or active status.

**Contract:** PUT /api/admin/promotions/:id { title?, description?, isActive? } -> 200 { promotion } | 401 | 403 | 404 | 422 | 503

## Why

REQ-FUNC-013 requires that an admin can edit an existing promotion so the updated details appear in the promotions list, keeping room offers current and accurate.

## What

A PUT /api/admin/promotions/:id endpoint that updates title, description, or isActive on an existing promotion, returns 200 with the updated object, and handles 404 for a missing promotion, guarded by Poly-X introspection and admin-role authorization.

## Scope

**In:** The PUT /api/admin/promotions/:id route handler, partial-update validation for title/description/isActive, the 404 not-found path, and the Poly-X introspection and admin-permission check on this route.

**Out:** Creating promotions (DC-006-01), deleting promotions (DC-006-03), the promotions table migration (DC-006-01), the admin UI (DC-006-04), public display (DC-006-05); authentication and session management, which Poly-X provides.

## Tasks

- [ ] **T1** — Implement the PUT /api/admin/promotions/:id route handler that looks up the promotion by id from the path parameter; return 404 with code PROMOTION_NOT_FOUND when the promotion does not exist _(verify: a PUT to /api/admin/promotions/{non-existent-id} returns 404 with code PROMOTION_NOT_FOUND)_
- [ ] **T2** — Wire the Poly-X introspection middleware from DC-001-03 before the handler: introspect the Bearer token, check the admin grant for promotions:update in permissions.modulePermissions, verify the organization-id header matches, and fail closed with 401 inactive, 403 missing grant or org-id mismatch, 503 Poly-X unreachable _(verify: a request without a Bearer token returns 401; a request with a valid token but no promotions:update grant returns 403; a request with a mismatched organization-id header returns 403; a request when Poly-X is unreachable returns 503)_
- [ ] **T3** — Implement the update logic: accept optional title (non-blank if provided), description, and isActive (boolean if provided); validate and return 422 with code TITLE_REQUIRED for a blank title; persist only the provided fields via Prisma and return 200 with the full updated promotion object _(verify: a PUT with title changed to 'Winter Special' on an existing promotion returns 200 with the promotion object where title is 'Winter Special'; a PUT with a blank title returns 422 with code TITLE_REQUIRED; a PUT with only isActive false returns 200 and only isActive is changed, title and description remain unchanged)_
- [ ] **T4** — Add structured request logging with the request id, the Poly-X userId, the promotion id, and the updated fields; add a counter metric for promotions_updated _(verify: the log entry for a successful update includes the request id, userId, promotion id, and the changed field names; the promotions_updated counter increments by 1)_
- [ ] **T5** — Write integration tests covering TC-023: a valid admin request updates a promotion title and returns 200 with the updated object; also cover 401 unauthenticated, 403 missing admin grant, 404 non-existent promotion, 422 blank title, and 503 Poly-X unreachable _(verify: the integration test suite passes: the valid update returns 200 with title 'Winter Special'; the 401, 403, 404, 422, and 503 cases each return their expected status and code)_
- [ ] **T6** — Definition of Done: all tests pass, the endpoint is deployed to the test environment, structured logs and metrics are emitted, and the API description for PUT /api/admin/promotions/:id is documented with its request body, response codes, and the polyxBearer security scheme _(verify: the test suite is green, the endpoint responds on the test environment, logs include the request id and userId, and the API documentation describes the 200/401/403/404/422/503 responses and the polyxBearer scheme)_

- Given an authenticated admin and an existing promotion, When the admin changes the promotion details and saves, Then the system updates the stored promotion and the updated promotion appears in the promotions list
