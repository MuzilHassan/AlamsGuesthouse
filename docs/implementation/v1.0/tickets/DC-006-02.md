# DC-006-02 — PUT /api/admin/promotions/:id

Edit an existing promotion. Updates title, description, or active status.

**Contract:** PUT /api/admin/promotions/:id { title?, description?, isActive? } -> 200 { promotion } | 401 | 403 | 404 | 422 | 503

## Why

Admins need to edit existing promotions to update titles, descriptions, or active status so that promotional content stays current, satisfying REQ-FUNC-013.

## What

A PUT /api/admin/promotions/:id endpoint that updates an existing promotion's fields, returns 200 with the updated promotion object, and returns 404 when the promotion does not exist, behind Poly-X admin authorization.

## Scope

**In:** The PUT /api/admin/promotions/:id route handler, its partial-update validation for title/description/isActive, the 404 not-found path, and the Poly-X introspection middleware wiring for this endpoint.

**Out:** Does not build the promotions management UI, the POST or DELETE promotion endpoints, or the public-site active-promotions query. Poly-X provides authentication and the admin role check; this unit consumes it.

## Tasks

- [ ] **T1** — Implement PUT /api/admin/promotions/:id, mounting @poly-x/sdk requireUser() middleware, checking the promotions:update grant in permissions.modulePermissions, validating the organization-id header against the token's organizationId, and returning 403 on mismatch or missing grant _(verify: a request with a valid admin token and matching organization-id returns 200 with the updated promotion; a request without the promotions:update grant returns 403; a request with a mismatched organization-id returns 403; a request with no token returns 401; when Poly-X is unreachable the endpoint returns 503)_
- [ ] **T2** — Add validation for optional fields: if title is provided it must be non-blank (422 with code TITLE_REQUIRED), if isActive is provided it must be a boolean (422 with code INVALID_IS_ACTIVE); return 404 with code PROMOTION_NOT_FOUND when the id does not match an existing promotion _(verify: PUT with a blank title returns 422 with code TITLE_REQUIRED; PUT with isActive as a string returns 422 with code INVALID_IS_ACTIVE; PUT to a non-existent promotion id returns 404 with code PROMOTION_NOT_FOUND; PUT with valid partial fields returns 200 with the updated object)_
- [ ] **T3** — Add structured logging with the request id and a promotion_updated metric counter on the success path _(verify: a successful PUT logs a structured line with the request id, promotionId, and updated fields; the promotion_updated counter increments by 1)_
- [ ] **T4** — Write integration tests covering TC-023: a valid PUT changing title to 'Winter Special' returns 200 with the updated promotion where title is 'Winter Special'; include cases for 401 unauthenticated, 403 missing admin grant, 404 PROMOTION_NOT_FOUND, 422 TITLE_REQUIRED, and 503 Poly-X unreachable _(verify: TC-023 passes: PUT /api/admin/promotions/{promotionId} with title 'Winter Special' returns 200 with the updated promotion object where title is 'Winter Special'; the 401, 403, 404, 422, and 503 error paths each return their documented status and error code)_
- [ ] **T5** — Document the PUT /api/admin/promotions/:id endpoint in the API description: request body schema (all fields optional), the polyxBearer security scheme, the organization-id header, the promotions:update permission, and the 200/401/403/404/422/503 responses _(verify: the API description lists PUT /api/admin/promotions/:id with its optional body fields, the polyxBearer scheme, the organization-id header, the required promotions:update grant, and all six response codes with their error codes)_
- [ ] **T6** — Definition of Done: all tests pass, TC-023 is demonstrated, configuration and API documentation are updated, and the endpoint is deployed to the test environment _(verify: the integration test suite passes including TC-023 and all error-path cases; the API description includes this endpoint; the endpoint responds in the test environment)_

## Acceptance

- Given an authenticated admin and an existing promotion, When the admin changes the promotion details and saves, Then the system updates the stored promotion and the updated promotion appears in the promotions list
