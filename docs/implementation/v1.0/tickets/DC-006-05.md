# DC-006-05 — Active promotions public display

Logic within the public content endpoint that filters promotions where is_active is true and includes them with their associated room data for public site display.

**Contract:** Public content query includes promotions where is_active = true, joined to Room; removed or inactive promotions excluded from public response

## Why

REQ-FUNC-015 requires that active promotions are displayed on the public site alongside their associated rooms, so visitors see current offers, and that removed or inactive promotions are excluded.

## What

A modification to the public content query that joins promotions where is_active is true to their associated room data, so the public room listing response includes active promotions and excludes inactive or removed ones.

## Scope

**In:** The public content query logic that filters promotions by is_active = true and joins them to Room for the /api/content/rooms response.

**Out:** The admin promotion CRUD endpoints (DC-006-01, DC-006-02, DC-006-03); the admin promotions UI (DC-006-04); the promotions table migration (DC-006-01); authentication, which is not required for public content.

## Tasks

- [ ] **T1** — Modify the public content query in the /api/content/rooms handler to include a join on promotions where is_active = true for each room, returning promotion title and description in the room response payload _(verify: a GET /api/content/rooms for a room with an active promotion includes the promotion title and description in the response; a room with no active promotion has no promotion field or an empty promotions array)_
- [ ] **T2** — Verify that inactive promotions are excluded: a promotion with is_active = false does not appear in the public content response, and a promotion that was deleted (DC-006-03) is absent _(verify: a GET /api/content/rooms for a room with only an inactive promotion does not include that promotion; a room whose promotion was deleted does not include any promotion)_
- [ ] **T3** — Add structured request logging with the request id and the count of active promotions included in the response; add a counter metric for active_promotions_displayed _(verify: the log entry for a public content request includes the request id and the number of active promotions returned; the active_promotions_displayed counter reflects the count)_
- [ ] **T4** — Write integration tests covering TC-025: Room A with an active promotion and Room B with a removed promotion; GET /api/content/rooms includes the active promotion for Room A and no promotion for Room B; only promotions where is_active is true are included _(verify: the integration test passes: the response includes the active promotion for Room A with its title and description; no promotion appears for Room B; an inactive promotion for a third room is excluded)_
- [ ] **T5** — Definition of Done: all tests pass, the public content query is deployed to the test environment, structured logs and metrics are emitted, and the API description for GET /api/content/rooms is updated to document the promotions field in the room response _(verify: the test suite is green, GET /api/content/rooms on the test environment includes active promotions and excludes inactive or removed ones, logs include the request id and promotion count, and the API documentation describes the promotions field)_

## Acceptance

- Given a room with an active promotion stored in the data store, When a site visitor loads the room listing on the public site, Then the public site displays the promotion for that room
- Given a room whose promotion has been removed, When a site visitor loads the room listing on the public site, Then the public site does not display a promotion for that room
