# DC-006-04 — Promotions management UI

Admin dashboard page at /admin/promotions showing promotions list with create, edit, and remove forms. Room selector dropdown. Conforms to WCAG 2.2 AA.

**Contract:** Page at /admin/promotions; list of promotions with room name, title, active status; create/edit form with room selector, title, description, isActive; WCAG 2.2 AA

## Why

REQ-FUNC-012, REQ-FUNC-013, and REQ-FUNC-014 require an admin dashboard interface for creating, editing, and removing promotions associated with rooms, so administrators can manage room offers without using the API directly.

## What

An admin dashboard page at /admin/promotions that lists all promotions with room name, title, and active status, and provides a create form, an edit form, and a remove action, with a room selector dropdown, conforming to WCAG 2.2 AA.

## Scope

**In:** The /admin/promotions page, the promotions list table, the create-promotion form with room selector, the edit-promotion form, the delete-promotion action, and all associated client-side state and API calls to DC-006-01, DC-006-02, and DC-006-03.

**Out:** The promotion API endpoints themselves (DC-006-01, DC-006-02, DC-006-03); public display of active promotions (DC-006-05); the promotions table migration (DC-006-01); authentication and session management, which Poly-X provides.

## Tasks

- [ ] **T1** — Create the /admin/promotions page scaffold with a server-side auth() check that redirects unauthenticated users to /sign-in and renders a loading state; fetch the promotions list and rooms list on mount _(verify: an unauthenticated user visiting /admin/promotions is redirected to /sign-in; an authenticated admin sees the page render with the promotions list and rooms list loaded)_
- [ ] **T2** — Build the promotions list table showing room name, title, and active status (as a badge) for each promotion, with sortable columns and an empty state message when no promotions exist _(verify: the table displays each promotion's room name, title, and active-status badge; with no promotions the empty state message is shown; column headers are keyboard-focusable and sortable)_
- [ ] **T3** — Build the create-promotion form with a room selector dropdown (populated from the rooms list), title input, description textarea, and isActive toggle; submit calls POST /api/admin/promotions and refreshes the list on 201; show field-level validation errors on 422 _(verify: submitting the form with a selected room, title 'Summer Discount', description '20% off', and isActive true calls POST /api/admin/promotions and the new promotion appears in the list; submitting with a blank title shows a TITLE_REQUIRED error on the title field)_
- [ ] **T4** — Build the edit-promotion form pre-populated with the promotion's current values; submit calls PUT /api/admin/promotions/:id and refreshes the list on 200; show a PROMOTION_NOT_FOUND message on 404; show field-level errors on 422 _(verify: editing a promotion's title to 'Winter Special' and saving calls PUT /api/admin/promotions/:id and the list shows the updated title; editing a promotion that was concurrently deleted shows a PROMOTION_NOT_FOUND message)_
- [ ] **T5** — Build the delete-promotion action with a confirmation dialog; confirm calls DELETE /api/admin/promotions/:id and removes the promotion from the list on 204; show a PROMOTION_NOT_FOUND message on 404 _(verify: clicking delete shows a confirmation dialog; confirming calls DELETE /api/admin/promotions/:id and the promotion is removed from the list; deleting a concurrently-removed promotion shows a PROMOTION_NOT_FOUND message)_
- [ ] **T6** — Ensure WCAG 2.2 AA compliance: all form inputs have associated label elements, the room selector is keyboard-reachable, focus moves to the first form field when a form opens, the active-status badge has sufficient color contrast, and the confirmation dialog traps focus and restores it on close _(verify: an accessibility audit passes: every input has a programmatically associated label, the room selector opens and navigates by keyboard, focus is managed on form open and dialog close, and the active/inactive badges meet 2.2 AA contrast ratios)_
- [ ] **T7** — Internationalise all user-facing text: no hard-coded strings for labels, button text, error messages, or the empty state; use the app's locale format for dates and the message catalog for all display text _(verify: switching the locale changes all labels, button text, error messages, and the empty-state message; no hard-coded user-facing strings remain in the component source)_
- [ ] **T8** — Write component and integration tests covering TC-022 (create), TC-023 (edit), and TC-024 (delete) through the UI: each test drives the form, asserts the API call, and verifies the list updates _(verify: the test suite passes: the create test submits the form and sees the new promotion in the list; the edit test changes the title and sees the update; the delete test confirms and sees the promotion removed)_
- [ ] **T9** — Definition of Done: all tests pass, the page is deployed to the test environment, the accessibility audit passes at WCAG 2.2 AA, all user-facing text is internationalised, and the runbook entry for managing promotions is documented _(verify: the test suite is green, /admin/promotions renders on the test environment, the a11y audit reports no violations at 2.2 AA, no hard-coded strings remain, and the runbook describes how to create, edit, and remove promotions)_

## Acceptance

- Given an authenticated admin on the promotions management interface, When the admin submits a create-promotion form for a room, Then the system stores the promotion in the data store and displays it in the promotions list
- Given an authenticated admin and an existing promotion, When the admin changes the promotion details and saves, Then the system updates the stored promotion and the updated promotion appears in the promotions list
- Given an authenticated admin and an existing promotion, When the admin removes that promotion, Then the system removes the promotion from the data store and the promotion no longer appears on the public site
