# DC-006-04 — Promotions management UI

Admin dashboard page at /admin/promotions showing promotions list with create, edit, and remove forms. Room selector dropdown. Conforms to WCAG 2.2 AA.

**Contract:** Page at /admin/promotions; list of promotions with room name, title, active status; create/edit form with room selector, title, description, isActive; WCAG 2.2 AA

## Why

Admins need a dashboard interface to create, edit, and remove promotions associated with rooms, satisfying REQ-FUNC-012, REQ-FUNC-013, and REQ-FUNC-014.

## What

An admin dashboard page at /admin/promotions showing a promotions list with room name, title, and active status, plus create, edit, and remove forms with a room selector dropdown, conforming to WCAG 2.2 AA.

## Scope

**In:** The /admin/promotions page, the promotions list table, the create form with room selector, the edit form, the delete confirmation action, and all client-side calls to the DC-006-01, DC-006-02, and DC-006-03 endpoints.

**Out:** Does not build the POST, PUT, or DELETE API endpoints themselves (those are DC-006-01, DC-006-02, DC-006-03), the public-site active-promotions display (DC-006-05), or any authentication UI; Poly-X provides the sign-in and session, this page consumes it.

## Tasks

- [ ] **T1** — Create the /admin/promotions page layout with a promotions list table showing room name, title, and active status for each promotion, fetched from the existing promotions data; include loading and empty states _(verify: the page renders a table with columns for room name, title, and active status; promotions from the data store appear as rows; an empty state message displays when no promotions exist; a loading indicator displays while fetching)_
- [ ] **T2** — Build the create-promotion form with a room selector dropdown (populated from the rooms list), a title text input, a description textarea, and an isActive toggle; on submit, POST to /api/admin/promotions and refresh the list on 201; display validation errors from 422 responses inline _(verify: submitting the form with a selected room, title 'Summer Discount', description '20% off', and isActive true sends a POST that returns 201 and the new promotion appears in the list; a 422 response displays the field-level error message inline next to the relevant input)_
- [ ] **T3** — Build the edit-promotion form, pre-populated with the selected promotion's current values, with editable title, description, and isActive fields; on save, PUT to /api/admin/promotions/:id and refresh the list on 200; display 404 and 422 errors appropriately _(verify: opening the edit form for a promotion shows its current title, description, and isActive; changing title to 'Winter Special' and saving sends a PUT that returns 200 and the list shows the updated title; a 404 response displays a 'promotion not found' message; a 422 response displays the field-level error inline)_
- [ ] **T4** — Build the delete-promotion action with a confirmation dialog; on confirm, DELETE /api/admin/promotions/:id and remove the row from the list on 204; display 404 errors appropriately _(verify: clicking delete shows a confirmation dialog; confirming sends a DELETE that returns 204 and the promotion row is removed from the list; a 404 response displays a 'promotion not found' message and the list is refreshed)_
- [ ] **T5** — Add accessibility to WCAG 2.2 AA: associate labels with all form inputs via htmlFor/id, ensure keyboard reachability through the table and forms with visible focus indicators, manage focus to the form on open and back to the table row on close, and verify colour contrast meets AA ratio for all text and controls _(verify: all form inputs have associated labels; the table rows and form controls are reachable via Tab key with visible focus rings; focus moves to the form when opened and returns to the triggering row when closed; all text and controls meet the WCAG 2.2 AA contrast ratio)_
- [ ] **T6** — Add internationalisation: no hard-coded user-facing text; use the locale message catalog for all labels, button text, error messages, and the empty state; format dates per the active locale _(verify: all user-facing strings are sourced from the locale message catalog with no hard-coded text; dates in the list render in the active locale's format; switching the locale changes all displayed text and date formats)_
- [ ] **T7** — Write component and integration tests covering TC-022 (create flow), TC-023 (edit flow), and TC-024 (delete flow) through the UI _(verify: TC-022: filling the create form and submitting results in the promotion appearing in the list; TC-023: editing a promotion's title to 'Winter Special' and saving results in the updated title in the list; TC-024: deleting a promotion and confirming results in the row being removed from the list)_
- [ ] **T8** — Definition of Done: all component and integration tests pass, TC-022, TC-023, and TC-024 are demonstrated through the UI, accessibility and i18n checks pass, and the page is deployed to the test environment _(verify: the test suite passes including TC-022, TC-023, and TC-024; an accessibility audit reports no WCAG 2.2 AA violations; no hard-coded user-facing text remains; the page renders in the test environment)_

## Acceptance

- Given an authenticated admin on the promotions management interface, When the admin submits a create-promotion form for a room, Then the system stores the promotion in the data store and displays it in the promotions list
- Given an authenticated admin and an existing promotion, When the admin changes the promotion details and saves, Then the system updates the stored promotion and the updated promotion appears in the promotions list
- Given an authenticated admin and an existing promotion, When the admin removes that promotion, Then the system removes the promotion from the data store and the promotion no longer appears on the public site
