# DC-002-01 — Room table

Prisma schema for Room table storing room listing name, description, amenities, max occupancy, and price.

**Contract:** Room { id UUID PK, name text not null, description text, amenities text[], max_occupancy int not null, price decimal(10,2) not null, created_at timestamp not null, updated_at timestamp not null }

## Why

REQ-FUNC-020 and REQ-NFUNC-006 require managed room content to persist across restarts and deployments; the Room table is the primary content record that makes that possible.

## What

A Prisma model and PostgreSQL migration for the Room table with id (UUID PK), name, description, amenities (text array), max_occupancy, price (decimal 10,2), created_at, and updated_at, plus its rollback migration.

## Scope

**In:** The Room Prisma model definition and its up/down SQL migration only.

**Out:** RoomImage, Promotion, and all other content tables; the Prisma client generation and DATABASE_URL configuration (DC-002-07); any API endpoints that read or write rooms.

## Tasks

- [ ] **T1** — Add the Room model to prisma/schema.prisma with id as UUID @id @default(uuid()), name as non-null String, description as nullable String, amenities as String[], max_occupancy as non-null Int, price as Decimal @db.Decimal(10,2) non-null, created_at and updated_at as non-null DateTime @default(now()) _(verify: prisma validate succeeds; the Room model in schema.prisma has every field and type matching the contract: id UUID PK, name text not null, description text, amenities text[], max_occupancy int not null, price decimal(10,2) not null, created_at timestamp not null, updated_at timestamp not null)_
- [ ] **T2** — Generate and apply the Prisma migration for the Room table with npx prisma migrate dev --name add_room_table, and confirm the down migration drops the Room table cleanly _(verify: the migration creates a room table with columns id, name, description, amenities, max_occupancy, price, created_at, updated_at matching the contract types; prisma migrate down removes the room table without errors)_
- [ ] **T3** — Write a persistence test that inserts a Room row, restarts the Prisma client connection, and re-reads the row to confirm it survives a connection cycle _(verify: after closing and reopening the Prisma client, the inserted Room row is present with all fields (name, description, amenities, max_occupancy, price, created_at, updated_at) unchanged, satisfying TC-031 for the Room table)_
- [ ] **T4** — Definition of Done: run prisma validate, run the migration up and down, run the persistence test, and confirm the schema is committed _(verify: prisma validate passes, migrate up creates the room table with the contract columns, migrate down removes it cleanly, the persistence test passes with no data loss across a connection restart, and the migration file is committed to the repository)_

## Acceptance

- Given managed content stored in the data store, When the application is restarted or redeployed, Then the managed content remains available in the data store unchanged
- Given managed content in the data store, When the application undergoes a restart or deployment, Then an inspection of the data store shows all managed content present and unchanged
