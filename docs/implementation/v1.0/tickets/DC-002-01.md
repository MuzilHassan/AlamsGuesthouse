# DC-002-01 — Room table

Prisma schema for Room table storing room listing name, description, amenities, max occupancy, and price.

**Contract:** Room { id UUID PK, name text not null, description text, amenities text[], max_occupancy int not null, price decimal(10,2) not null, created_at timestamp not null, updated_at timestamp not null }

## Why

REQ-FUNC-020 and REQ-NFUNC-006 require managed room content to persist across application restarts and deployments, so room listings remain available and unchanged in the data store at all times.

## What

A Room table in PostgreSQL 16 defined via a Prisma 6 schema, with a migration that creates the table and a down migration that drops it, so room records survive restarts and redeployments.

## Scope

**In:** The Prisma model and migration for the Room table only: columns id (UUID PK), name, description, amenities (text array), max_occupancy, price (decimal(10,2)), created_at, updated_at.

**Out:** RoomImage, Promotion, HeroImage, GalleryImage, and BlogPost tables; the Prisma client configuration and DATABASE_URL wiring (DC-002-07); any API endpoints or business logic that read or write rooms.

## Tasks

- [ ] **T1** — Add the Room model to prisma/schema.prisma with id as @id @db.Uuid, name as String not null, description as String?, amenities as String[], max_occupancy as Int not null, price as Decimal @db.Decimal(10,2) not null, created_at and updated_at as DateTime not null _(verify: prisma validate succeeds and the Room model matches the contract fields and types exactly)_
- [ ] **T2** — Generate the Prisma migration for the Room table (prisma migrate dev --name add_room_table) and verify the up SQL creates the room table with all contract columns and the UUID primary key _(verify: the migration SQL creates a room table with id uuid PK default gen_random_uuid(), name text not null, description text, amenities text[], max_occupancy int not null, price decimal(10,2) not null, created_at timestamp not null, updated_at timestamp not null)_
- [ ] **T3** — Write the down migration that drops the room table, so the migration is reversible _(verify: running the down migration removes the room table cleanly and prisma migrate status reports no pending migrations)_
- [ ] **T4** — Write a unit test that inserts a Room record, restarts the Prisma client connection (simulating an application restart), and reads the record back to confirm it is present and unchanged _(verify: the test inserts a room with name 'Deluxe Suite', max_occupancy 4, price 199.99, re-instantiates the PrismaClient, and reads the same record with all fields matching; TC-031 is demonstrated: no data loss occurs across the restart)_
- [ ] **T5** — Definition of Done: run prisma validate, prisma migrate dev, and the persistence test suite; confirm the migration and its rollback both apply cleanly _(verify: prisma validate passes, the room migration applies and rolls back without error, the persistence test passes confirming room content survives a simulated restart, and the schema is committed to the repository)_

## Acceptance

- Given managed content stored in the data store, When the application is restarted or redeployed, Then the managed content remains available in the data store unchanged
- Given managed content in the data store, When the application undergoes a restart or deployment, Then an inspection of the data store shows all managed content present and unchanged
