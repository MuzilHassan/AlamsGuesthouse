# DC-005-04 — Hero images management UI

Admin dashboard page at /admin/hero showing hero carousel images with add, remove, and reorder controls. Image upload calls /api/admin/upload. Drag-and-drop or arrow-button reordering. Conforms to WCAG 2.2 AA.

**Contract:** Page at /admin/hero; list of hero images with positions; add button calls /api/admin/upload then POST /api/admin/hero-images; remove button calls DELETE; reorder calls PUT /api/admin/hero-images/reorder; WCAG 2.2 AA

## Why

REQ-FUNC-007, REQ-FUNC-008, and REQ-FUNC-009 require an admin dashboard interface where an authenticated admin can add, remove, and reorder hero carousel images.

## What

An admin page at /admin/hero displays the list of hero carousel images with their positions and provides add (upload then POST), remove (DELETE), and reorder (drag-and-drop or arrow buttons then PUT) controls, conforming to WCAG 2.2 AA with no hard-coded user-facing text.

## Scope

**In:** The /admin/hero page component, the hero image list with thumbnails and positions, the add image flow (calls /api/admin/upload then POST /api/admin/hero-images), the remove button (calls DELETE /api/admin/hero-images/:id), the reorder control (drag-and-drop or arrow buttons, calls PUT /api/admin/hero-images/reorder), accessibility to WCAG 2.2 AA, internationalisation, and component tests.

**Out:** The POST /api/admin/hero-images endpoint (DC-005-01), the DELETE endpoint (DC-005-02), the reorder endpoint (DC-005-03), the image upload endpoint (DC-003-01), and the public hero carousel display. Authentication is provided by Poly-X; this unit renders the page behind the Poly-X proxy gate, it does not build login, token handling, or a password store. The hero_images database schema is owned by DC-005-01.

## Tasks

- [ ] **T1** — Scaffold the /admin/hero page that fetches the current hero images list and renders each image with its thumbnail (from cloudinaryUrl), displayPosition, and action buttons (remove, move up, move down), with a heading and an add-image button _(verify: the /admin/hero page renders a list of hero images sorted by displayPosition, each showing its thumbnail and position number, with remove and reorder controls and an add-image button; the page is behind the Poly-X proxy protected route gate)_
- [ ] **T2** — Implement the add image flow: the add button opens a file picker, the selected file is sent to /api/admin/upload, and on success the returned cloudinaryUrl is sent with the next displayPosition to POST /api/admin/hero-images; the list refreshes on 201 and an error message is shown on 422 or 503 _(verify: selecting an image file and confirming calls /api/admin/upload then POST /api/admin/hero-images; on 201 the new image appears at the end of the management list; on 422 a validation error message is displayed; on 503 a Poly-X unavailable message is displayed)_
- [ ] **T3** — Implement the remove button: clicking it shows a confirmation dialog, on confirm calls DELETE /api/admin/hero-images/:id, and on 204 removes the image from the list; on 404 shows a not-found message and on 503 shows an unavailable message _(verify: clicking remove and confirming calls DELETE /api/admin/hero-images/:id; on 204 the image is removed from the list; on 404 a 'image not found' message is shown; on 503 a 'service unavailable' message is shown; the list remains unchanged on error)_
- [ ] **T4** — Implement reorder via drag-and-drop and arrow buttons: moving an image triggers PUT /api/admin/hero-images/reorder with the new orderedIds array; the list updates optimistically and reverts on error (422, 503); keyboard arrow buttons are provided as an alternative to drag-and-drop _(verify: dragging an image from position 3 to position 1 calls PUT /api/admin/hero-images/reorder with the reordered ids; on 200 the list reflects the new order; clicking the up arrow on an image moves it one position and calls the reorder endpoint; on 422 or 503 the list reverts to the previous order and an error message is shown)_
- [ ] **T5** — Add accessibility to WCAG 2.2 AA: label every button and control with an aria-label (add image, remove image at position N, move up, move down), ensure all controls are keyboard reachable with visible focus, manage focus after add (focus the new item) and after remove (focus the next item or the add button), and verify color contrast meets WCAG 2.2 AA _(verify: all interactive controls have aria-labels; tabbing reaches every button with a visible focus ring; after adding an image, focus moves to the new image's controls; after removing an image, focus moves to the next image or the add button; color contrast ratios meet WCAG 2.2 AA for all text and controls)_
- [ ] **T6** — Add internationalisation: replace all hard-coded user-facing strings (button labels, confirmation prompts, error messages, page heading) with locale-aware message keys so the page renders correctly in the application's supported locales _(verify: no hard-coded user-facing text remains in the component; all labels, prompts, and messages are resolved from locale message files; switching the locale changes the displayed text accordingly)_
- [ ] **T7** — Write component and integration tests covering TC-015 (add: upload then POST returns 201, image appears in list), TC-016 (remove: DELETE returns 204, image disappears from list), and TC-017 (reorder: PUT returns 200, list reflects new order, GET /api/content/hero-images confirms new order) _(verify: TC-015: adding an image via the UI results in a 201 and the image appears in the management list; TC-016: removing an image via the UI results in a 204 and the image is absent from the list and from GET /api/content/hero-images; TC-017: reordering via the UI results in a 200 and the list and GET /api/content/hero-images reflect the new order)_
- [ ] **T8** — Definition of Done: confirm the /admin/hero page is accessible, internationalised, covers all three acceptance criteria, tests pass, and the page is deployed to the test environment _(verify: the /admin/hero page renders behind the Poly-X proxy gate; add, remove, and reorder all function per TC-015, TC-016, and TC-017; the page meets WCAG 2.2 AA; no hard-coded user-facing text remains; all component and integration tests pass; the page is reachable in the test environment)_

## Acceptance

- Given an authenticated admin on the hero section management interface, When the admin uploads an image and adds it to the hero carousel, Then the system stores the image reference and display position in the data store and the image appears in the hero carousel management list
- Given an authenticated admin and an existing hero section image, When the admin removes that image, Then the system removes the image from the data store and the image no longer appears in the hero carousel on the public site
- Given an authenticated admin and a hero carousel with images in positions 1, 2, and 3, When the admin moves the image in position 3 to position 1, Then the system stores the updated order and the public site displays the carousel images in the new order on the next page load
