# DC-005-04 — Hero images management UI

Admin dashboard page at /admin/hero showing hero carousel images with add, remove, and reorder controls. Image upload calls /api/admin/upload. Drag-and-drop or arrow-button reordering. Conforms to WCAG 2.2 AA.

**Contract:** Page at /admin/hero; list of hero images with positions; add button calls /api/admin/upload then POST /api/admin/hero-images; remove button calls DELETE; reorder calls PUT /api/admin/hero-images/reorder; WCAG 2.2 AA

## Why

REQ-FUNC-007, REQ-FUNC-008, and REQ-FUNC-009 require an admin dashboard interface for adding, removing, and reordering hero section images on the homepage carousel, so that an admin can manage the hero carousel visually.

## What

An admin dashboard page at /admin/hero that lists hero carousel images with their positions, provides an add button that uploads via /api/admin/upload then POST /api/admin/hero-images, a remove button that calls DELETE /api/admin/hero-images/:id, and a reorder control (drag-and-drop or arrow buttons) that calls PUT /api/admin/hero-images/reorder, conforming to WCAG 2.2 AA.

## Scope

**In:** The /admin/hero page, its image list rendering, add/upload flow, remove flow, reorder controls, accessibility and internationalisation, and integration tests through the UI.

**Out:** The backend endpoints POST /api/admin/hero-images (DC-005-01), DELETE /api/admin/hero-images/:id (DC-005-02), PUT /api/admin/hero-images/reorder (DC-005-03), and the Cloudinary upload endpoint (DC-003-01). Poly-X provides authentication; this unit does not build login, token signing, or password handling. The public-site hero carousel rendering is not built here.

## Tasks

- [ ] **T1** — Scaffold the /admin/hero page that fetches the current hero images from the API and renders a list showing each image thumbnail with its display position, ordered by displayPosition ascending _(verify: navigating to /admin/hero as an authenticated admin shows the list of hero images ordered by displayPosition, each with its thumbnail and position number)_
- [ ] **T2** — Add the image upload and add flow: an 'Add image' button that opens a file picker, uploads the file to /api/admin/upload, and on success calls POST /api/admin/hero-images with the returned cloudinaryUrl and the next displayPosition, then refreshes the list _(verify: clicking 'Add image', selecting a file, and completing the upload adds the image to the list at the next position; the POST /api/admin/hero-images call includes the cloudinaryUrl from the upload response and the correct displayPosition; a 422 from the upload shows a validation error message)_
- [ ] **T3** — Add the remove control: a 'Remove' button on each image that shows a confirmation dialog, and on confirm calls DELETE /api/admin/hero-images/:id, then removes the image from the list _(verify: clicking 'Remove' on an image shows a confirmation dialog; confirming calls DELETE /api/admin/hero-images/:id and the image disappears from the list; a 404 response shows a 'image not found' message; a 403 shows a 'permission denied' message)_
- [ ] **T4** — Add the reorder control using arrow buttons (up/down) on each image that swap positions and call PUT /api/admin/hero-images/reorder with the new orderedIds array, then refreshes the list in the new order _(verify: clicking the up arrow on the image in position 3 moves it to position 2 and calls PUT /api/admin/hero-images/reorder with the updated orderedIds; the list reflects the new order; a 422 response shows a validation error message and reverts the list to the previous order)_
- [ ] **T5** — Apply WCAG 2.2 AA: add ARIA labels to all interactive elements (add button, remove button, up/down arrows, file input), ensure keyboard reachability and focus management (focus moves to the added image after add, focus moves to the next image after remove), and verify colour contrast meets AA ratio for all text and controls _(verify: all interactive elements have ARIA labels; the add button, remove button, and arrow buttons are reachable and operable via keyboard; focus moves to the newly added image after add; focus moves to the next remaining image after remove; colour contrast for all text and controls meets the WCAG 2.2 AA ratio)_
- [ ] **T6** — Add internationalisation: replace all hard-coded user-facing text with locale keys for the page title, button labels ('Add image', 'Remove', 'Move up', 'Move down'), confirmation dialog text, and error messages, so no user-facing string is hard-coded _(verify: no user-facing string is hard-coded in the /admin/hero page; all labels, dialog text, and error messages resolve from locale keys; switching the locale changes the displayed text accordingly)_
- [ ] **T7** — Add integration tests covering TC-015 (add an image and verify it appears in the list), TC-016 (remove an image and verify it is absent), and TC-017 (reorder by moving position 3 to position 1 and verify the new order) through the UI _(verify: the integration test suite passes: TC-015 adds an image via the UI and it appears in the management list; TC-016 removes an image via the UI and it is absent from the list; TC-017 reorders via the UI and the list reflects the new order)_
- [ ] **T8** — Definition of Done: verify the /admin/hero page is deployed to the test environment, all integration tests pass, WCAG 2.2 AA conformance is verified, i18n keys are in place, and the page is accessible to an authenticated admin with the hero_images manage permission _(verify: in the test environment, an authenticated admin with the hero_images manage permission can load /admin/hero, add an image, remove an image, and reorder images; all integration tests pass; no accessibility violations are reported at WCAG 2.2 AA; no user-facing text is hard-coded)_

## Acceptance

- Given an authenticated admin on the hero section management interface, When the admin uploads an image and adds it to the hero carousel, Then the system stores the image reference and display position in the data store and the image appears in the hero carousel management list
- Given an authenticated admin and an existing hero section image, When the admin removes that image, Then the system removes the image from the data store and the image no longer appears in the hero carousel on the public site
- Given an authenticated admin and a hero carousel with images in positions 1, 2, and 3, When the admin moves the image in position 3 to position 1, Then the system stores the updated order and the public site displays the carousel images in the new order on the next page load
