# DC-004-04 — PUT /api/admin/rooms/:id/price

Update a room price specifically. Validates price is positive numeric. Updates updated_at timestamp.

**Contract:** PUT /api/admin/rooms/:id/price { price } -> 200 { room } | 401 | 403 | 404 | 422 price invalid | 503

## Why

REQ-FUNC-011 requires that an authenticated admin can update a room price specifically, and that the updated price is reflected on the public site on the next page load.

## What

A PUT /api/admin/rooms/:id/price endpoint that validates the price is positive numeric with zod, updates the room price and updated_at timestamp in PostgreSQL via Prisma, and returns 200 with the updated room, or 404 if the room does not exist, 422 for a non-positive price, 401/403 on auth failure, 503 when Poly-X is unreachable.

## Scope

**In:** The PUT /api/admin/rooms/:id/price endpoint, its price-only zod validation schema (positive amount, valid currency), the Prisma update logic for the price field and updated_at timestamp, and the Poly-X introspection middleware wiring for admin authorization.

**Out:** Does not build the create endpoint (DC-004-01), the general edit endpoint (DC-004-02), the delete endpoint (DC-004-03), the room listings UI (DC-004-05), or the Prisma schema (DC-002-07). Poly-X provides authentication; this unit only wires the introspection middleware from DC-001-03.

## Tasks

- [ ] **T1** — Add the zod validation schema for the price-update request body: price object with a positive numeric amount string and a non-blank currency string _(verify: the schema accepts price { amount: '3500.00', currency: 'PKR' } and rejects price { amount: '0.00', currency: 'PKR' } with a field '/price' error)_
- [ ] **T2** — Wire the Poly-X introspection middleware from DC-001-03 on the PUT /api/admin/rooms/:id/price route: introspect the Bearer token, check admin role, validate organization-id header, fail closed with 401/403/503 as specified _(verify: a request without a Bearer token returns 401, a request with a valid token but no admin role returns 403, and a request when Poly-X is unreachable returns 503)_
- [ ] **T3** — Implement the PUT /api/admin/rooms/:id/price handler: look up the room by id returning 404 if not found, validate the body with the zod schema returning 422 with error code VALIDATION_ERROR and an errors array containing an item with field '/price' on failure, update the room price and set updated_at to the current timestamp via the Prisma client from DC-002-07, return 200 with the updated room object _(verify: PUT /api/admin/rooms/:id/price with price { amount: '3500.00', currency: 'PKR' } on an existing room returns 200 with the updated room where price is 3500; PUT with price { amount: '0.00', currency: 'PKR' } returns 422 with error code VALIDATION_ERROR and an errors array containing an item with field '/price', and the stored price remains unchanged; PUT on a non-existent room id returns 404)_
- [ ] **T4** — Add structured logging with the request id on the price-update handler: log the admin userId, organizationId, room id, old price, and new price on success, and the validation error or 404 details on failure _(verify: a successful price update logs the userId, organizationId, room id, old price, and new price with the request id; a 422 response logs the invalid price field with the request id)_
- [ ] **T5** — Write integration tests covering TC-020 (price update from 3000 to 3500 returns 200 and public site shows 3500) and TC-021 (non-positive price 0.00 returns 422 with field '/price' and stored price unchanged) _(verify: TC-020 passes: PUT with price { amount: '3500.00', currency: 'PKR' } returns 200 with price 3500, and a subsequent GET to /api/content/rooms shows the updated price; TC-021 passes: PUT with price { amount: '0.00', currency: 'PKR' } returns 422 with error code VALIDATION_ERROR and errors array item { field: '/price' }, and the stored price remains the previous value)_
- [ ] **T6** — Definition of Done: all tests pass, the endpoint returns 200 with the updated room for a valid positive price, 422 with field '/price' for a non-positive price, 404 for a non-existent room, 401/403/503 auth paths are covered, structured logs include the request id, and the endpoint is deployed to the test environment _(verify: the test suite passes, TC-020 and TC-021 are green, a curl to the test environment PUT /api/admin/rooms/:id/price with a valid price returns 200 with the updated price, and a curl with amount '0.00' returns 422 with field '/price')_

## Acceptance

- Given an authenticated admin and an existing room listing priced at 3000, When the admin changes the price to 3500 and saves, Then the system stores the updated price and the public site displays 3500 for that room on the next page load
