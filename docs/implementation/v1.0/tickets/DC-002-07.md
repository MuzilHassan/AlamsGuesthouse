# DC-002-07 — Prisma client and schema configuration

Prisma schema file (prisma/schema.prisma), generated client, and DATABASE_URL environment variable configuration. Provides type-safe database access for all content operations.

**Contract:** prisma/schema.prisma defining all tables; Prisma client generated; env DATABASE_URL; indexes on PKs and FKs; supports tens of rooms, hundreds of images and posts

## Why

REQ-FUNC-020, REQ-NFUNC-004, and REQ-NFUNC-006 require a type-safe data access layer that persists all managed content across restarts and deployments and performs without degradation at expected content volumes (tens of rooms, hundreds of images and posts).

## What

A consolidated prisma/schema.prisma with all six content tables, generated Prisma client, DATABASE_URL environment configuration, and indexes on primary keys and foreign keys, providing type-safe database access for all content operations.

## Scope

**In:** The prisma/schema.prisma datasource and generator configuration, DATABASE_URL environment variable setup, Prisma client generation, and indexes on all PKs and FKs across the six content tables.

**Out:** The individual table models and their migrations (DC-002-01 through DC-002-06); any API endpoints, repositories, or service-layer code that uses the Prisma client; application-level caching or query optimization beyond database indexes.

## Tasks

- [ ] **T1** — Configure the datasource block in prisma/schema.prisma with provider postgresql and the DATABASE_URL environment variable, and the generator block with provider prisma-client-js _(verify: prisma validate succeeds and the datasource uses postgresql provider with url = env("DATABASE_URL"))_
- [ ] **T2** — Add database indexes on all primary keys (id columns) and foreign keys (room_id on RoomImage and Promotion) to prisma/schema.prisma using @@index annotations where Prisma does not auto-index FKs _(verify: prisma validate succeeds and the schema includes @@index on room_id for RoomImage and Promotion models; Prisma auto-indexes id PK columns)_
- [ ] **T3** — Run prisma generate to produce the Prisma client and confirm it exports typed models for Room, RoomImage, Promotion, HeroImage, GalleryImage, and BlogPost _(verify: prisma generate succeeds and the generated client in node_modules/.prisma/client exports types for all six models with their fields and relations)_
- [ ] **T4** — Add DATABASE_URL to the environment configuration files (e.g. .env.example) as a documented placeholder without a real value, and confirm the application reads it at startup _(verify: .env.example contains DATABASE_URL=postgresql://user:password@localhost:5432/dbname as a placeholder and the Prisma client initialises without error when a valid DATABASE_URL is set)_
- [ ] **T5** — Write an integration test that populates the data store with the expected content volume (tens of rooms, hundreds of room images, gallery images, and blog posts), measures read and write query times, and confirms they remain within acceptable bounds without performance degradation _(verify: the test inserts 50 rooms, 200 room images, 200 gallery images, and 100 blog posts, then measures read times for querying all rooms with their images and write times for inserting a new blog post; query times are logged and remain under an acceptable threshold; TC-044 is demonstrated at expected content volumes)_
- [ ] **T6** — Write a persistence integration test that records all content across the six tables, simulates an application restart by disconnecting and re-instantiating the PrismaClient, and verifies all content is present and unchanged _(verify: the test inserts records across all six tables, disconnects and re-creates the PrismaClient, queries each table and confirms every record is present with all fields matching; TC-031 is demonstrated across all content types)_
- [ ] **T7** — Definition of Done: run prisma validate, prisma generate, prisma migrate dev, the persistence test suite, and the performance test; confirm DATABASE_URL is documented and the client is generated _(verify: prisma validate passes, prisma generate produces the client with all six models, all migrations apply cleanly, the persistence test passes confirming all content survives a restart, the performance test passes confirming no degradation at expected volumes, DATABASE_URL is documented in .env.example, and the schema and generated client are committed)_

## Acceptance

- Given managed content stored in the data store, When the application is restarted or redeployed, Then the managed content remains available in the data store unchanged
- Given the data store contains the expected volume of room listings, gallery images, and blog posts, When the admin dashboard or public site reads or writes content, Then the data store responds without performance degradation (target content volumes to be confirmed by the client)
- Given managed content in the data store, When the application undergoes a restart or deployment, Then an inspection of the data store shows all managed content present and unchanged
