# DC-002-07 — Prisma client and schema configuration

Prisma schema file (prisma/schema.prisma), generated client, and DATABASE_URL environment variable configuration. Provides type-safe database access for all content operations.

**Contract:** prisma/schema.prisma defining all tables; Prisma client generated; env DATABASE_URL; indexes on PKs and FKs; supports tens of rooms, hundreds of images and posts

## Why

REQ-FUNC-020, REQ-NFUNC-004, and REQ-NFUNC-006 require a type-safe, performant data access layer that persists content across restarts and handles the expected content volumes without degradation.

## What

A complete prisma/schema.prisma consolidating all six table models, a generated Prisma client, DATABASE_URL environment configuration, indexes on all primary keys and foreign keys, and a performance verification at expected content volumes.

## Scope

**In:** The consolidated prisma/schema.prisma with all six models, Prisma client generation, DATABASE_URL env configuration, and PK/FK indexes.

**Out:** Individual table model definitions (DC-002-01 through DC-002-06); any API endpoints or business logic that uses the Prisma client; any database hosting or provisioning infrastructure.

## Tasks

- [ ] **T1** — Consolidate all six table models (Room, RoomImage, Promotion, HeroImage, GalleryImage, BlogPost) into a single prisma/schema.prisma with the PostgreSQL datasource provider set to postgresql, and add @@index annotations on every foreign key column (room_id on RoomImage and Promotion) _(verify: prisma validate succeeds; schema.prisma contains all six models with their contract fields, the datasource provider is postgresql, and @@index is present on room_id in RoomImage and Promotion)_
- [ ] **T2** — Configure the DATABASE_URL environment variable in .env.example with a placeholder PostgreSQL connection string (no real credentials), and document it in the project README as a required environment variable for the Prisma client _(verify: .env.example contains DATABASE_URL with a placeholder value (e.g. postgresql://user:password@localhost:5432/dbname), the README documents DATABASE_URL as required, and no real credentials are present)_
- [ ] **T3** — Generate the Prisma client with npx prisma generate and confirm it produces type-safe query builders for all six models _(verify: npx prisma generate succeeds; the generated client exports types for Room, RoomImage, Promotion, HeroImage, GalleryImage, and BlogPost with fields matching their contracts)_
- [ ] **T4** — Generate and apply the consolidated migration with npx prisma migrate dev --name init_content_schema, and confirm the down migration drops all six tables cleanly in reverse dependency order _(verify: migrate up creates all six tables with their contract columns, primary keys, and foreign key constraints; migrate down drops BlogPost, GalleryImage, HeroImage, Promotion, RoomImage, then Room without errors)_
- [ ] **T5** — Write a persistence test that inserts rows across all six tables, restarts the Prisma client connection, and re-reads all rows to confirm they survive a connection cycle unchanged _(verify: after closing and reopening the Prisma client, all inserted rows across Room, RoomImage, Promotion, HeroImage, GalleryImage, and BlogPost are present and unchanged, satisfying TC-031 for the full content schema)_
- [ ] **T6** — Write a performance test that populates the data store with the expected content volume (tens of rooms, hundreds of images and posts) and measures read and write query times against a baseline, covering TC-044 _(verify: with tens of rooms, hundreds of RoomImage/GalleryImage/HeroImage rows, and hundreds of BlogPost rows populated, read queries for public content and write queries for admin operations complete within acceptable bounds without performance degradation, satisfying TC-044 (target content volumes to be confirmed by the client))_
- [ ] **T7** — Definition of Done: run prisma validate, run prisma generate, run the consolidated migration up and down, run the persistence test, run the performance test, and confirm the schema and configuration are committed _(verify: prisma validate passes, prisma generate produces types for all six models, migrate up creates all six tables and migrate down removes them cleanly, the persistence test passes with no data loss across a connection restart, the performance test shows no degradation at expected volumes, DATABASE_URL is documented in .env.example, and the schema and migration files are committed to the repository)_

## Acceptance

- Given managed content stored in the data store, When the application is restarted or redeployed, Then the managed content remains available in the data store unchanged
- Given the data store contains the expected volume of room listings, gallery images, and blog posts, When the admin dashboard or public site reads or writes content, Then the data store responds without performance degradation (target content volumes to be confirmed by the client)
- Given managed content in the data store, When the application undergoes a restart or deployment, Then an inspection of the data store shows all managed content present and unchanged
