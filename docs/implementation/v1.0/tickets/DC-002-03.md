# DC-002-03 — Promotion table

Prisma schema for Promotion table storing promotions associated with rooms.

**Contract:** Promotion { id UUID PK, room_id UUID FK->Room not null, title text not null, description text, is_active boolean not null default true, created_at timestamp not null, updated_at timestamp not null }

## Why

REQ-FUNC-020 and REQ-NFUNC-006 require room promotions to persist across restarts and deployments; the Promotion table stores promotional content associated with individual rooms.

## What

A Prisma model and PostgreSQL migration for the Promotion table with id (UUID PK), room_id (FK to Room, not null), title (text not null), description (text), is_active (boolean not null, default true), created_at, and updated_at, plus its rollback migration.

## Scope

**In:** The Promotion Prisma model definition, its foreign key to Room, and its up/down SQL migration only.

**Out:** The Room table itself (DC-002-01); the Prisma client generation and DATABASE_URL configuration (DC-002-07); any business logic for activating or deactivating promotions; any API endpoints that read or write promotions.

## Tasks

- [ ] **T1** — Add the Promotion model to prisma/schema.prisma with id as UUID @id @default(uuid()), room_id as UUID with a @@relation to Room (onDelete cascade), title as non-null String, description as nullable String, is_active as Boolean @default(true) non-null, created_at and updated_at as non-null DateTime @default(now()), and a @@index on room_id _(verify: prisma validate succeeds; the Promotion model has id UUID PK, room_id UUID FK->Room not null, title text not null, description text, is_active boolean not null default true, created_at timestamp not null, updated_at timestamp not null)_
- [ ] **T2** — Generate and apply the Prisma migration for the Promotion table with npx prisma migrate dev --name add_promotion_table, and confirm the down migration drops the Promotion table cleanly _(verify: the migration creates a promotion table with columns id, room_id, title, description, is_active default true, created_at, updated_at and a foreign key constraint on room_id referencing room(id); prisma migrate down removes the promotion table and its foreign key without errors)_
- [ ] **T3** — Write a persistence test that inserts a Room row and a linked Promotion row, restarts the Prisma client connection, and re-reads both rows to confirm they survive a connection cycle _(verify: after closing and reopening the Prisma client, the inserted Promotion row is present with room_id, title, description, is_active, created_at, and updated_at unchanged and the foreign key to Room is intact, satisfying TC-031 for the Promotion table)_
- [ ] **T4** — Definition of Done: run prisma validate, run the migration up and down, run the persistence test, and confirm the schema is committed _(verify: prisma validate passes, migrate up creates the promotion table with the contract columns and FK to room, migrate down removes it cleanly, the persistence test passes with no data loss across a connection restart, and the migration file is committed to the repository)_

## Acceptance

- Given managed content stored in the data store, When the application is restarted or redeployed, Then the managed content remains available in the data store unchanged
- Given managed content in the data store, When the application undergoes a restart or deployment, Then an inspection of the data store shows all managed content present and unchanged
