# DC-002-03 — Promotion table

Prisma schema for Promotion table storing promotions associated with rooms.

**Contract:** Promotion { id UUID PK, room_id UUID FK->Room not null, title text not null, description text, is_active boolean not null default true, created_at timestamp not null, updated_at timestamp not null }

## Why

REQ-FUNC-020 and REQ-NFUNC-006 require promotions associated with rooms to persist across restarts and deployments so active promotional content remains available without data loss.

## What

A Promotion table in PostgreSQL 16 with a foreign key to Room, defined via a Prisma 6 schema with migration and rollback, storing promotion title, description, and active status.

## Scope

**In:** The Prisma model and migration for the Promotion table only: columns id (UUID PK), room_id (UUID FK to Room, not null), title (text not null), description (text), is_active (boolean not null default true), created_at, updated_at, and the FK relation to Room.

**Out:** The Room table itself (DC-002-01); the Prisma client configuration (DC-002-07); any business logic for applying or expiring promotions; API endpoints that serve promotions.

## Tasks

- [ ] **T1** — Add the Promotion model to prisma/schema.prisma with id as @id @db.Uuid, room_id as UUID not null with @relation to Room, title as String not null, description as String?, is_active as Boolean not null with @default(true), created_at and updated_at as DateTime not null, and the relation field on Room _(verify: prisma validate succeeds and the Promotion model matches the contract fields, types, and the default true on is_active)_
- [ ] **T2** — Generate the Prisma migration for the Promotion table (prisma migrate dev --name add_promotion_table) and verify the up SQL creates the promotion table with the FK constraint to room(id) and is_active defaulting to true _(verify: the migration SQL creates promotion with id uuid PK, room_id uuid not null referencing room(id), title text not null, description text, is_active boolean not null default true, created_at timestamp not null, updated_at timestamp not null)_
- [ ] **T3** — Write the down migration that drops the promotion table, so the migration is reversible _(verify: running the down migration removes the promotion table and its FK constraint cleanly)_
- [ ] **T4** — Write a unit test that inserts a Room and a Promotion referencing it, simulates a restart by re-instantiating the PrismaClient, and reads the Promotion back to confirm it is present and unchanged with is_active defaulting to true on insert _(verify: the test creates a room and a linked promotion without specifying is_active, re-instantiates the client, reads the promotion and confirms title, description, is_active=true, and room_id resolve correctly; TC-031 is demonstrated)_
- [ ] **T5** — Definition of Done: run prisma validate, apply the migration and its rollback, and run the persistence test suite for Promotion _(verify: prisma validate passes, the promotion migration applies and rolls back without error, the persistence test passes confirming promotion content survives a simulated restart, and the schema is committed)_

## Acceptance

- Given managed content stored in the data store, When the application is restarted or redeployed, Then the managed content remains available in the data store unchanged
- Given managed content in the data store, When the application undergoes a restart or deployment, Then an inspection of the data store shows all managed content present and unchanged
